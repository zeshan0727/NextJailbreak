MusicLRC Adds Time-Synced Lyrics for Local Songs in Apple Music

MusicLRC is a jailbreak tweak maintained by iCraze that adds support for time-synced lyrics for local songs or local media within Apple Music. The official depiction says lyric data must be saved in the song’s tags in LRC or TTML format. It does not describe support for streamed Apple Music catalog tracks, lyric downloads, or online lyric services. The depiction lists iOS 13.0 through iOS 18.7.9, while warning that the tweak may be broken on some versions. The supplied package stanza identifies version 1.0, whereas the depiction lists version 1.1 and documents changes including iOS 13 support, iOS 14 confirmation, an Airplane Mode fix for iOS 14.0–14.2, and patchfinder optimisations.

Key points

  • MusicLRC is intended for local songs or local media used within Apple Music.
  • The official depiction names LRC and TTML as supported tagged lyric formats.
  • The listed compatibility range is iOS 13.0 through iOS 18.7.9, with a warning that some versions may be broken.
  • The package stanza says version 1.0, while the depiction lists version 1.1 and its changelog.
  • The package metadata lists the identifier com.icraze.musiclrc, iphoneos-arm64 architecture, and a mobilesubstrate dependency of version 0.9.5000 or newer.

What MusicLRC is designed to do

MusicLRC is presented as a jailbreak tweak for Apple Music users who play songs stored locally on their devices. Its stated purpose is to add time-synced lyrics for local songs or local media within the Apple Music app. The official package description does not present it as a general lyric service or as an extension for every type of Apple Music playback.

The release material is specific about the source of the lyric information: song files must have lyrics saved in their tags. It also names LRC and TTML as the supported formats. This gives MusicLRC a clearly defined use case: displaying synchronized lyric data already associated with a local media file, rather than describing a system for retrieving lyrics from an external service.

The supplied sources do not claim lyric downloading, automatic lyric searches, translation, lyric editing, or support for streamed catalog tracks. Those functions should not be inferred from the tweak’s name or from its support for timed lyrics. The official description is limited to local media and tagged LRC or TTML lyrics.

  • Target application: Apple Music.
  • Target media: local songs or local media.
  • Lyric data must be saved in the song’s tags.
  • Supported formats named by the depiction: LRC and TTML.

The importance of tagged LRC and TTML data

The tagged-lyrics requirement is the central preparation detail in the official depiction. MusicLRC is not described as a tool that creates lyric timing or obtains lyric content. Instead, the song’s tags must already contain the lyric data in one of the formats identified by the developer.

LRC and TTML are both named specifically in the package depiction, and the surrounding description refers to time-synced lyrics. Therefore, the relevant file needs more than ordinary unsynchronized lyric text if synchronized display is expected. The source does not provide a tag-editing workflow, conversion instructions, or a method for acquiring lyric files.

This distinction matters when assessing the result after installation. Installing the tweak does not, by itself, establish that every local song will show synchronized lyrics. The official material ties the feature to the contents and format of the song’s tags, and it separately warns that the tweak may be broken on some iOS versions. A missing or unsupported lyric display cannot automatically be attributed to one cause based on the supplied documentation alone.

  • Confirm that the affected song contains lyrics in its tags.
  • Check whether the tagged data uses LRC or TTML.
  • Do not assume that ordinary plain-text lyrics provide synchronization information.
  • The official sources do not document a lyric downloader or tag-editing utility.

Compatibility information and documented changes

The official depiction gives an iOS range of 13.0 through 18.7.9. Its description also says that the tweak should support devices running iOS 13 through iOS 18, while cautioning that the tweak is complex internally and may be broken on some versions. The warning is important: the listed range is not a guarantee that every device, system version, or Apple Music configuration will work identically.

The depiction mentions iOS 26 only as a possible future target. That statement does not establish current support for iOS 26. Based on the supplied material, the documented compatibility information ends with the listed iOS 13.0–18.7.9 range, subject to the developer’s warning about possible breakage.

The depiction’s changelog lists version 1.1 and several changes. It says support was added for iOS 13, support was confirmed for iOS 14, the tweak was fixed for iOS 14.0–14.2 when the device was in Airplane Mode, and patchfinder optimisations were made. These are release-note claims from the official depiction, not independent test results or a promise of identical behavior across all supported setups.

  • Information table range: iOS 13.0–18.7.9.
  • The depiction warns that the tweak may be broken on some versions.
  • The 1.1 changelog mentions iOS 13 support and iOS 14 confirmation.
  • The changelog lists an Airplane Mode fix for iOS 14.0–14.2.
  • iOS 26 is described only as possible future support.

The supplied sources show two package versions

The package stanza identifies MusicLRC as version 1.0. Separately, the official depiction’s information table lists version 1.1 and an October 17, 2026 update date. Its changelog presents version 1.1 as containing the documented compatibility and patchfinder changes, while version 1.0 is identified as the initial release dated October 12, 2026.

The supplied material does not explain why the package stanza and depiction show different versions. It may reflect separate package and depiction records, but that possibility is not confirmed by the sources. The discrepancy should therefore remain explicit rather than being resolved through assumption.

For readers evaluating the release, the practical conclusion is to distinguish the package metadata from the depiction’s release information. The package stanza says 1.0; the depiction says 1.1. The available package listing and changelog should be checked before installation so that users know which release information applies to the package being offered.

  • Package stanza version: 1.0.
  • Official depiction version: 1.1.
  • The depiction labels version 1.0 as the initial release.
  • The supplied sources do not explain the mismatch.
  • The changelog should be read together with the version actually offered.

Package metadata

The package stanza identifies the package as com.icraze.musiclrc. It names MusicLRC as a tweak in the Tweaks section and lists iCraze as both maintainer and author. The maintainer contact recorded in that stanza is an iCraze email address.

The metadata lists iphoneos-arm64 as the architecture and declares mobilesubstrate version 0.9.5000 or newer as a dependency. These are package-level requirements recorded by the repository metadata. The supplied sources do not provide broader details about supported jailbreak environments beyond that dependency declaration.

The same stanza reports an installed size of 532 and a package size of 89,614 bytes. The depiction gives the size as 89.78 KB. These figures describe the package records and do not establish performance, memory use, battery impact, or the amount of storage used by local music and lyric files.

  • Identifier: com.icraze.musiclrc.
  • Author and maintainer: iCraze.
  • Architecture: iphoneos-arm64.
  • Dependency: mobilesubstrate version 0.9.5000 or newer.
  • Package stanza size: 89,614 bytes; depiction size: 89.78 KB.

What the accompanying repository shows

The supplied repository metadata identifies a project named MusicLRC owned by meloDu. Its description, written in Chinese, is translated in the source as “a demo of lyric color gradient from left to right.” The repository metadata records a default branch named master and an update date of March 21, 2019.

The repository page shows a single commit, marked “Initial commit,” and lists an Android and Gradle-oriented project structure. The visible tree includes an app directory, Gradle files, wrapper files, and related project files. The supplied page data does not show a README explaining the project’s relationship to the packaged Apple Music tweak.

The repository should therefore be kept separate from the package claims. Its metadata documents a lyric color-gradient demo and an early Android/Gradle project structure; it does not establish the iOS tweak’s compatibility, package version, implementation, or release process. The official package stanza and depiction remain the sources for MusicLRC’s jailbreak-package details.

  • Repository description: a lyric color-gradient demo.
  • The supplied metadata records one initial commit from March 21, 2019.
  • The visible project structure is Android/Gradle-oriented.
  • The supplied repository material does not document the packaged iOS tweak.

Does MusicLRC add lyrics to Apple Music’s streaming catalog?

The official description only says that MusicLRC supports time-synced lyrics for local songs or local media within Apple Music. It does not claim support for streamed catalog tracks, lyric downloads, or online lyric services.

What lyric formats are supported?

The official depiction names LRC and TTML. It says the lyric data must be saved in the song’s tags, and the package is intended for time-synced lyrics rather than unspecified plain-text lyrics.

Which iOS versions are listed as compatible?

The official depiction lists iOS 13.0 through iOS 18.7.9. It also warns that the tweak may be broken on some versions, so the range should not be treated as a guarantee for every device or Apple Music configuration.

Is iOS 26 supported?

No current support is established by the supplied material. The depiction says support for iOS 26 may be added in the future, which is a future possibility rather than a present compatibility statement.

Why do the supplied sources show versions 1.0 and 1.1?

The package stanza identifies version 1.0, while the official depiction lists version 1.1 and documents its changelog. The source material does not explain the mismatch, so users should check the available package listing and changelog before installing.
