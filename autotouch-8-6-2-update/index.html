AutoTouch 8.6.2 Improves WebDAV, Finder Access and Script Playback Reliability

AutoTouch 8.6.2, released September 24, is a maintenance update for the Lua-based automation toolkit for jailbroken iPhone and iPad devices. The release improves WebDAV compatibility with macOS Finder, optimizes folder-listing responses when browsing large folders, allows device-pairing codes to be reused after a restart, and fixes touch restrictions that could affect later or concurrently running script playbacks. The update should be considered alongside the Lua-only migration requirements introduced in version 8.6.0.

Key points

  • AutoTouch 8.6.2 improves WebDAV connection compatibility with macOS Finder.
  • Folder-listing responses are optimized to reduce processing overhead on the device when browsing large folders.
  • Device-pairing codes can be reused and remain valid after a restart; a new code can be generated in Settings when replacement is needed.
  • A bug involving touch restrictions affecting later or concurrent script playbacks has been fixed.
  • AutoTouch requires a jailbroken iPhone or iPad, with package selection dependent on the jailbreak environment.
  • Current builds use Lua only; JavaScript scripts no longer run, so older automation may require migration.

What changed in AutoTouch 8.6.2

AutoTouch 8.6.2 is dated September 24 in the project’s release notes. Rather than introducing a new scripting language, the update concentrates on remote file management, connection behavior and script-playback reliability.

The release lists four principal changes: improved WebDAV compatibility with macOS Finder, optimized WebDAV folder-listing responses, reusable device-pairing codes that remain valid after a restart, and a fix for touch restrictions triggered during script playback. The touch issue could affect later playbacks or other scripts running concurrently.

These changes are relevant to different parts of the AutoTouch workflow. WebDAV and Finder improvements affect how users manage scripts from a computer, while the pairing-code change affects device connections. The playback fix is aimed at cases where a restriction from one script run influenced subsequent or simultaneous runs.

  • WebDAV compatibility with macOS Finder has been improved.
  • Large-folder browsing receives a device-side processing optimization.
  • Pairing codes can be reused after a restart.
  • Touch restrictions no longer carry the documented playback effects into later or concurrent runs.

Finder and WebDAV access

The release notes provide a specific procedure for connecting from macOS Finder. First enable WebDAV in AutoTouch Settings. Then copy the displayed HTTP address, open Finder’s server-connection dialog with Command-K, and connect as Guest.

Version 8.6.2 adds the server address and Guest-connection instructions to Settings, making the connection details easier to find. The change is particularly useful for users who manage script files through Finder instead of a separate WebDAV client or the browser-based web interface.

The update also optimizes WebDAV folder-listing responses. According to the release notes, this reduces processing overhead on the device when browsing folders containing many files. The notes still caution that folders with many files may take longer to load, so the improvement should not be read as a guarantee of instant directory browsing.

AutoTouch documentation distinguishes among its Web Server, WebDAV and HTTP API features. WebDAV is the relevant service for the Finder workflow described in the 8.6.2 notes. Users should enable the service they intend to use and rely on the address currently displayed in AutoTouch Settings.

  • Enable WebDAV in AutoTouch Settings.
  • Use the displayed HTTP address when connecting from Finder.
  • Press Command-K in Finder to open the server-connection dialog.
  • Connect as Guest, as specified in the release notes.
  • Large folders may still take longer to load.

Pairing-code behavior after the update

AutoTouch 8.6.2 changes the handling of device-pairing codes. The release notes state that pairing codes can be reused and remain valid after a restart. They do not specify whether “restart” refers to a particular component or enumerate different restart scenarios, so the documented behavior should be understood only as stated: the code remains valid after a restart.

The same note says that users can generate a new code in Settings whenever they want to replace an existing one. This gives users a documented way to replace the current code rather than continuing to use it.

The release notes do not describe the complete security model for pairing codes, what actions a code authorizes, or how access is managed across different computers. Accordingly, the update supports a narrower conclusion: an existing pairing code is reusable after a restart, and generating a new code is the available replacement action documented by the project.

  • The release notes say pairing codes remain valid after a restart.
  • Codes can be reused rather than regenerated solely because of that restart.
  • Generate a new code in Settings when you want to replace the existing one.
  • The release notes do not define additional pairing-code authorization or expiry rules.

Touch-restriction fix for script playback

The final 8.6.2 fix concerns touch restrictions during playback. The release notes say that restrictions triggered during one script playback could affect later playbacks or other concurrently running scripts. Version 8.6.2 fixes that behavior.

This is relevant to users who repeatedly run automation or use more than one active script. The source does not identify a particular command, app or jailbreak as the cause, so the supported conclusion is limited to the playback-state problem described in the release notes.

AutoTouch’s product documentation describes Lua scripts that can launch apps, simulate touches, enter text and combine actions with conditions and loops. Scripts can be launched from the device control panel, and the documentation says a long press of Volume Down stops a running script unless the control action has been customized. Those controls remain useful when testing or reviewing automation after an update.

  • The old issue could affect later playbacks after a restriction was triggered.
  • Concurrent scripts could also be affected.
  • The release notes do not claim that every possible touch or automation problem is resolved.
  • A long press of Volume Down is documented as the normal way to stop a running script, subject to customization.

Lua-only migration remains an important upgrade condition

Although the Lua migration is not new to version 8.6.2, it remains important for anyone upgrading from an older AutoTouch release. The 8.6.0 release notes state that Lua is now the only supported scripting language and that JavaScript scripts no longer run. Users coming from older versions should convert JavaScript scripts to Lua before upgrading and update them against the current Lua API.

The project’s FAQ adds that current recordings produce Lua files, packages use a main.lua entry point, and JavaScript files cannot run as scripts in current builds. This means users should inventory older automation before changing versions rather than assuming that previously recorded JavaScript files will continue to execute.

Version 8.6.0 also warns that scripts depending on fixed screenshot sizes or coordinates may need adjustments, particularly on Plus devices or when Display Zoom is used. Newly password-encrypted scripts require a compatible AutoTouch version, while existing encrypted Lua scripts remain supported according to the release notes.

AutoTouch’s current automation features include device control, image matching, OCR and Lua scripting. The product documentation says local Vision OCR requires iOS 13 or later, while the release notes state continued support for iOS 12.2 and later for the version 8.6.0 package context. Feature availability can therefore depend on the iOS version and installation environment.

  • Convert older JavaScript scripts to Lua before upgrading to current builds.
  • Review fixed coordinates and screenshot-size assumptions.
  • Check compatibility before opening or distributing newly password-encrypted scripts.
  • Use the current Lua API and Lua-based recordings as the basis for new work.

Installation and compatibility considerations

AutoTouch is built for jailbroken iPhone and iPad devices. The FAQ states that it cannot run on stock iOS or as an App Store application. The product documentation identifies rootful, rootless and roothide environments, and the FAQ advises users to select the package that matches their jailbreak.

The 8.6.0 release notes state continued support for iOS 12.2 and later, with Standard and InputText packages for rootful, rootless and roothide installations. They also describe stability and compatibility improvements across supported jailbreak environments. This is compatibility information for the documented release context, not a guarantee that every feature behaves identically on every device.

The documented installation path is to add the official AutoTouch repository to a compatible package manager, install the package matching the jailbreak, and then open AutoTouch to create or import a script. Before upgrading, users should preserve important scripts and review any version-specific requirements relevant to their device.

  • AutoTouch requires a jailbroken iPhone or iPad.
  • Choose the package matching the rootful, rootless or roothide environment.
  • Review iOS and jailbreak compatibility before installing or upgrading.
  • Preserve important scripts before changing versions.

Practical checklist before upgrading

Start by checking whether the device contains JavaScript automation, since current builds no longer execute JavaScript. Convert those scripts to Lua and check their behavior against the current API. Next, review scripts that depend on fixed coordinates, screenshot dimensions or encrypted packages.

For computer-based management, plan to use the WebDAV address shown in AutoTouch Settings. If the goal is Finder access, follow the documented sequence: enable WebDAV, copy the displayed HTTP address, use Command-K in Finder and connect as Guest. Keep in mind that large folders may still load more slowly.

Pairing-code behavior should be reviewed separately. Version 8.6.2 says that codes can be reused and remain valid after a restart, while a new code can be generated in Settings when replacement is wanted. The source does not provide further rules about authorization or expiry, so users should not infer undocumented behavior.

Finally, confirm how playback can be stopped before testing migrated or unfamiliar automation. AutoTouch documents a long press of Volume Down and also documents a script-level stop function. Testing one script at a time can make it easier to distinguish migration issues from the touch-restriction problem addressed by 8.6.2.

  • Inventory JavaScript files and migrate them to Lua.
  • Review coordinate-dependent scripts and encrypted packages.
  • Use the current WebDAV address shown in Settings.
  • Follow the documented Finder connection steps.
  • Confirm the playback stop control before testing scripts.

Frequently asked questions

What is new in AutoTouch 8.6.2?

The release improves WebDAV compatibility with macOS Finder, optimizes folder-listing responses, allows pairing codes to be reused and remain valid after a restart, and fixes touch restrictions that could affect later playbacks or other concurrently running scripts.

How do I connect to AutoTouch from macOS Finder?

Enable WebDAV in AutoTouch Settings, copy the displayed HTTP address, open Finder’s server-connection dialog with Command-K, and connect as Guest. The release notes say folders containing many files may still take longer to load.

What does the update say about pairing codes?

The 8.6.2 release notes state that device-pairing codes can be reused and remain valid after a restart. Generate a new code in Settings when you want to replace the existing one. The notes do not specify additional authorization or expiry rules.

Does AutoTouch 8.6.2 support JavaScript scripts?

No. Current builds use Lua only, and JavaScript scripts no longer run. Users upgrading from older releases should convert JavaScript automation to Lua and update it against the current Lua API.

Does AutoTouch require a jailbreak?

Yes. AutoTouch runs on jailbroken iPhone and iPad devices and cannot run on stock iOS or as an App Store app. Select the package that matches the device’s rootful, rootless or roothide environment.

Before installing: confirm the current package version, compatibility and dependencies at the original developer/repository source for your exact device and jailbreak.
