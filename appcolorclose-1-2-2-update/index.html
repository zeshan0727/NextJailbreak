AppColorClose 1.2.2 Updates Build Support for Rootless and Traditional Jailbreak Environments

PoomSmart’s AppColorClose has reached version 1.2.2 in the project’s current package metadata. The tweak changes the iOS Home Screen close box so its tint and X control use a color derived from the associated app icon. The latest 2026 update primarily changes build and packaging configuration rather than documenting a new user-facing feature: it adds separate Theos targets for rootless and traditional builds, sets SpringBoard as the installation target process, refreshes bundled resources, and updates the package description and license year.

Key points

  • AppColorClose 1.2.2 is the current version listed in the project’s control file.
  • The project README and package metadata state that iOS 12 or later is required.
  • The tweak derives a color from the app icon and applies it to the close-box tint and X control.
  • The latest Makefile adds a rootless build path targeting iOS 15.0 and retains a traditional path targeting iOS 12.0.
  • The package declares dependencies on firmware 12.0 or later, MobileSubstrate, and PreferenceLoader.
  • The source does not document a one-click installation process, a changelog, performance results, or device testing; users should confirm package-manager and jailbreak compatibility before proceeding.

What AppColorClose changes

AppColorClose is a small SpringBoard customization focused on the close box shown for Home Screen app icons. Its stated purpose is to tint the control according to the app icon’s color rather than using one uniform appearance. The repository describes the project as making the app’s close box “based on app icon,” while the package metadata describes it as tinting the app close box using app-icon color.

The implementation in the current source calculates an average RGB color from an icon image. It then applies that color to the close box’s tint view and to the X image. The code also reads two SpringBoard preference values: SBCloseBoxTintAlpha controls opacity, and SBCloseBoxBorderWidth controls the border width. When a border is enabled, the source uses the same derived color for the border.

This is a visual customization rather than a feature that changes app management behavior. The source hooks SBIconView’s close-box update method, so the documented scope is the appearance of the close control associated with an icon. The available source does not claim changes to app launching, multitasking, battery life, or system performance.

  • Color is calculated from the app icon image.
  • The close-box tint and X control use the derived color.
  • Tint opacity and border width are exposed through SpringBoard preference keys.
  • The package description does not identify any new controls beyond this visual behavior.

What changed in version 1.2.2

The current control file identifies the package as version 1.2.2, with package identifier com.ps.appcolorclose and PoomSmart listed as author and maintainer. The latest project commit, dated September 26, 2026, updates the package metadata to version 1.2.2 and changes the description wording from “Tint app close box based on app icon color” to “Tints app close box based on app icon color.” It also updates the license copyright range through 2026.

The most meaningful technical change is in the Makefile. Earlier configuration used a single iPhone target beginning at iOS 12. The current configuration checks THEOS_PACKAGE_SCHEME. For rootless builds, it selects an iPhone target using Clang 16.5 with a minimum of iOS 15.0. For the other path, it selects Clang 14.5 with a minimum of iOS 12.0 and exports the Xcode 11 toolchain path. The Makefile also adds INSTALL_TARGET_PROCESSES = SpringBoard.

That build distinction matters because it shows the project is being prepared for more than one packaging layout. However, a build target is not the same thing as a blanket runtime guarantee for every jailbreak environment. The repository’s explicit user-facing compatibility statement remains iOS 12 or later, while the rootless build branch itself specifies iOS 15.0 as its target minimum. Users should therefore check which packaging scheme their environment requires instead of assuming that every build variant has identical coverage.

The update also modifies the AppColorClose icon resources at 1x, 2x, and 3x sizes. The source does not provide a visual changelog explaining how those images changed. A separate 2023 commit updated the README screenshot, but the current release-specific update does not describe a new visual feature.

  • Package version: 1.2.2.
  • Rootless Makefile path: iOS 15.0 target with Clang 16.5.
  • Other Makefile path: iOS 12.0 target with Clang 14.5 and an Xcode 11 toolchain prefix.
  • SpringBoard is listed as the installation target process.
  • The bundled 1x, 2x, and 3x resource images were modified.

Compatibility and dependencies

The README says AppColorClose requires iOS 12 or later. The package control file repeats that baseline through a firmware dependency of 12.0 or later. It also declares dependencies on MobileSubstrate and PreferenceLoader, which are therefore part of the package’s stated requirements.

The control file identifies the architecture as iphoneos-arm and lists conflicts with org.thebigboss.appcolorclose and com.spicat.appcolorclose. Those conflict declarations indicate that users should avoid installing AppColorClose alongside packages using either of those identifiers. The source does not explain whether an installed conflicting package will be automatically removed, disabled, or blocked by a particular package manager, so that behavior should be checked in the package manager used by the device.

The project’s build configuration adds an important qualification. The traditional branch retains an iOS 12.0 target, but the rootless branch specifies iOS 15.0. The safest interpretation from the supplied material is that the project advertises iOS 12-plus support at the package level while providing a newer, separately configured rootless build path. The repository does not publish a device-by-device compatibility table or identify particular jailbreak tools.

  • Advertised runtime baseline: iOS 12 or later.
  • Declared dependencies: firmware 12.0 or later, MobileSubstrate, and PreferenceLoader.
  • Declared conflicts: org.thebigboss.appcolorclose and com.spicat.appcolorclose.
  • The package metadata lists iphoneos-arm architecture.
  • The source does not provide a jailbreak-tool compatibility matrix.

The supplied source does not include step-by-step installation instructions, a repository feed, or a supported binary-download procedure. The Makefile’s rootless branch targets iOS 15.0, while the package metadata states iOS 12.0 or later, so those two pieces of information should be treated as separate compatibility checks rather than merged into one guarantee.

Why this update matters

For users who already rely on AppColorClose, version 1.2.2 is primarily an infrastructure and packaging update. The visible concept remains unchanged: close-box styling follows the app icon’s derived color, with opacity and border controls represented in the SpringBoard preferences. The new build branches are more significant for maintainers and users on newer rootless environments than for someone expecting a redesigned interface.

The update also makes the package identity clearer. PoomSmart is named as both author and maintainer, the package identifier is com.ps.appcolorclose, and conflicts with two earlier identifiers are explicitly declared. These details can help users distinguish the maintained package from similarly named installations.

There is no source-backed claim of a new animation, new preference panel, performance improvement, or expanded iOS range in the 1.2.2 material. The practical takeaway is to view this as a refreshed package and build configuration that preserves the project’s established visual purpose while requiring environment-specific verification.
