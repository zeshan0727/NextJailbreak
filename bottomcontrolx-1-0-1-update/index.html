BottomControlX 1.0.1 adds stealth screenshots and broader lock-screen gesture behavior

BottomControlX has reached version 1.0.1 as package com.ichitaso.bottomcontrolx. The update adds SecretShot, described by the official package depiction as a stealthy screenshot feature, and enables the tweak while the device is passcode locked on the Lock Screen. Recent upstream commits also address gesture availability after Face ID or Touch ID authentication and change the lock-state notification behavior so updates are delivered immediately. The repository lists support for iOS 11 through iOS 13, while the current package depiction lists a broader iOS 11 through iOS 26 range across rootless, roothide, and rootful environments. That difference makes the package’s own device and jailbreak-mode notes especially important before installation.

Key points

  • BottomControlX 1.0.1 adds SecretShot, identified in the official changelog as a stealthy screenshot function.
  • The package depiction says actions can be triggered by swiping up from the bottom-left or bottom-right of the display.
  • Recent source changes track lock status around Face ID and Touch ID authentication and adjust CFNotification delivery.
  • The package declares firmware version 11.0 or later and depends on MobileSubstrate and PreferenceLoader.
  • The current depiction lists iOS 11 through iOS 26 and rootless, roothide, and rootful support, but the README describes the older project as supporting iOS 11 through iOS 13.
  • The maintainer warns that actions may be difficult to execute on some devices and says the project has not been tested on every device.

What BottomControlX 1.0.1 changes

BottomControlX is a jailbreak tweak intended to make Control Center and other actions easier to reach on devices using the iPhone X-style gesture system. The official package description focuses on iPhone X series devices, while the current depiction also names iPad support. Instead of relying only on the standard edge gesture, the tweak lets users configure actions associated with swipes from the lower-left or lower-right areas of the screen.

The 1.0.1 changelog contains two additions: SecretShot, described as “Stealthy screenshot,” and support for being enabled when the passcode is locked on the Lock Screen. These are the clearest user-facing changes attached to the packaged release. The available material does not define every SecretShot behavior or provide a full list of its configuration options, so users should treat the feature name as a description rather than assume a particular screenshot workflow.

  • Package version: 1.0.1.
  • Package identifier: com.ichitaso.bottomcontrolx.
  • The package lists ichitaso as maintainer and ichitaso/XCXiao as author information.
  • The package replaces and conflicts with com.xcxiao.bottomcontrolx.

Why the recent source changes matter

The upstream source history shows a sequence of lock-state changes behind the new behavior. One commit adds an isLocked state, updates it when the Cover Sheet appears, and resets it when the display-status notification is received. The gesture handling condition was changed so the original system behavior is allowed after the device is no longer locked; the commit message specifically says the BottomControlX gesture is now available after unlocking with Face ID or Touch ID.

A later commit describes a fix for CFNotification. Its code changes the display-status observer from coalesced delivery to immediate delivery. In practical terms, the source is attempting to refresh the tweak’s understanding of the lock state without waiting for notifications to be combined. The source supports describing this as a notification-delivery and lock-state handling change; it does not establish that every device will respond identically.

The source history also shows that the project’s build configuration targets arm64 and arm64e in the Makefile, while the published package stanza identifies the binary architecture as iphoneos-arm64. Readers compiling from source should not assume that the repository’s old build setup and the current packaged distribution have identical packaging behavior.

  • The source checks authentication differently for iOS 13 and later than for earlier versions.
  • Lock-state tracking was added around Cover Sheet appearance and display-status notifications.
  • The latest listed source fix changes the notification behavior to DeliverImmediately.
  • The repository README calls the project old, potentially buggy, and difficult to compile.

Compatibility is broader in the package depiction than in the README

Compatibility requires careful reading because the official materials describe different scopes. The repository README says BottomControlX supports all iOS devices with Fluid Gesture from iOS 11 to iOS 13. The current package depiction instead lists compatibility from iOS 11 through iOS 26 and identifies rootless, roothide, and rootful environments. It also records devices and versions under a “Tested” field: iPhone X on iOS 12.4, iPhone 12 mini on iOS 15.4.1, iPhone 14 Pro on iOS 16.5, iPad 6 on iOS 17.5.1, iPad 7 on iOS 18.6, and iPhone 11 Pro on iOS 26.0.1.

Those package-page entries are useful signals, but they do not eliminate the need to check a device-specific setup. The same depiction explicitly says the maintainer has not tested every device and is waiting for operational reports. It also lists a known issue: depending on the device, actions may be difficult to execute. The README’s warning that the project is old and may be buggy reinforces that this is not presented as a universally predictable tweak.

The package page says the release was made because SquidGesture could not be used on iOS 18 or later. That explains the intended role of this build in the maintainer’s current package ecosystem, but it is not a guarantee that BottomControlX will behave identically across all iOS 18-or-later devices.

  • Check the package depiction’s device and jailbreak-mode information against the exact phone or iPad being used.
  • Treat the iOS 11-to-26 listing as package-publisher compatibility information, not a promise of identical behavior on every device.
  • Expect possible gesture-execution difficulty on some hardware.
  • Note the README’s narrower iOS 11-to-13 description when evaluating older source documentation.

Dependencies, replacement behavior, and installation checks

The package declares firmware version 11.0 or later, MobileSubstrate, and PreferenceLoader as dependencies. These are package requirements rather than a guarantee that a particular jailbreak environment will handle the tweak correctly. Before installing, users should confirm that their package manager can satisfy those dependencies and that the selected package matches their jailbreak mode.

BottomControlX 1.0.1 replaces and conflicts with com.xcxiao.bottomcontrolx. That matters for users who already have the older package installed: the package metadata indicates that the two package identities should not coexist. The safest check is to review the package manager’s proposed upgrade, removal, or replacement actions before accepting them, especially if the older package was installed under the previous identifier.

The official depiction identifies the package as free and says configuration options are available from Settings. It does not provide a universal configuration recipe for every action, so users should review the available preferences after installation rather than assume all gestures are enabled or mapped the same way by default.

  • Required firmware: 11.0 or later.
  • Declared dependencies: MobileSubstrate and PreferenceLoader.
  • The package replaces and conflicts with the older com.xcxiao.bottomcontrolx identifier.
  • Settings is used to configure options.
  • Use the official package source shown by the package manager; avoid unofficial mirrors or repackaged builds.

Source availability and project condition

BottomControlX is released under GPL v3, and the official repository includes the tweak source, Makefile, preference directory, package metadata, and license. The README lists Theos and SettingsKit as compiling requirements and gives make package install as the build command. However, the same README warns that the project’s coding style is poor, that it may be buggy, and that compiling it may be difficult.

For most users, the published 1.0.1 package is the relevant release artifact. Developers considering a source build should compare the source revision with the package version and account for the repository’s age and stated build difficulties. The recent commits explain important lock-state behavior, but they do not amount to a modern compatibility certification or a promise of successful compilation with every current toolchain.

  • The project is licensed under GPL v3.
  • The README lists Theos and SettingsKit for compilation.
  • The repository warns that the project is old and may be buggy.
  • The source history documents lock-state and notification changes, but not comprehensive device testing.
