How to Enable JIT in Husk 0.7.0 with StikJIT, StikDebug or TrollStore

Husk needs JIT before it can run its Android translation workload. This guide shows which of Husk 0.7.0’s four JIT methods fits your device, then walks through built-in StikJIT, StikDebug and TrollStore without confusing iOS 26 support with iOS 27’s computer-free pairing.

By Zeeshan Barvi · Published October 6, 2026 · Verified against Husk 0.7.0’s official JIT documentation and source

Version scope: these steps are for Husk 0.7.0. Built-in StikJIT needs iOS 26 or newer, but only iOS 27 can create Husk’s pairing record entirely on the iPhone. On iOS 26, built-in StikJIT still needs a pairing file created on a computer.

Why Husk needs JIT

Husk translates Android code on iPhone and iPad. Its official README says that this requires executable memory and therefore an attached debugger on iOS. Installing or signing the IPA is not enough by itself: the app must also obtain JIT before starting the Android workload.

Husk 0.7.0 can request that debugger through StikDebug, TrollStore or its bundled StikJIT helper. The built-in helper removes the need for a second JIT app when its pairing and LocalDevVPN requirements are satisfied.

Choose the correct JIT method

MethodBest fitRequirements
AutomaticMost users who want Husk to select an available routeTries StikDebug first when installed, then TrollStore, otherwise built-in StikJIT
StikDebugExisting StikDebug setup or devices where built-in StikJIT is unsuitableStikDebug installed and configured; Husk hands off through its URL scheme
TrollStoreHusk installed through TrollStore on a TrollStore-compatible deviceA TrollStore installation of Husk; Husk requests JIT through TrollStore’s enable-JIT URL
Built-in StikJITiOS 26+ without a separate JIT appLocalDevVPN, the device’s remote pairing file and a sideloader that preserves and signs Husk’s helper extension

Select a method in Husk → Settings → JIT & sideload → Method. The default Automatic mode does not silently move to another method after a failure; Husk reports the selected path’s error so you can correct it.

Built-in StikJIT on iOS 27: pair entirely on the iPhone

  1. Open Husk and go to Settings → JIT & sideload → Set up JIT. The same walkthrough appears from first-run setup or when Start detects that JIT is missing.
  2. Choose Pair on this iPhone, tap Start pairing, and allow Local Network access.
  3. Open Settings → Privacy & Security → Developer Mode.
  4. Scroll down, tap Pair with Husk, and enter the code shown by Husk. The code can also appear in the background-task banner and a notification.
  5. Return to Husk and choose Connect LocalDevVPN. The VPN app should return to Husk through the husk:// URL scheme after connecting.
  6. Tap Check setup. Husk checks the VPN, downloads the matching Developer Disk Image, mounts it and verifies it.
  7. Tap Enable JIT, then start the Android workload.

Each new on-device pairing replaces Husk’s previous pairing record. If a connection reset makes the old file invalid, use the walkthrough’s Pair again option.

Built-in StikJIT on iOS 26: import a pairing file

iOS 26 supports Husk’s built-in StikJIT helper, but Husk’s own on-device pairing flow is documented for iOS 27. On iOS 26:

  1. Create the device pairing file on a computer using the official StikDebug pairing-file guide.
  2. In Husk’s JIT walkthrough, choose Use a pairing file and import the file made for that exact iPhone or iPad.
  3. Connect LocalDevVPN.
  4. Run Check setup so Husk can obtain and verify the matching Developer Disk Image.
  5. Tap Enable JIT.

A pairing file is device-sensitive. Do not use a file from another iPhone, and do not publish or share it.

Use StikDebug instead

  1. Install and configure StikDebug using its project instructions.
  2. In Husk, open Settings → JIT & sideload → Method.
  3. Select StikDebug.
  4. Start Husk’s workload. Husk uses its existing URL-scheme hand-off to request JIT from StikDebug.

This is also the fallback recommended by Husk’s documentation when a sideloader does not preserve or correctly sign the embedded HuskJITHelper app extension and StikJIT framework.

Use TrollStore on a compatible device

  1. Install Husk through TrollStore, not through a normal sideloader.
  2. Open Husk’s JIT method picker and select TrollStore.
  3. Start the workload. Husk asks TrollStore to enable JIT through apple-magnifier://enable-jit.

TrollStore is only an option on devices and firmware where TrollStore itself is supported. The presence of Husk’s method button does not make TrollStore available on iOS 26 or iOS 27. See our TrollStore IPA installation guide for the supported workflow.

Signing requirements that matter

For built-in StikJIT, Husk, HuskJITHelper and StikJIT.framework must be signed together. The current implementation reads the helper’s actual post-signing bundle identifier, which supports sideloaders such as SideStore and AltStore that append a development-team identifier. A signer that removes the extension or leaves its framework unsigned can still install the main app while breaking built-in JIT.

Husk’s documentation also distinguishes an installed app from a usable runtime: the build needs the debugger/JIT path at launch time. A developer certificate may keep the app installed longer, but it does not remove the JIT requirement.
