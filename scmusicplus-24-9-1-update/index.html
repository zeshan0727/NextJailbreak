SCMusicPlus 24.9.1 Targets SoundCloud 7.55.0, Adds Rootless Packages and Clarifies Project Status

Rov3r’s SCMusicPlus 24.9.1 jailbreak tweak is aimed at SoundCloud version 7.55.0 and removes several in-app monetization elements, including ads, promoted playlists and upgrade prompts. The release page also states that rootless Debian packages are now provided and that IPA files are no longer included in releases. A later repository update adds important context: network-served ads are not blocked by this version, and the maintainer recommends that users examine newer forks offering built-in network blocking and other improvements.

Key points

  • SCMusicPlus 24.9.1 is listed as supporting SoundCloud 7.55.0.
  • The release claims to remove ads, hide the upgrade tab, and suppress promoted playlists and upsell buttons.
  • Rootless Debian packages are provided; the release no longer includes IPA files.
  • The tweak does not block network-served ads by itself.
  • The maintainer says sign-in issues during sideloading are addressed when Sideloadly’s Sideload Spoofer option is used while compiling the IPA.
  • The repository now describes the project as effectively limited in scope and points users toward forks with built-in network blocking and other improvements.

What SCMusicPlus 24.9.1 changes

SCMusicPlus is a jailbreak tweak designed to alter the SoundCloud app’s handling of advertising and upgrade prompts. The official release notes for version 24.9.1 list support for SoundCloud 7.55.0 and identify three headline changes: ads are removed, the upgrade tab is hidden, and rootless Debian packages are supplied instead of IPA files in the release assets.

The project README describes a broader set of interface and playback-related goals. It lists removal of ads, promoted playlists and upsell buttons. The tweak source also disables several monetization and upsell checks inside SoundCloud’s classes, including checks associated with monetizable tracks, audio-ad playback events and upgrade prompts. Those implementation details explain the general direction of the package, but they should not be read as a guarantee that every form of advertising or promotion disappears.

  • Release target: SoundCloud 7.55.0.
  • Reported UI changes: removed ads and hidden upgrade tab.
  • README feature list: removal of ads, promoted playlists and upsell buttons.
  • Package identifier: com.rov3r.scmusicplus.
  • The package declares a MobileSubstrate dependency.

The most important limitation: network ads remain

The repository’s current known-issues section explicitly says that network-served ads are not blocked in this version. That qualification is central to understanding what the tweak does. SCMusicPlus changes application-side behavior, but the maintainer does not claim that it provides complete network-level ad blocking.

The README suggests using a DNS filter to block the SoundCloud advertising domain if users want broader ad filtering. That is an additional network configuration, not a built-in feature of SCMusicPlus 24.9.1. Results may therefore depend on how SoundCloud delivers a particular advertisement and whether the separate DNS configuration is active.

This limitation also explains why the project’s current status matters. In a 2026 update, Rov3r advises users to look at forks because other developers have added built-in network blocking and other improvements. The maintainer says the existing project is likely as far as it can be pushed with the current tools. Readers should treat the original package as a limited, maintenance-conscious option rather than assume it is the newest or most complete implementation available.

  • The tweak does not claim to block network-served ads.
  • The README recommends a separate DNS filter for broader blocking.
  • The maintainer points to forks with built-in network blocking and other improvements.
  • The repository does not promise complete ad removal in every delivery path.

Rootless packaging and build implications

The 24.9.1 release notes specifically call out rootless Debian packages. The README says the project can be built through GitHub Actions and that the workflow produces both rootful and rootless Debian packages in a ZIP archive. This gives developers a documented build path and separates the package format from the application itself.

The repository’s build workflow contains distinct rootless and rootful jobs. The rootless job produces an arm64 Debian package, while the rootful job produces an arm package. The workflow also checks out Theos and SDK components before invoking the package build. These details describe the project’s build configuration; they do not establish broad device or iOS compatibility beyond what the release explicitly states.

The package control metadata identifies version 24.9.1-3 and an iphoneos-arm architecture. Because the release page identifies SoundCloud 7.55.0 as the supported app version, users should compare their installed SoundCloud version with that target before applying the tweak. The supplied materials do not provide a wider SoundCloud-version compatibility list.

  • The release includes rootless Debian packages.
  • The project documents both rootful and rootless build jobs.
  • The workflow’s rootless artifact is arm64; the rootful artifact is arm.
  • Package metadata reports version 24.9.1-3.
  • The explicit app target is SoundCloud 7.55.0.

Sideloading guidance has changed

The repository no longer documents the earlier, detailed sideloading procedures that appeared in older revisions. Its current Sideloading section says that previous sign-in problems are fixed by using Sideloadly’s Sideload Spoofer option when compiling the IPA.

The release notes also explain that IPA files are no longer included with releases. This change is described as a way to improve the longevity of the tweak, while rootless Debian packages are now provided. In practical terms, sideloading requires users to handle the SoundCloud application and package-building process separately rather than downloading an IPA directly from the release assets.

The source material does not provide a general compatibility matrix for sideloading methods, signing services or iOS versions. Users should therefore avoid assuming that a successful package build guarantees installation or sign-in behavior on every device. Before proceeding, check the repository’s current instructions, issue reports and package depiction for the exact release details.

  • The current README recommends Sideloadly’s Sideload Spoofer option when compiling an IPA.
  • IPA files are no longer included in the release assets.
  • The supplied material does not establish universal sideloading compatibility.
  • Users should consult the project’s issue tracker and current package information before proceeding.

What to verify before installing

The first check is the SoundCloud app version. The release page lists 7.55.0, so users on another version should not assume that the same hooks or behavior will work. The project source modifies named SoundCloud classes and methods, which can change between app versions.

The second check is the package type required by the device’s jailbreak environment. The repository documents rootful and rootless builds, but the correct choice depends on the user’s existing setup. Installing the wrong package type can lead to failure or an unusable installation, so the environment should be identified before selecting an artifact.

Finally, set expectations about advertising. SCMusicPlus may suppress the application-level elements described by the maintainer, but network-served ads remain a known issue. Users who need network blocking should evaluate the separate DNS approach mentioned by the project or investigate the newer fork direction identified by Rov3r. The source does not establish that any fork is officially supported by the original package, so those options should be reviewed independently.

  • Match the tweak to SoundCloud 7.55.0 unless the project publishes updated compatibility information.
  • Select rootful or rootless packaging according to the existing jailbreak environment.
  • Review the current known issues and changelog before updating.
  • Do not expect the package alone to block all network-served ads.
  • Use only source-authenticated project materials and avoid unverified IPA packages.
