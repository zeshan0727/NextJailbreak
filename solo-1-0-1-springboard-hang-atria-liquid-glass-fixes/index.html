Solo 1.0.2 Fixes iOS 15 Crash and Atria Carousel Widgets

Solo 1.0.2 fixes an iOS 15 device-check crash and several Atria carousel-widget bugs, while adding experimental, untested iOS 14 and rootful iOS 15 support.

Published November 17, 2026Updated November 19, 2026By Zeeshan Barvi
Quick answer: Solo 1.0.2 is a worthwhile update for iOS 15 users and anyone pairing Solo with Atria. It fixes an iOS 15 crash caused by the iPad device-type check and repairs several carousel-widget layout problems. The new iOS 14 and rootful iOS 15 path is explicitly experimental and untested, so it should not be treated as stable support.

What changed in Solo 1.0.2

iOS 15 device-check crash fixed

The most important general fix targets a crash on iOS 15 caused by Solo’s iPad device-type check. This is a specific runtime fix; it does not expand jailbreak availability or confirm every iOS 15 device and tweak combination.

Atria compatibility should apply after one respring

The developer says Atria compatibility now takes only one respring to take effect. That should remove the previous extra restart cycle when Solo and Atria are configured together, but custom layouts may still need adjustment because both tweaks modify the Home Screen.

Carousel widget placement and sizing fixes

  • Carousel widgets should no longer be sized incorrectly in some layouts.
  • Dragging a widget from the app list into the carousel should no longer create it at the top-left of the screen in an unremovable state.
  • Widgets should once again push apps off the page correctly.
  • The visual app-overflow indicator should return when a widget is moved from a page into the carousel.

Experimental iOS 14 and rootful iOS 15 build path

Version 1.0.2 adds what the changelog calls experimental iOS 14 and rootful iOS 15 support. The developer also describes this path as untested and says it should only “semi-work” in theory. Users should read that as a development preview, not a compatibility guarantee. The main package description still presents iOS 15–26 rootless as the normal supported configuration.

What Solo 1.0.1 already fixed

The previous 1.0.1 release remains relevant context: it fixed SpringBoard hangs involving medium or large widgets, a Safe Mode crash caused by looking for a missing method in an older Liquid (Gl)ass build, App Library search scaling with Atria, first-install Atria layout adaptation and occasional carousel-widget resizing. Version 1.0.2 includes those fixes and adds the newer crash and widget corrections above.

Compatibility and unsupported setups

Solo’s official description says the normal target is iOS 15 through 26 on rootless jailbreaks. Havoc’s structured package metadata now lists iOS 14.0 through 26.0.1, but the developer’s changelog makes clear that iOS 14 and rootful iOS 15 are experimental. RootHide is explicitly unsupported, and no stock-iOS, TrollStore-only or ordinary sideload installation path is documented.

A tweak’s firmware range is not a jailbreak compatibility chart. Solo cannot make an unsupported iPhone or firmware jailbreakable. Confirm your exact device, iOS build and jailbreak first using the jailbreak tweak compatibility checklist.

Safe update steps

  1. Take screenshots of your current Home Screen, Atria grid, dock and carousel configuration.
  2. Update Solo only from its official Havoc package through Sileo or Zebra. Our Sileo tweak installation guide covers the package workflow.
  3. Respring once and check widget sizing, app displacement, the dock and App Library before changing more settings.
  4. If you also use Atria, confirm its layout after the first respring before resetting either tweak. See the Atria compatibility article for its separate RootHide and package limits.
  5. Do not test the experimental rootful lane on a device where recovery access is uncertain.

Troubleshooting after updating

SpringBoard crashes or hangs

Start the jailbreak with tweak injection disabled, open Sileo or Zebra, and update or remove Solo. Respring before restoring other Home Screen tweaks. The Dopamine bad-tweak recovery guide explains the safe sequence.

A carousel widget is still misplaced

Remove the affected widget after confirming you are on 1.0.2, respring once, then add it again from the carousel. Avoid changing Atria and Solo layout settings in the same test cycle.

Atria changes do not appear

Respring once, as the 1.0.2 changelog now expects compatibility to apply in one cycle. If the layout remains wrong, temporarily disable one Home Screen tweak to identify which preference set controls the grid.

RootHide installation fails

Do not convert or force the rootless package. The developer explicitly excludes RootHide, so a package-manager error or missing injection is not evidence that the firmware itself is unsupported.
