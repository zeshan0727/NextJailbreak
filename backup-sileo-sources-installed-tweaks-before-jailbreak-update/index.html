How to Back Up Sileo Sources and Installed Tweaks Before a Jailbreak Update

Export Sileo repository URLs and record installed package IDs, versions and architectures before updating, removing or switching a jailbreak.

By Zeeshan Barvi · Published October 9, 2026 · Source behavior checked against Sileo 2.5.1

What this backup actually preserves

A safe pre-update record has two parts: the repository URLs Sileo can use to find packages, and an inventory of package identifiers already installed in the active jailbreak environment. These are reference lists, not a full system image.

  • Sileo source export: saves the raw URLs for repositories currently shown in Sileo.
  • Package inventory: records each installed package ID, version and architecture reported by dpkg-query.
  • Not included: tweak preferences, app data, jailbreak settings, package archives and files installed outside APT/dpkg.

Make this record before updating the jailbreak, removing it, moving between rootful and rootless, or troubleshooting a package-manager failure. If the device is already unjailbroken and the old environment cannot be started, its package database may not be available.

1. Export your Sileo repository URLs

  1. Open Sileo and select the Sources tab.
  2. Tap Edit.
  3. Tap Export, confirm the prompt, and save or send the resulting text with the iOS share sheet.
  4. Open the saved file and confirm that it contains one repository URL per line.

This sequence is not inferred from a screenshot: Sileo 2.5.1’s official source changes the right navigation button to Export while the Sources screen is in edit mode. Its export function joins every repository’s raw URL with newline separators and passes that text to the system share sheet.

Store the text somewhere outside the jailbreak filesystem, such as Files on iCloud Drive, an encrypted note or your computer. A copy kept only inside the environment you are about to remove is not a useful backup.

2. Record installed package IDs, versions and architectures

Open a terminal inside the currently active jailbreak environment and run:

dpkg-query -W -f='${binary:Package}\t${Version}\t${Architecture}\n'

The Debian dpkg-query manual documents -W for listing matching installed packages and -f for choosing the output fields. This command prints a tab-separated inventory that distinguishes package identity from the display name shown in a package manager.

To save the same output to a file in the terminal’s current directory, use:

dpkg-query -W -f='${binary:Package}\t${Version}\t${Architecture}\n' > jailbreak-packages.tsv

Copy the resulting file off the device before removing or replacing the jailbreak. If your terminal app cannot share files, print the list without redirection and copy the output. Do not publish the list publicly without reviewing it; package names can reveal private repositories or security tools you use.

3. Add a short manual note

Package metadata cannot explain every part of a setup. Add the device model, iOS version, jailbreak name and version, and whether the environment is rootful, conventional rootless or RootHide. Also note any packages installed from local DEB files, because their original repository may not appear in the exported source list.

A useful header looks like this:

Device: iPhone model
iOS: exact version
Jailbreak: name and version
Environment: rootful / rootless / RootHide
Backup date: YYYY-MM-DD

4. Restore cautiously after the change

On Sileo 2.5.1, the add-source menu includes Import Repos. Import the saved URL list, refresh sources, and review any errors before installing packages. A repository may have moved, closed or stopped supporting your new environment.

Use the package inventory as a checklist rather than an automatic reinstall script. Check each important tweak against its current official package page, dependencies and architecture. A package that worked in a rootful environment is not automatically valid on conventional rootless or RootHide, even if its marketing page lists the same iOS version.

For local packages, follow the Sileo local DEB guide. Before reinstalling anything, use the tweak compatibility checklist. If Sileo reports an interrupted transaction, follow the dpkg repair guide instead of deleting lock files.

What not to do

  • Do not copy an entire APT or dpkg database into a different jailbreak environment.
  • Do not bulk-install every package from the inventory; it includes libraries and dependencies that the package manager should resolve.
  • Do not assume iphoneos-arm, iphoneos-arm64 and RootHide packages are interchangeable.
  • Do not call this a preference backup. Tweak settings normally require a separate, carefully scoped backup and may not be portable.

Quick checklist

  • Sources exported from Sileo and opened successfully
  • Package inventory includes ID, version and architecture
  • Device, iOS, jailbreak and environment written down
  • Local-DEB packages noted separately
  • Copies saved outside the jailbreak filesystem
  • Reinstallation planned one package at a time
