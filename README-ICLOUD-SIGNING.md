# Next Ledger 1.3.82 — iCloud Documents / personal developer certificate installation

**Source branch:** `feature/next-ledger-1.3.82-auto-cloud-backup`

**Built artifact:** [GitHub Actions run 39376758338](https://github.com/zeshan0727/NextJailbreak/actions/runs/39376758338). It contains the unsigned `NextLedger-1.3.82-iCloud-Signing-Ready.ipa`, its SHA-256, and `NextLedger-1.3.82-iCloud.entitlements` generated by XcodeGen.

**Bundle ID:** `com.nextsolution.dailyledger` (unchanged from 1.3.81).

**iCloud container:** `iCloud.com.nextsolution.dailyledger`. The app must be granted the `CloudDocuments` entitlement plus the iCloud/ubiquity container identifiers in an Apple provisioning profile.

## Signing on your own computer

1. In Apple Developer → Identifiers, use an **explicit** App ID `com.nextsolution.dailyledger`. Enable iCloud and associate container `iCloud.com.nextsolution.dailyledger`.
2. Make sure your iPhone UDID is registered in Apple Developer → Devices.
3. Create **Ad Hoc** provisioning profile for the App ID using your Apple Distribution certificate and the iPhone UDID. Download the resulting `.mobileprovision` file.
4. Sign the **unsigned IPA** using your own `.p12` private key and the matching `.mobileprovision`, preserving the iCloud entitlements. Do not just sign with a generic provisioning profile or strip entitlements; the iCloud container will return nil.
5. Verify the final signed app includes `com.apple.developer.icloud-services = CloudDocuments`, the correct container entitlement and `embedded.mobileprovision`. Install using an authorized iOS IPA installation method on the registered device. Enable Developer Mode if required.
6. On the iPhone, enable iCloud Drive, turn on Next Ledger's **iCloud Drive Sync** in Settings → Backup & Sync, then create a test transaction and confirm a JSON file appears in Files → iCloud Drive → Next Ledger → DailyLedger.

**Critical migration warning:** Changing from TrollStore installation to Ad Hoc signing may not preserve the same app container. Before replacing or uninstalling your existing app, export your ledger JSON to Files/Google Drive, independently verify it and retain the previous working TIPA. Never erase the original app expecting iCloud to contain your data already.

## Automatic backup behavior

- `DailyLedger/Services/BackupSyncService.swift` writes validated versioned backups on app launch and after saved ledger changes; it retains the latest plus nine previous versions per destination.
- The original bank SMS importer and app accounting screens are retained.
- The iCloud folder becomes available only after installing a correctly provisioned build. The app cannot guarantee the remote upload has finished merely because its local iCloud-container write succeeded.
- A new backup of a zero-transaction ledger is deliberately refused to avoid overwriting useful history with empty data.

**Private-key security:** Never commit private `.p12` keys, their passwords, or provisioning profiles to the GitHub source tree. Keep certificate signing on your own trusted PC/Mac.
