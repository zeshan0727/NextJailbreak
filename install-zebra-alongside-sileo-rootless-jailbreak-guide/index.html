How to Install Zebra Alongside Sileo on a Rootless Jailbreak

Zebra and Sileo can coexist. Add Zebra’s official repository to a working Sileo installation, let APT select the build compatible with your jailbreak, review the queue, and keep Sileo until Zebra has completed a clean source refresh and package transaction.

By Zeeshan Barvi · Published October 27, 2026 · Verified against Zebra’s official site, repository and releases

Before you begin: Zebra is not a jailbreak. The official project requires a jailbroken device. This guide assumes Sileo already works in a compatible rootless environment; it does not expand the device or firmware support of Dopamine, palera1n, or any other jailbreak.

What this method changes

Zebra and Sileo are interfaces for APT, the package system used by modern jailbreak bootstraps. Installing Zebra does not create a second bootstrap or duplicate every installed tweak. Both managers read the same installed-package state, so a package installed in one should appear installed in the other after a refresh.

The practical reason to keep both is recovery and preference: you can learn Zebra’s interface while retaining a known-working manager. Do not remove Sileo merely to make Zebra the daily manager. First confirm that Zebra can refresh sources, display installed packages and complete a harmless package transaction on your setup.

Requirements

  • An already-jailbroken iPhone or iPad with an active, supported rootless environment.
  • A working Sileo installation that can refresh its current sources without APT or dpkg errors.
  • The official Zebra repository: https://getzbra.com/repo/.
  • A compatible Zebra package offered to the active jailbreak. Rootless packages use the iphoneos-arm64 architecture.

Zebra’s official site calls it an open-source package manager for jailbroken iOS devices and publishes the repository address above. Zebra 1.1.37, released August 7, 2026, is the current tagged release checked for this guide. Its initial release channel was tied to Dopamine 3, so users of other jailbreaks should install only the version their official repo or bootstrap actually offers rather than forcing a downloaded DEB.

Step 1: make sure the jailbreak is active

After a full device reboot, a semi-untethered jailbreak such as Dopamine is no longer active until you run its jailbreak process again. Open your jailbreak app and confirm the environment is active before troubleshooting Sileo or trying to add another manager. Zebra cannot replace that step.

Open Sileo and refresh the existing sources once. If the refresh already reports dependency, lock or interrupted-dpkg errors, resolve those first with the Sileo package-manager repair guide. Adding another frontend does not repair a broken package database.

Step 2: add Zebra’s official repository in Sileo

  1. Copy https://getzbra.com/repo/ exactly from Zebra’s official site.
  2. In Sileo, open Sources, tap the add button, and paste the repository address.
  3. Confirm the addition and wait for Sileo to finish refreshing. Do not close Sileo or respring while the source indexes are downloading.
  4. Open the new Zebra source from the Sources list. If the address redirects somewhere unexpected or the source shows unsigned or unrelated packages, cancel and re-check the URL.

Avoid search-result download pages, signing services and repositories that repackage Zebra. The project states that Zebra and jailbreaks are free and warns that anyone charging for the download is a scam.

Step 3: verify the package before installing

Search for Zebra from the official source and inspect the package page before tapping Get. Confirm the developer or source is Zebra Team, the displayed version is the one offered for your environment, and the queue does not propose removing the jailbreak bootstrap, core APT packages or Sileo.

The Zebra 1.1.29 release documentation explains the architecture split: iphoneos-arm is for traditional root-filesystem jailbreaks, while iphoneos-arm64 is for rootless jailbreaks on iOS 15 and later. That architecture information describes the package format; it is not proof that every iOS version or device has a compatible jailbreak.

Step 4: install, return to the Home Screen, and test

  1. Tap Get or Install only after the queue passes the checks above.
  2. Let dpkg finish. Use the return, respring or restart action that the package manager presents; do not force-close the app during configuration.
  3. Open Zebra and allow its initial source refresh to complete.
  4. Open Zebra’s installed-packages view and confirm that packages previously installed through Sileo are visible.
  5. Install or update only a small, known-compatible package as a first transaction. Review the queue again before confirming.

If Zebra’s icon does not appear even though the package installed, use the jailbreak’s supported app-registration or SpringBoard refresh controls. On Dopamine, follow the order in the missing Sileo and jailbreak-app icons guide instead of repeatedly reinstalling the package.

Alternative on Dopamine: use its package-manager control

Dopamine includes a Reinstall Package Managers action that can repair or install its supported managers. If Zebra is offered there for the version of Dopamine you are running, this is a valid bootstrap-managed route. Select Zebra deliberately, allow the action to finish, and restart SpringBoard if the app icon does not register immediately.

Use that control as a package-manager install or repair action, not as a universal fix for every missing jailbreak application. If Sileo, Zebra, Filza and other apps all disappear together, refresh jailbreak app registrations first.

How to use both managers safely

  • Let one package transaction finish before opening the other manager. Do not run simultaneous installs or source refreshes.
  • Keep repository URLs consistent. A source added in one frontend may need to be added or refreshed in the other depending on its source-list handling.
  • Judge each tweak separately. Appearing in Zebra or Sileo does not prove rootless, RootHide, device or firmware compatibility.
  • Do not use one manager to override dependency warnings raised by the other; both ultimately rely on the same package database.
  • Before a large upgrade, use the source and installed-package backup guide.

Removing Zebra without removing your tweaks

If you decide to return to Sileo only, confirm Sileo still opens and refreshes first. Then remove the Zebra application package through Sileo and review the removal queue. Cancel if the queue includes bootstrap essentials or installed tweaks that are unrelated to Zebra.

Removing the frontend should not be treated as removing the jailbreak or all packages. Do not manually delete Zebra files from Filza, and do not erase APT or dpkg databases to “clean up” the manager.

Frequently asked questions

Can Zebra replace Sileo?

It can be your preferred APT frontend on a supported jailbreak, but keep Sileo until Zebra has refreshed sources and completed a normal transaction. Having a working fallback is useful.

Can Zebra and Sileo install different versions of the same tweak?

They use the same package state, so forcing conflicting versions is unsafe. Refresh sources and resolve the repository or dependency difference instead of trying simultaneous transactions.

Why does Sileo show an incompatible-architecture error?

The package does not match the bootstrap architecture. Rootless environments use iphoneos-arm64; do not force a rootful iphoneos-arm DEB into them.

Can I install Zebra without a jailbreak?

No. The official Zebra project explicitly requires a jailbroken iOS device. A sideloaded lookalike cannot provide the jailbreak package-management environment.

Is Zebra 1.1.37 compatible with every jailbreak?

No universal claim is made here. The release was initially distributed for Dopamine 3. Other environments should use only the build their official bootstrap or Zebra repository offers.

For feature and release differences rather than installation steps, see Sileo vs Zebra in 2026. For jailbreak and firmware boundaries, check the applicable jailbreak’s official documentation instead of inferring support from the package manager.
