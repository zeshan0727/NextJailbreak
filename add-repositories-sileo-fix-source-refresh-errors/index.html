How to Add Repositories to Sileo and Fix Source Refresh Errors

A Sileo source is an APT repository, not proof that a tweak supports your device. This guide shows the safe way to add a developer’s official repository, refresh one problem source, remove it when necessary, and interpret the error instead of repeatedly forcing a broken URL.

By Zeeshan Barvi · Published October 7, 2026 · Verified against the official Sileo 2.5.1 source

Version scope: the interface labels and behavior below were checked against Sileo 2.5.1, the current official tagged release. Sileo requires a compatible jailbreak environment. Adding a repository cannot jailbreak a device or make an incompatible package safe.

Before adding a repository

Get the APT URL from the developer’s official project page, package listing or verified profile. Do not substitute a copied paid-package mirror. Sileo’s source code checks flagged repositories and shows an explicit warning for sources associated with piracy, illegal content or malware.

  • Confirm that the URL belongs to the developer or established repository.
  • Keep the complete https:// URL, including its path when the developer supplies one.
  • Check whether the package is rootless, rootful or RootHide compatible. See our rootless vs rootful vs RootHide guide.
  • Remember that an iOS compatibility label describes the package—not whether a jailbreak exists for every device on that iOS version.

How to add a repository to Sileo

  1. Copy the exact repository URL from the official source.
  2. Open Sileo and select the Sources tab.
  3. Tap the add button. If Sileo detects a URL on the clipboard, it can offer to add the detected source; otherwise choose manual entry.
  4. Review the displayed URL. Sileo’s manual dialog is titled Add Source and asks for an APT URL.
  5. Tap Add Source and let the repository finish refreshing.
  6. Open the new source and verify that its package list and developer identity match the page from which you copied the URL.

For a normal “flat” jailbreak repository, use Add Source. Sileo also exposes an advanced distribution-repository option with suites and components; do not use that unless the repository owner publishes those exact values.

What Sileo checks when a source is added

For a single ordinary URL, Sileo 2.5.1 makes a request to the repository’s Release path before adding it. If that check fails, Sileo warns that the URL may be offline or entered incorrectly and asks whether to add it anyway. That warning is useful evidence—not a prompt to keep forcing an unknown source.

Sileo also checks the URL against its flagged-source service. If it presents a harmful-repository warning, the safe choice is to go back and locate the developer’s legitimate source.

Refresh one source instead of every repository

If only one repository is failing, open Sources and swipe left on that source. Sileo 2.5.1 exposes two actions:

  • Refresh updates only that repository.
  • Remove deletes the source from Sileo.

Try the single-source refresh once after confirming internet access. If the same error persists, read the message and use the matching fix below. Repeated global refreshes do not repair an invalid URL, expired signing key or broken repository metadata.

Sileo source errors and the correct response

Error or symptomWhat it usually meansSafe action
Repository “does not appear to be valid”Sileo could not validate the source’s Release path; the URL may be wrong or the server may be offline.Cancel, reopen the developer’s official page and copy the exact URL. Add anyway only when the repository owner confirms the URL and temporary outage.
404 Not Found or missing ReleaseThe source path no longer exists, redirected incorrectly or is not an APT-repository root.Remove the source and obtain its current official URL. A normal website homepage is not automatically a Sileo source.
NO_PUBKEY, bad signature, expired or revoked keyAPT cannot establish the expected repository signature trust.Do not bypass the warning or install an unauthenticated replacement. Check the repository owner’s status and wait for corrected signing metadata.
Hash or file-size mismatchThe server or CDN is serving metadata and package indexes from different update states.Wait, then refresh that source once. If it continues, remove it temporarily and report the exact output to the repository owner.
401 or 403The repository needs authorization, purchase/account access, or is refusing the request.Use the repository’s legitimate account flow or contact its support. Do not use a mirror to evade access controls.
Source refreshes, but the tweak is absentThe package may be hidden for your architecture, removed, renamed or not published in that repository.Check the package’s official listing and required architecture. Do not assume the source is broken.
Package appears but cannot be installedA dependency, firmware, architecture or jailbreak-environment requirement is unmet.Read the package details and dependency output. Repository refresh success does not prove tweak compatibility.

Remove and re-add a broken source safely

  1. Record the exact URL and error text if you need to report the problem.
  2. In Sources, swipe left on the failing repository and choose Remove.
  3. Close and reopen Sileo only if the list does not update normally.
  4. Return to the developer’s official page and verify whether the URL changed.
  5. Re-add the source once. If the same server-side or signature error returns, leave it removed and wait for the maintainer.

Removing a repository does not automatically remove packages already installed from it. Those packages may simply stop receiving updates. Review installed packages before deleting a source you rely on.

Do not mix package compatibility with jailbreak availability

A repository can advertise a tweak for iOS 18 or iOS 26 even when your specific device has no usable jailbreak on that firmware. Sileo manages packages inside an existing jailbreak; it does not supply the exploit, jailbreak or kernel access. For current jailbreak boundaries, use the Dopamine 3 compatibility guide and our iOS 27 jailbreak status.

Quick checklist

Use: the developer’s official HTTPS repository URL.

One failing source: swipe left and choose Refresh.

Wrong or retired URL: swipe left and Remove.

Signature warning: stop and wait for the maintainer.

Package missing: check architecture and environment.
