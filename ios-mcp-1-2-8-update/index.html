iOS MCP 1.2.8 adds system-language settings support for jailbroken iPhones

The iOS MCP project has moved to version 1.2.8, with the latest source changes centered on its Settings interface. The update adds localization support that follows the device’s preferred language and includes English, Simplified Chinese and Traditional Chinese resources. The release also updates the server, package metadata, preference bundle, health-check example and OCR package test defaults from 1.2.7 to 1.2.8. The underlying MCP capabilities and stated jailbreak compatibility remain the same in the supplied source material.

Key points

  • iOS MCP 1.2.8 adds automatic settings localization for English, Simplified Chinese and Traditional Chinese.
  • The language is selected from the device’s preferred-language list, with no manual language selector or saved language override described by the source.
  • The update changes the reported server and package version from 1.2.7 to 1.2.8; the source does not describe a new MCP tool or a protocol-version change.
  • Supported environments remain rootful on iOS 13–18, rootless on iOS 15–18 and roothide on iOS 15–18, subject to matching package architecture.
  • The service has no built-in authentication, and its shell, file, logging and device-control capabilities make trusted-network use essential.

What changed in iOS MCP 1.2.8

The most visible change in iOS MCP 1.2.8 is a localized Settings experience. The project’s recent source changes add a new preference localization implementation and include it in the preferences target. The Settings page now follows the device’s preferred language and supports English, Simplified Chinese and Traditional Chinese without requiring a manual language choice.

The localization work covers more than a translated heading. The updated preference controller localizes visible specifier names, footer text, placeholders and custom-cell captions. It also localizes status messages, port-validation alerts, server start and stop text, prompt-sharing errors, debug-log labels and other user-facing strings. The QR-code cell was updated to use localized captions and to calculate its caption height dynamically, while the restart button adjusts its width for translated text.

The implementation uses the device’s preferred language list rather than its regional setting. The source comments also state that the preference bundle is used independently of the host application’s resource bundle and that there is no saved language override or cached language selection. If none of the supported languages is selected, English is used as the fallback.

  • Supported settings languages: English, Simplified Chinese and Traditional Chinese.
  • No manual language-selection control is described.
  • Translated text includes controls, alerts, status messages, prompt-sharing text and debug-log interface labels.
  • The settings build now includes the added localization source file.

Version and packaging updates

The 1.2.8 change also updates version identifiers across the project. The server constant in MCPServer.m changes from 1.2.7 to 1.2.8, and the Debian control metadata reports version 1.2.8. The preference bundle’s short version and bundle version are updated as well.

The project’s documented health response now identifies the server as version 1.2.8. The source continues to list MCP protocol version 2025-11-25 as the default, with compatibility for 2025-06-18 and 2025-03-26. Nothing in the supplied commit material indicates that those protocol versions changed in this update.

The OCR package test script also changes its default version argument from 1.2.7 to 1.2.8. That is a tooling and version-reference update; it should not be read as a new OCR engine feature. The README continues to describe two selectable OCR paths: offline PaddleOCR with ONNX Runtime CPU, or Apple Vision. Engine selection remains per request, and the documentation says a failed engine does not automatically switch to the other one.

  • Server version: 1.2.8.
  • Package metadata version: 1.2.8.
  • Preference bundle versions: 1.2.8.
  • Default health-check example: server version 1.2.8.
  • MCP protocol versions remain listed as 2025-11-25, 2025-06-18 and 2025-03-26.

What the project still provides

iOS MCP is an MCP server designed to run on jailbroken iPhones and expose device inspection and control to AI agents such as Claude, Codex and Cursor. The README lists 46 MCP tools across touch, hardware buttons, text entry, screenshots, application management, accessibility, clipboard, filesystem access, logs, device controls, device information, URL handling and Shell execution.

For automation, the tool set includes coordinate-based taps, swipes, long presses, double taps and drag-and-drop, along with HID-style Home, power, volume and mute operations. Text tools support clipboard-oriented input, character-by-character HID input and special keys. The accessibility and screen-analysis group can retrieve UI elements, locate elements by coordinates, tap by text or label, wait for elements to appear or disappear, and perform OCR or screen description.

The project also documents application installation support for IPA, TIPA and DEB files. Computer-local files must first be uploaded through the service’s upload endpoint before the resulting device path is passed to the installation tool. These capabilities are significant because the MCP server is not limited to passive screen observation: it can affect applications, files, logs and system state.

  • 46 MCP tools are documented by the project.
  • Supported areas include UI automation, app management, OCR, files, logs, device information and Shell commands.
  • The OCR interface supports PaddleOCR or Apple Vision through an optional per-request engine parameter.
  • Application installation supports IPA, TIPA and DEB file extensions according to the README.

Compatibility and installation considerations

The project states that it requires a jailbroken iOS device. Its support table lists rootful jailbreaks on iOS 13 through iOS 18 using the iphoneos-arm package architecture. Rootless is listed for iOS 15 through iOS 18 with iphoneos-arm64, while roothide is listed for iOS 15 through iOS 18 with iphoneos-arm64e.

Those entries describe the project’s stated support matrix, not a guarantee for every device or jailbreak configuration. Before installing, readers should identify their jailbreak type, iOS version and required package architecture. The README also lists mobilesubstrate or ElleKit and preferenceloader as dependencies for manual installation.

The documented installation routes are a matching package from the project’s Release page or direct installation through Cydia or Sileo by searching for iOS MCP. After installation, the project recommends restarting SpringBoard and checking the local health endpoint in a browser. A successful response should report status ok, the ios-mcp server name, version 1.2.8 and the supported MCP protocol versions.

The supplied source does not provide evidence that the 1.2.8 build was tested on every listed jailbreak type or iOS version. Users should therefore treat the compatibility table as the maintainer’s stated target and consult the project’s current installation material before changing a working setup.

  • Rootful: iOS 13–18, iphoneos-arm.
  • Rootless: iOS 15–18, iphoneos-arm64.
  • Roothide: iOS 15–18, iphoneos-arm64e.
  • Manual installation requires the dependencies listed by the project.
  • A SpringBoard restart and health check are recommended after installation.

Security implications remain central

The new localization feature does not change the service’s security model. The project explicitly states that the MCP server has no built-in authentication and recommends using it only on a local or otherwise trusted network. This matters because the tool surface includes commands that can inspect or modify a device.

The run_command tool can execute arbitrary Shell commands. The documentation places read_file, write_file and download_file at a similar risk level because they can access paths within the MCP process’s permission scope. The get_syslog tool can read live system-wide logs for apps, and the project warns that those logs may contain sensitive information.

The README also describes restricted root elevation through mcp-root. It is limited to bundled helpers, selected chmod and launchctl operations, no-argument id, and constrained dpkg operations; the project specifically says it is not a general sudo replacement. When the device is locked or the screen is off, the server blocks several interactive or mutating tools, including taps, swipes, text input, app launch and Shell commands, while retaining observation, screenshots and wake or recovery functions.

These controls reduce some accidental interaction risks, but they do not substitute for network isolation and careful authorization. Anyone configuring an AI agent to use this server should review which tools the agent can invoke and avoid exposing the service beyond a trusted environment.

  • There is no built-in authentication.
  • Shell execution and file access can affect the device within the service’s permissions.
  • System logs may contain sensitive data.
  • Locked or screen-off devices restrict several interaction and mutation tools.
  • The project’s mcp-root helper is described as restricted rather than a general sudo mechanism.

Frequently asked questions

What is new in iOS MCP 1.2.8?

The documented feature change is automatic localization of the Settings interface. It follows the device’s preferred language and supports English, Simplified Chinese and Traditional Chinese. The release also updates version references and package metadata from 1.2.7 to 1.2.8.

Does iOS MCP 1.2.8 add new MCP tools?

The supplied 1.2.8 commit material does not identify a new MCP tool. The README continues to describe 46 tools, and the listed protocol versions remain unchanged.

Which languages does the Settings page support?

The project lists English, Simplified Chinese and Traditional Chinese. The implementation chooses from the device’s preferred-language settings and falls back to English when another supported language is not selected.

Which jailbreak environments are listed as compatible?

The README lists rootful on iOS 13–18 with iphoneos-arm, rootless on iOS 15–18 with iphoneos-arm64, and roothide on iOS 15–18 with iphoneos-arm64e. Users still need to match the package to their actual environment and review current project guidance.

How can users check whether the service started?

The project recommends restarting SpringBoard and opening the device’s port-8090 health endpoint from a browser. The documented successful response reports status ok, server ios-mcp and version 1.2.8.

Before installing: confirm the current package version, compatibility and dependencies at the original developer/repository source for your exact device and jailbreak.
