AppBadgeClear 1.1.1 Adds Smarter Notification Clearing for Rootless iOS 16 and 17 Jailbreaks

AppBadgeClear 1.1.1 expands its Home Screen quick action beyond removing an app’s visible badge. The update can also clear that app’s currently delivered notifications, prevent stale badge state from being restored immediately, and return to normal badge behavior when a genuinely new notification arrives. The package listing identifies rootless iOS 16 and iOS 17 jailbreaks as supported, while iOS 18 and newer are not supported.

Key points

  • Version 1.1.1 adds optional clearing of an app’s currently delivered notifications.
  • The tweak is designed to prevent old or stale notification state from immediately restoring a cleared badge.
  • Timestamp-based detection lets new notifications restore normal badge behavior automatically.
  • The official depiction lists rootless iOS 16 and iOS 17 jailbreak compatibility and excludes iOS 18 and newer.
  • The package depends on MobileSubstrate, PreferenceLoader, and firmware from iOS 16.0 up to—but not including—iOS 18.0.
  • The tweak cannot modify third-party account data or mark messages as read on an app’s server.

What AppBadgeClear 1.1.1 changes

AppBadgeClear is a jailbreak tweak that adds a Clear Badge action to an app icon’s Home Screen long-press menu. Its purpose is to remove an app’s current badge without requiring users to open the app or work through its notification settings.

Version 1.1.1 broadens that behavior with an optional setting called Clear Current Notifications Too. When enabled, the tweak clears the app’s currently delivered notifications as well as its current badge. The release notes also say it prevents an app from immediately restoring stale badge state after the clearing action.

That distinction matters for apps whose visible badge is connected to notifications that remain delivered by the system. Clearing only the icon badge may not address the underlying current notification state. AppBadgeClear 1.1.1 is specifically described as handling both states when the optional mode is enabled.

  • Native Home Screen quick action.
  • Optional clearing of currently delivered notifications.
  • Protection against immediate restoration of stale badges.
  • A settings panel with optional haptic feedback.

New-notification handling is the central feature

The update is not described as permanently disabling badges. Instead, it uses timestamp-based new-notification detection to distinguish genuinely new notifications from older notification state being reloaded. According to the official depiction, normal badge behavior is automatically restored when a new notification arrives.

The changelog also calls out protection against old notifications reloaded after a respring restoring badges. This is an important limitation to understand: the feature is intended to suppress stale state, not to prevent future notifications from behaving normally.

In practical terms, the release targets a specific annoyance: a user clears an unwanted or stuck badge, the system reloads existing notifications, and the badge comes back even though no new event occurred. Version 1.1.1’s detection and hook changes are intended to address that cycle.

  • New notifications can restore normal badge behavior.
  • Old notifications reloaded after a respring should not restore a cleared badge, according to the changelog.
  • The tweak operates on current system notification and badge state rather than server-side account data.

Compatibility and jailbreak requirements

The official package metadata declares a firmware requirement of iOS 16.0 or later and below iOS 18.0. The package depiction presents the supported range as iOS 16.0 through iOS 17.7.11, and explicitly states that iOS 18 and newer are not currently supported.

The depiction further identifies compatibility with rootless iOS 16 and iOS 17 jailbreaks. Users should therefore check both their exact iOS version and jailbreak environment before considering the package. A device running an unsupported major iOS version should not be treated as compatible merely because the package appears in a repository.

The package lists MobileSubstrate and PreferenceLoader as dependencies. Those requirements are part of the package metadata and may affect whether a package manager can resolve installation on a particular setup. The package architecture is listed as iphoneos-arm64.

  • Supported firmware range in package metadata: iOS 16.0 and newer, below iOS 18.0.
  • The depiction lists iOS 16.0–17.7.11.
  • Rootless iOS 16 and iOS 17 jailbreaks are identified as compatible.
  • iOS 18 and newer are explicitly unsupported.
  • Dependencies include MobileSubstrate and PreferenceLoader.

Hook and stability work in the release

Beyond the user-facing notification option, the 1.1.1 changelog lists improved compatibility and stability for notification and badge hooks. It also adds safe runtime method-signature validation across supported iOS versions.

These changes are technical safeguards rather than new controls exposed directly in the Home Screen menu. They indicate that the release addresses how the tweak interacts with system notification and badge behavior across the supported operating-system versions. The available source does not provide performance measurements or a detailed list of affected methods, so those specifics should not be inferred from the changelog.

The depiction also states that AppBadgeClear preserves correct behavior across resprings and performs no daemon or background network activity. Those are claims made in the package description, not independent test results.

  • Improved compatibility and stability for notification and badge hooks.
  • Safe runtime method-signature validation across supported iOS versions.
  • The depiction claims correct behavior across resprings.
  • The depiction says the tweak has no daemon or background network activity.

What the tweak cannot do

AppBadgeClear works with the notification and badge state presented by iOS. It cannot modify third-party account data or mark messages as read on an app’s server. Clearing a notification from the device is therefore not the same as processing the message inside the service that generated it.

This limitation is especially relevant for messaging, email, social, and work applications. A cleared badge may disappear from the Home Screen while an unread count, message status, or server-side notification remains unchanged. The app may still show its own unread indicator when opened, depending on how it manages account data.

The release description calls its smart clearing behavior a way to remove current system notifications and stale badge state. Readers should interpret that narrowly: it is a local notification-management feature, not an account-management or message-read automation tool.

  • It does not mark messages as read on an app’s server.
  • It does not modify third-party account data.
  • A local badge change should not be assumed to change an app’s server-side unread state.

What to verify before installing

First, verify the device’s exact iOS version against the stated range. The package metadata and depiction both exclude iOS 18 and newer, even though the package requires firmware below 18.0. Next, confirm that the jailbreak is a supported rootless iOS 16 or iOS 17 environment if that is the configuration being used.

Users should also check that the package manager can satisfy MobileSubstrate and PreferenceLoader dependencies. The package is listed as proprietary and commercial, so readers should review the package’s current terms and source-provided information before proceeding. The official package record identifies version 1.1.1 and an installed size of approximately 440 KB, while the depiction lists a download size of 41.42 KB.

Finally, decide whether the optional notification-clearing mode matches the intended workflow. It is designed to clear currently delivered notifications and stale badge state, but it does not alter server-side data. Anyone relying on an app’s notification history should understand that clearing current system notifications may remove those local entries from the notification state the tweak manages.

  • Check the exact iOS version and jailbreak type.
  • Confirm MobileSubstrate and PreferenceLoader availability.
  • Review the package’s proprietary/commercial status and current terms.
  • Understand that clearing local notifications is not the same as marking messages read online.
  • Use the official package source rather than unofficial or mirrored downloads.

Frequently asked questions

What is new in AppBadgeClear 1.1.1?

The update adds optional clearing of currently delivered notifications, prevents apps from immediately restoring stale badges, restores normal badge behavior for genuinely new notifications, adds timestamp-based detection, and includes notification-hook compatibility and runtime method-signature improvements.

Which iOS versions does AppBadgeClear 1.1.1 support?

The package metadata requires firmware from iOS 16.0 up to—but not including—iOS 18.0. The official depiction lists iOS 16.0 through iOS 17.7.11 and describes compatibility with rootless iOS 16 and iOS 17 jailbreaks.

Does AppBadgeClear support iOS 18?

No. The official depiction explicitly says iOS 18 and newer are not currently supported, and the package metadata requires firmware below 18.0.

Will clearing a notification mark a message as read?

No. The package description says AppBadgeClear cannot modify third-party account data or mark messages as read on an app’s server. It manages current system notifications and local stale badge state.

How does the tweak handle new notifications?

The depiction says it uses timestamp-based new-notification detection. When a genuinely new notification arrives, normal badge behavior is automatically restored so the new badge appears as expected.
