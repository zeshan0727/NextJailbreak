IconTweak2 1.1.0 Adds App-Data Backup, Restore and Wipe Controls

IconTweak2 1.1.0, released November 1, expands its Home Screen action menu with per-app backup, restore and wipe tools. The useful part is portability: each backup is one tar archive and may be copied to another device. The risky part is scope: App Groups and keychain groups can be shared between apps, so a wipe can affect more than the icon you selected.

Before using Wipe: make a separate device backup and confirm which apps share App Groups or keychain access. IconTweak2's developer specifically warns that apps from the same developer—Google apps are the given example—may share data, so restoring or wiping one can affect the others.

What changed in IconTweak2 1.1.0

The official changelog adds three related actions: Backup Data, Restore Data and Wipe App Data. Backups are stored under (/var/jb)/var/mobile/Documents/IconTweak/; the /var/jb prefix applies to conventional rootless layouts. Each backup is a single .tar file, and the menu can keep multiple backups per app, identified by date and app version.

  • Backups can include the app's data container, App Group containers and keychain items.
  • Include Caches in Backup is optional and off by default.
  • Wipe also clears app-extension data such as widget, share-extension and notification-extension data.
  • Wipe intentionally keeps iCloud Keychain items so other devices are not affected.
  • The tweak reports when keychain processing fails, including when the device is locked.

This is more than a cosmetic release. A copied tar file can make a controlled device-to-device restore possible, but a tar archive is not the same as an encrypted full-device backup and should not be treated as one.

Compatibility: what is supported and what is not proven

Havoc lists iOS 15.0 through 26.0.1 and identifies rootless support. The developer's compatibility text separately says iOS 15–26 on rootful, rootless and RootHide. The package depends on MobileSubstrate and PreferenceLoader. A separate RootHide package is supplied through the developer's support route rather than the standard package shown to conventional rootless users.

Safe backup workflow

  1. Update IconTweak2 only from its official Havoc listing and confirm the installed version is 1.1.0.
  2. Unlock the device before backing up so keychain processing is not blocked.
  3. Leave cache inclusion off for the first backup unless the app genuinely needs cached content.
  4. Create a backup, then check that a dated tar file appears in the IconTweak backup directory.
  5. Copy that tar file somewhere outside the device before testing Wipe or a cross-device restore.
  6. For apps from the same developer, assume App Group and keychain data may be shared until you verify otherwise.

If you plan to move a backup to another device, install the same app first and compare its app version. IconTweak2 records the app version with each backup, but the official notes do not promise that every older data schema can be restored into every newer app build.

What Wipe does not reset

Wipe clears the app's local and extension data, but the developer says it does not reset the iOS notification-permission decision because that permission is stored by the operating system. For a TrollStore-installed app, the documented recovery is to run Rebuild Icon Cache in TrollStore or reinstall the app. That operation is about notification registration; it is not a substitute for restoring app data.

Wipe also preserves iCloud Keychain items. That design avoids pushing a destructive keychain change to other devices, but it means reinstalling or wiping locally may not produce a completely new sign-in state if the app later reads credentials from iCloud Keychain.

If backup, restore or wipe fails

  • Keychain warning: unlock the device, reopen the menu and retry once. Do not repeatedly wipe while the keychain step is failing.
  • Restore opens but the app crashes: verify the target app version and remove only the failed restored copy if you still retain the original tar archive.
  • Related app lost data: stop using Wipe, restore the affected App Group from a known-good backup, or fall back to a full device/app backup.
  • No preference pane: troubleshoot PreferenceLoader first using the PreferenceLoader settings guide.
  • Package or dependency error: repair the package-manager state before reinstalling; see the Sileo and dpkg recovery guide.
  • SpringBoard instability: disable the tweak in your injection manager or enter the jailbreak's safe mode, then consult the bad-tweak recovery guide.

Other IconTweak2 controls still included

The data tools sit beside the existing per-app actions: rename the app, clear or set badges, open the app bundle/data/App Group in Filza, copy the bundle ID or URL schemes, inspect entitlements, mute notifications and open the app. Filza URL-scheme control is not available in the TrollStore version according to the official listing.

Before installing any tweak with destructive controls, use the tweak compatibility checklist to verify firmware, architecture, dependencies and recovery options for your exact jailbreak.

Frequently asked questions

What does IconTweak2 1.1.0 back up?

The developer says each tar archive can include app data, App Group containers and keychain items. Cache inclusion is optional and disabled by default.

Can wiping one app affect another app?

Yes. Apps can share App Groups and keychain groups. The official notes warn that restoring or wiping one app may affect related apps from the same developer.

Does Wipe delete iCloud Keychain items?

No. Version 1.1.0 intentionally keeps iCloud Keychain items so the operation does not affect your other devices.

Does IconTweak2 support RootHide?

The developer lists RootHide support, but says RootHide uses a separate package supplied through the support route. Conventional rootless support is separately marked on Havoc.

Where are IconTweak2 backups stored?

The official path is (/var/jb)/var/mobile/Documents/IconTweak/, with the rootless /var/jb prefix used when applicable.
