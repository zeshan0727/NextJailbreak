How to Ignore a Tweak Update in Sileo—and Verify the Hold

Sileo can place one installed package on hold so its newer version is separated from normal updates. Because an unresolved Sileo 2.5.1 issue says the choice may not persist for every user, the safe workflow includes a relaunch check before you trust it.

By Zeeshan Barvi · Published October 20, 2026 · Verified against the official Sileo 2.5.1 source and issue tracker

A hold is temporary update management, not a compatibility fix. It does not repair a broken tweak, change rootless/rootful architecture or make an old package support a newer iOS version. Record why you are delaying the update and review the developer’s later changelog.

Quick answer

Open the installed tweak’s package page in Sileo, tap the share/actions button and choose Ignore Future Updates. Then reopen Sileo and return to the same action sheet. If the option now reads Stop Ignoring Updates, the installed package is marked as held. Keep Show Ignored Updates enabled in Sileo settings so the package remains visible in the Updates view.

What Sileo’s hold actually does

The official 2.5.1 source does more than hide a row. When you choose Ignore Future Updates, Sileo changes the installed package’s desired state to hold and calls apt-mark hold with that package identifier. Choosing Stop Ignoring Updates changes the state back to install and calls apt-mark unhold.

Sileo’s Updates view filters held packages out of the ordinary upgrade list and can place them in an ignored-updates section. This applies to that package identifier—not every package from the same developer or repository.

Before ignoring an update

  1. Confirm the exact package. Record its package identifier, installed version, repository and developer. Similar display names are not proof of identity.
  2. Read the new changelog. An update may contain a compatibility or security fix you should not delay.
  3. Write down why you are holding it. Examples include a confirmed regression, dependency conflict or waiting for the developer to verify your jailbreak environment.
  4. Back up configuration if it matters. A hold protects the package version, not its preference files or the rest of the jailbreak.
  5. Check the current state. If the bad version is already installed, ignoring future updates will not roll it back; use the safe Sileo downgrade guide first.

Ignore one tweak update in Sileo

  1. Open Sileo while the jailbreak and package manager are working normally.
  2. Open Packages → Installed and select the exact tweak or library you want to hold.
  3. Verify the installed version and source on the package page.
  4. Tap the package page’s share/actions button.
  5. Choose Ignore Future Updates.
  6. Return to the Updates view and refresh it. The package should no longer appear among normal upgrades.
  7. Open Sileo settings and keep Show Ignored Updates enabled so held packages stay visible for review.

Verify the hold persisted

Do not stop after the first tap. Sileo’s official issue tracker contains an unresolved report from a 2.5.1 user whose newly ignored packages returned to the normal Upgrades section after Sileo was reopened.

  1. Fully close Sileo, then open it again.
  2. Refresh sources and the Updates view.
  3. Find the held package under ignored updates, if available.
  4. Open its package page and tap the share/actions button again.
  5. Confirm the action now says Stop Ignoring Updates.

If it again says Ignore Future Updates, the hold did not persist. Avoid Upgrade All until you are comfortable accepting that package’s update. Record the Sileo version, package identifier, installed and offered versions, jailbreak and environment, then add those facts to the existing official issue rather than installing an unofficial “hold fix.”

Stop ignoring the update later

  1. Open the held package from the ignored-updates section or Packages → Installed.
  2. Tap the share/actions button.
  3. Choose Stop Ignoring Updates.
  4. Refresh sources and the Updates view.
  5. Review the offered version, dependencies, removals and restart action before confirming the upgrade.

Removing the hold does not install the update silently. It allows Sileo to offer the newer version again; you still review and confirm the package-manager transaction.

When a hold is appropriate

  • A developer-confirmed regression affects your exact device or jailbreak environment.
  • A required companion package has not yet received a compatible release.
  • You downgraded to a known-working version and need to stop an immediate re-upgrade.
  • You need time to back up preferences or read a major-version migration note.

When not to rely on it

  • Security fixes: do not indefinitely hold a package with a documented vulnerability unless the developer recommends it.
  • Core components: avoid casually holding APT, dpkg, Sileo, the bootstrap or the hooking framework; partial core updates can create dependency conflicts.
  • Wrong architecture: a hold does not convert rootful, conventional rootless or RootHide packages.
  • Broken repositories: holding a package does not fix missing Release files, signatures or package indexes.
  • Already-upgraded packages: use the supported downgrade workflow; a future-update hold cannot undo an installed version.

Official sources

  • Sileo 2.5.1 package action sheet — defines Ignore Future Updates and Stop Ignoring Updates.
  • Sileo 2.5.1 dpkg wrapper — maps the actions to apt-mark hold and unhold.
  • Sileo 2.5.1 Updates list — separates packages whose desired state is hold.
  • Official persistence issue #350 — unresolved report that newly ignored updates may reappear after relaunch.
Does Ignore Future Updates downgrade a tweak?

No. It prevents ordinary future upgrades for the currently installed package. Use Sileo’s separate version selector to downgrade first if necessary.

Will Upgrade All skip a held package?

Sileo’s source filters held packages out of normal available updates, but verify the hold after relaunch because a persistence issue is open for 2.5.1.

How do I find an ignored package?

Enable Show Ignored Updates in Sileo settings, refresh the Updates view, or locate it under Packages → Installed.

Does ignoring a package block its dependencies too?

No. The hold applies to the selected package identifier. Related libraries and dependencies can have their own versions and transactions.

Sources checked October 20, 2026. Sileo 2.5.1 remains the latest official tagged release at verification time. This guide describes the source-defined behavior and documented persistence report; it does not claim the hold was tested on every jailbreak environment.

Hold checklist

Action: Ignore Future Updates.

Verify: reopen Sileo and look for Stop Ignoring Updates.

Reveal: enable Show Ignored Updates.

Undo: Stop Ignoring Updates, then refresh.

Known limit: persistence issue remains open for some 2.5.1 users.
