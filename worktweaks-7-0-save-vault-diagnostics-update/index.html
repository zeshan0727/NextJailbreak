WorkTweaks 7.0 Adds Save Vault, Diagnostics and Wi-Fi File Sharing

The November 27 release turns WorkTweaks into a broader device and app-data toolbox, but its exact-build gate matters more than the long feature list: iOS 18 and 26 remain partial, iOS 27.3 beta 2 is unsupported, and two headline diagnostic pages do not work on the developer’s iOS 27.0.1 test build.

Published November 27, 2026Official v7.0 release and tagged source checked
Quick answer: update if you need Save Vault, Wi-Fi file transfer, SQLite/plist editing or the new data-inspection tools and your exact build appears in the official support table. Do not update expecting the removed Status Bar, SpringBoard or Install IPA on Container tools, and do not install on iOS 27.3 beta 2 or later.

What is genuinely useful in version 7.0

Save Vault and app-data inspection

Save Vault stages an app’s user data into a ZIP backup so it can be restored after a sideloaded app is reinstalled. A largest-file scanner helps identify what occupies a container, while App Data gains in-place SQLite database and property-list editors. The developer’s source says edits create a pristine backup before the first write, but that does not make every restore risk-free: close the target app first and keep an independent copy of important data.

Wi-Fi sharing and export tools

The new Wi-Fi File Sharing page serves only WorkTweaks’ Documents directory, including Save Vault backups, staged vaults and uploads. It is PIN-protected and stops when the page closes or the app goes into the background. Version 7.0 also adds Voice Memos export, Apple Intelligence cache inspection and an installed-profile viewer.

Diagnostics with an important exception

Battery & Thermal reads a cloned copy of the system powerlog for battery health, cycle count, cell temperature and thermal history. Jetsam & Crash lists termination and crash reports. However, the official v7.0 notes say both pages are blocked on iOS 27.0.1 because the required paths are absent. That is the developer’s recorded test build, so users should not treat the feature names as proof they work on every supported iOS 27 version.

A safer manual Siri path, not a complete Siri fix

The MobileGestalt plist viewer can jump to the relevant Siri line and replace the whole line, with a pristine backup and Restore option. The release notes are explicit: this can make the Apple Intelligence waitlist appear, but it does not solve Siri remaining stuck on “Adding support” after models are downloaded.

What version 7.0 removed

  • Status Bar and SpringBoard tweaks: removed from the release rather than silently retained.
  • Install IPA on Container: removed after the developer documented failed device behavior in the source history.
  • Disable Thermal: not shipped because the developer says no MobileGestalt key exists for it.
  • Internal Features on iOS 27.0.1: blocked because CacheData returns zero and no file-based method is available.

Check the exact firmware build, not just “iOS 27”

WorkTweaks stops at an unsupported screen when the current build is not in its table. The full list includes iOS 27.0 betas 1–8, the RC and public 27.0; 27.0.1; the listed iOS 27.1 iPhone Duo build; 27.2 betas 1–4, RC, public 27.2 and 27.2.1; and 27.3 beta 1. It excludes 27.3 beta 2 and newer because worse_query is patched there.

On listed iOS 18.0 and iOS 26 releases, support is only App Data plus Airlift. MobileGestalt tweaks are not promised on those builds. This is also separate from jailbreak availability: WorkTweaks does not require Dopamine, RootHide or another jailbreak environment. For the broader escape boundary, see the current Erosion and worse_query status.

Installation choices and common failures

  1. Download only from the official v7.0 release. WorkTweaks is distributed as an unsigned IPA.
  2. Use iLoader or SideInstaller on a computer, Feather on-device, or import the unsigned IPA into LiveContainer. The developer’s current README lists all four paths.
  3. For a normally signed installation, the provisioning profile must carry WorkTweaks’ App Group under your team. The developer says direct signing with KSign, shared/free ESign certificates or Sideloadly does not supply the required App Group. ESign can still install an IPA that was already provisioned correctly.
  4. If choosing a container workflow, review the LiveContainer versus Feather comparison; the two methods have different signing, App ID and isolation models.
  5. With a free Apple ID, expect the normal short signing lifetime and refresh requirement for sideloaded apps.

Back up before applying MobileGestalt or container changes

  1. Open WorkTweaks and confirm the exact version and iOS build before changing anything.
  2. Create its original MobileGestalt backup and export any Save Vault ZIP to Files or another computer. A backup stored only inside the app can disappear when the app is removed.
  3. Apply one change at a time, then respring or restart only when the tool instructs you to.
  4. Before editing a database or plist, close the owning app. If the app is actively writing, a technically valid edit can still corrupt live state.
  5. If a MobileGestalt change causes layout or feature problems, restore the pristine backup rather than guessing replacement values. The MobileGestalt reset guide explains why reverting with the tool that created the change should come first.
