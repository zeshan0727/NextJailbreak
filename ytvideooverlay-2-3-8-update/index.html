YTVideoOverlay 2.3.8 fixes missing bottom buttons in YouTube’s video overlay

PoomSmart’s YTVideoOverlay 2.3.8 is a focused maintenance release for the helper tweak that adds buttons to iOS YouTube’s video player overlay. The official changelog says the update fixes bottom buttons not showing for some users. Associated source changes adjust how fullscreen controls are measured and move bottom-button views between hosting views before an early-return condition. The package metadata lists iOS 11.0 or later, the iphoneos-arm architecture, and a MobileSubstrate dependency of version 0.9.5000 or later.

Key points

  • YTVideoOverlay 2.3.8 replaces version 2.3.7 in the package control file.
  • The official changelog says the release fixes bottom buttons not showing for some users.
  • The related code measures the fullscreen button in the appropriate hosting view and moves bottom buttons before an early-return condition.
  • The package declares firmware version 11.0 or later, the iphoneos-arm architecture, and MobileSubstrate version 0.9.5000 or later.
  • The supplied release material does not identify a specific current YouTube version as compatible with 2.3.8.

What is new in YTVideoOverlay 2.3.8

YTVideoOverlay is described by its maintainer, PoomSmart, as a helper tweak for adding buttons to iOS YouTube’s video player overlay. It is not presented as a standalone YouTube client. Instead, it provides an overlay-focused layer that can support additional controls and related tweak integrations.

Version 2.3.8 is a targeted maintenance update. The package control file changes the version from 2.3.7 to 2.3.8, while retaining the same package name, identifier, architecture, description, and maintainer information. The official depiction gives the release a concise changelog entry: “Fixed bottom buttons not showing for some users,” with the contribution attributed to JeffreyCA.

There is no source-backed indication that this version introduces a new button type, a new settings category, or a new user-facing overlay feature. The available material instead points to a correction in the way existing bottom buttons are positioned and displayed. That makes the update most relevant to users who rely on bottom overlay buttons and have encountered cases where those controls were absent.

  • Package name: YTVideoOverlay
  • Version: 2.3.8.
  • Package identifier: com.ps.ytvideooverlay.
  • Maintainer and author listed in the package metadata: PoomSmart.
  • Package description: a helper tweak to add buttons on YouTube video overlay.

How the source code addresses missing buttons

The associated code change modifies the routine that sorts and positions overlay buttons. One part of the change obtains the peekable view earlier and uses it when selecting the coordinate space for fullscreen measurements. When the layout is in fullscreen mode, the code chooses the peekable view as the host for measuring the enter/exit fullscreen control; otherwise, it uses the main view.

This matters because a button’s frame is meaningful only within the view coordinate system used to host it. The change therefore measures the fullscreen button and its surrounding group in the relevant host rather than always converting those frames into the main overlay view. The commit message describes this adjustment as measuring the simplified fullscreen button in the hosting view.

The same source change moves the handling of bottom buttons before the routine’s visibility-related early-return checks. The accompanying code comment explains that buttons are moved between hosts before an early return so that none remain in the hidden peekable view. In practical terms, the button transfer is no longer skipped merely because a later frame check determines that the routine should stop.

After that host transition, the code performs the existing frame validation and positioning work. It calculates spacing using the fullscreen button’s width and image width, adjusts the horizontal position, applies the corner radius and frosted-glass treatment, and assigns the resulting frame to the applicable buttons. The supplied source supports describing this as a visibility and layout correction for existing controls, not as the addition of a new control.

  • Fullscreen measurements now use the relevant hosting view.
  • Bottom buttons are moved between hosting views before early-return checks.
  • The change addresses button placement and visibility in the overlay layout routine.
  • The source does not describe the update as adding a new button or a new user-facing feature.

Compatibility and package requirements

The official depiction lists YTVideoOverlay as compatible with iOS 11.0 and later. The package control file expresses that baseline with a firmware dependency of at least 11.0. The same metadata lists MobileSubstrate version 0.9.5000 or later as a dependency.

The package also specifies the iphoneos-arm architecture. These are declared package requirements, so they should be read as baseline metadata rather than as a guarantee that the tweak will work in every jailbreak environment, device configuration, YouTube build, or combination of installed modifications.

The supplied 2.3.8 material does not provide a specific current YouTube version range. The historical changelog does mention fixes connected with particular YouTube releases, including problems involving fullscreen positioning, crashes, text buttons, spacing, and button visibility. Those historical entries show that YouTube changes have affected overlay behavior, but they do not establish a current compatibility list for version 2.3.8.

Users should therefore distinguish between the package’s declared iOS requirement and verified compatibility with a particular YouTube installation. The former is stated directly in the package metadata; the latter is not supplied for this release.

  • Declared iOS baseline: iOS 11.0 or later.
  • Declared dependency: MobileSubstrate 0.9.5000 or later.
  • Declared architecture: iphoneos-arm.
  • No specific current YouTube version is identified for 2.3.8 in the supplied release material.

What users should check before updating

Existing users can begin by checking whether their installed package is older than 2.3.8 and whether the package identity matches the official metadata: YTVideoOverlay, identifier com.ps.ytvideooverlay, and maintainer PoomSmart. Comparing these details helps distinguish the intended package from similarly named modifications.

The declared platform requirements are also worth reviewing. The device should meet the iOS 11.0-or-later baseline, and the environment should provide the listed MobileSubstrate dependency. These checks do not prove that every overlay button will work, but they can identify a basic mismatch before troubleshooting the YouTube interface.

Because the release specifically concerns bottom buttons, users experiencing that problem should note whether the issue affects all videos, only fullscreen playback, or only certain button configurations. The source describes changes to hosting views, fullscreen measurement, and the order of layout operations, so the exact display state may be useful when evaluating the result.

It is also sensible to record the installed YouTube version and review other tweaks that modify the video player overlay. The supplied material confirms the 2.3.8 implementation changes, but it does not document interactions with other overlay customizations or promise universal compatibility. If buttons remain absent after updating, the YouTube build, button configuration, and other injected changes are relevant factors to investigate.

  • Confirm that the installed package is version 2.3.8 or an earlier release being updated.
  • Check the package identifier and maintainer details.
  • Verify the declared iOS and MobileSubstrate requirements.
  • Record the installed YouTube version before making changes.
  • Review other tweaks that modify YouTube’s player overlay.
  • Do not treat the release notes as a guarantee for every device or YouTube build.

How 2.3.8 fits the project’s development history

YTVideoOverlay’s earlier changelog entries show a continuing focus on overlay controls and their presentation. Previous releases addressed text overlay buttons, frosted-glass border radius, frosted-glass view management, button ordering, fullscreen positioning, button spacing, crashes, and visibility on different YouTube versions or device configurations.

The project has also included feature-oriented changes. Version 2.1.0 added the ability to reorder buttons and removed unnecessary YouQuality-specific code. Version 2.2.0 added support for extra boolean settings from the tweak side. Version 2.3.0 added an option for a frosted-glass effect behind bottom buttons on supported recent YouTube versions.

Against that background, 2.3.8 is narrower. Its documented purpose is to address bottom buttons that were not showing for some users, while the corresponding code refines view hosting and fullscreen measurement. The release does not claim a new customization system or a broader redesign of the YouTube player.

The repository README also points developers to Template.x.example for a code example and control.example for a Debian package control-file example. That documentation reflects the project’s role as a helper layer for developers building or packaging overlay-button integrations.

  • Earlier versions added button reordering, text-button support, extra settings support, and frosted-glass options.
  • The project’s changelog includes fixes for fullscreen positioning, crashes, spacing, text rendering, and overlay visibility.
  • Version 2.3.8 is focused on missing bottom buttons and related layout handling.
  • The repository includes examples for integrating the helper and preparing package metadata.
