Apollo Reborn adds silent Gallery View playback and strengthens crash handling

Recent Apollo Reborn project history describes three focused improvements. Gallery View can now animate GIFs and play video tiles silently while they remain visible, with separate controls for each media type. GIF tiles generally use Reddit’s MP4 rendition for efficient grid playback, while the original GIF remains available in the full viewer and through Save and Share. The same development work also addresses a non-Liquid-Glass search-cancellation crash caused by repeated scroll-offset corrections and adds a guard for unexpected non-dictionary Reddit listing responses. These changes complement Apollo Reborn’s broader purpose: keeping the Apollo Reddit app usable with custom API credentials while adding enhancements and fixes.

Key points

  • Gallery View now has separate controls for video playback and GIF animation, with both enabled by default in the described implementation.
  • Media playback is silent, limited to visible tiles, and stopped by scrolling, navigation, app backgrounding, memory warnings, or Low Power Mode.
  • Reddit’s MP4 rendition is used for most GIF grid previews, while the original GIF remains available to the viewer and Save/Share actions.
  • A non-Liquid-Glass search-cancellation issue is addressed by respecting UIKit’s minimum content offset and limiting repeated correction attempts.
  • Unexpected non-dictionary responses from listing endpoints are converted into errors instead of being passed to code that assumes dictionary data.

Apollo Reborn’s latest documented work

Apollo Reborn is an iOS tweak for the Apollo Reddit app. Its project description says it enables continued use with personal Reddit and Imgur API keys after Apollo’s shutdown in June 2023, while also unlocking selected Ultra features and providing additional enhancements and fixes.

The supplied repository history does not identify a package release number for these changes. Instead, it records individual commits that improve Gallery View media behavior, search teardown handling, and Reddit response validation. Reading the changes as implementation updates rather than as a numbered release avoids assuming that every installation has received the same build or commit set.

Gallery View can play media silently

The most visible change affects galleries containing videos and animated images. Gallery View now exposes two controls under Apollo Reborn’s media browsing settings: “Play Videos in Gallery View” and “Play GIFs in Gallery View.” They are separate switches, and the supplied implementation enables both by default. A change to either setting can affect an already open gallery immediately.

The feature is intended for previews inside the scrolling grid, not for replacing Apollo’s full-screen media viewer. Video tiles use a muted, looping AVPlayer presentation. For animated GIFs, Apollo first looks for Reddit’s MP4 rendition. That rendition can be decoded as video rather than loading and animating the original GIF frame by frame, making it suitable for a grid of small tiles.

Playback begins after the grid settles and is restricted to media that is actually on screen. A tile stops playing as soon as it scrolls out of view, the viewer opens, the gallery is dismissed, the app moves into the background, or the device reports a memory warning. Low Power Mode also pauses the behavior. These conditions make the feature closer to an animated preview system than unrestricted autoplay across an entire feed.

  • Video and GIF playback are muted.
  • The two media types can be enabled or disabled independently.
  • Only visible tiles are eligible for playback.
  • Playback stops during the lifecycle and memory conditions described by the project.
  • A failed stream releases its playback slot instead of remaining marked as active.

GIFs retain their original media path

Using an MP4 rendition in the grid does not convert or replace the original GIF throughout Apollo. The implementation stores the rendition separately as a grid-only resource. When a user opens the viewer or uses Save and Share, those paths continue to use the actual GIF. This preserves the expected source format for actions that involve viewing or exporting the media rather than merely scanning a gallery.

The project limits active gallery playback to 12 tiles. A real GIF without an available MP4 rendition follows Apollo’s animated-image path and is subject to a separate limit of three simultaneously animated GIFs. The reason given in the implementation is that full GIF frame decoding places different demands on the CPU, while Reddit’s MP4 rendition can generally use the hardware video path. The source notes that Reddit provides such a rendition for nearly every GIF it hosts, although the fallback remains available when one is absent.

For video streams, the gallery uses a lower-cost preview path. The implementation caps HLS playback at 1.5 Mbps and chooses media near the tile’s display size. A stream that fails to load, including one that reaches a failed AVPlayer item state, no longer occupies a playback slot for the rest of the visit.

Gallery layout behavior also receives a correction

The Gallery View work includes a rotation-layout fix. The grid now measures the collection view’s actual width when calculating its rotation anchor instead of relying on the transition’s proposed size. The commit specifically describes a case involving a gallery presented modally within a subreddit: a landscape layout could otherwise receive an incorrect width and produce oversized columns. Measuring the real container is intended to keep the grid aligned with the space it actually occupies.

The supplied source does not present this as a general performance benchmark or promise identical results on every device. It documents a targeted correction to gallery sizing alongside the new media controls.

Search cancellation is hardened on non-Liquid-Glass builds

A separate commit addresses a crash involving in-feed search on non-Liquid-Glass builds. The described sequence includes Subreddit Headers being enabled, a user opening the in-feed search control, entering a query, and tapping Cancel. During dismissal, Apollo’s search-position logic could read a toolbar position that was still laid out for the surfaced search state.

That stale measurement caused the code to request an increasingly invalid scroll offset. UIKit would clamp the value back to its own minimum, then observe another offset change during visible-cell updates. The process could repeat through hundreds of nested table-view update frames before producing a stack-related SIGSEGV. In user terms, the issue could appear as a crash shortly after cancelling a search in the affected configuration.

The correction floors every relevant “return to rest” target at UIKit’s own minimum content offset. If the calculated resting value is below that floor, the code uses the floor rather than continuing to write an invalid position. A bounded clamp-fight breaker provides an additional safeguard: when the same incoming offset is repeatedly overridden during one main-thread callout, the correction stands down instead of feeding the loop. The commit describes the Liquid Glass path as unchanged because its resting position already remains above the relevant floor.

  • The documented trigger is specific to non-Liquid-Glass layouts.
  • The sequence involves in-feed search, a query, Subreddit Headers, and Cancel.
  • The fix preserves the temporary feed positioning needed while the search toolbar is restored.
  • The safeguard limits repeated offset corrections during a single callout.

Unexpected listing responses now take an error path

The third documented change concerns RedditKit response handling. Some listing completions assumed that a parsed Reddit response was a dictionary and attempted keyed access without checking its class first. Because the serializer permits JSON fragments, an unexpected response whose root is an array, string, number, or bare null could reach that code and trigger an exception.

Apollo Reborn now adds a response-shape guard for Reddit paths whose expected root is a listing dictionary. When a non-dictionary object arrives for one of those paths, the guard returns an error instead of allowing unsafe dictionary access. The normal failure path can then report the request problem and offer a retry rather than crashing the application.

The guard is deliberately scoped. The source identifies comments, duplicates, certain preference data, and API endpoints as families that can legitimately use arrays or other response shapes. Those paths are left untouched. The change therefore does not claim to repair every failed Reddit request; it changes one class of unexpected listing response from a crash risk into ordinary error handling.

What users should understand before updating

The documented changes are most relevant to people who browse media-heavy communities, use in-feed search on non-Liquid-Glass builds, or have encountered failures while Apollo retrieves listing data. Gallery autoplay can be disabled separately for videos and GIFs, so users who prefer static grids do not have to turn off both media types together.

Installation details still matter. Apollo Reborn’s README describes Standard or Liquid Glass builds with app extensions and widgets, as well as No Extensions builds that use fewer App IDs. The suitable choice depends on the installer, Apple account, and whether extensions are needed. The project also relies on custom API configuration, and the README warns that Reddit and Imgur no longer allow new API key creation in the ordinary way.

The supplied commits describe specific fixes and features, not a universal guarantee that every package or installation includes them. Users should check the build they are installing, preserve their settings, and verify that their API credentials and signing arrangement remain compatible.

Frequently asked questions

Is a numbered Apollo Reborn release established by the supplied material?

No. The supplied repository metadata and commit records document project activity and individual changes, but they do not establish a package version number for this article.

Does Gallery View play GIFs and videos with sound?

No. The documented Gallery View playback is silent. Video tiles are muted, and GIFs generally use Reddit’s silent MP4 rendition when available.

Does the MP4 rendition replace the original GIF?

No. The MP4 is used as a grid-only playback resource. The full viewer and Save/Share paths continue to use the original GIF.

Can GIF and video playback be controlled separately?

Yes. The implementation adds separate switches for Play Videos in Gallery View and Play GIFs in Gallery View. Both are enabled by default in the described code.

What search problem does the update address?

On an affected non-Liquid-Glass layout, dismissing in-feed search could repeatedly apply an invalid scroll correction while UIKit applied its own minimum offset. The fix respects that floor and stops repeated corrections after a bounded number of attempts.

Before installing: confirm the current package version, compatibility and dependencies at the original developer/repository source for your exact device and jailbreak.
