LiveContainer 3.8.0 vs September 18 Nightly: Features and Requirements

LiveContainer 3.8.0, released on July 17, 2026, is the feature-focused stable release. It adds storage management, share-sheet integration, per-app multitasking preferences, improved window handling, StosDebug support, tweak controls, signing improvements, and fixes for several iOS and multitasking scenarios. The September 18, 2026 nightly is not a second feature release: its release entry identifies it as an automatically generated pre-release containing the litehook update “add arm64e_x1 dsc suffix.” Users should therefore distinguish the predictable feature set of 3.8.0 from the narrower but less mature purpose of the nightly build.

\n \n
\n

Key points

  • LiveContainer 3.8.0 was released July 17, 2026; the compared nightly was released September 18, 2026.
  • The nightly is marked as a pre-release and records one change: an updated litehook with an arm64e_x1 DSC suffix.
  • Stable 3.8.0 adds storage tools, share-sheet handling, per-app multitasking settings, StosDebug support, and tweak toggles.
  • The standalone build requires SideStore 0.6.2+ or AltStore 2.2.1+.
  • The built-in-SideStore package, LiveContainer+SideStore.ipa, is installed through Impactor or iloader.
  • LiveContainer is an app launcher and sandbox, not a full jailbreak, emulator, or hypervisor; app and JIT compatibility should be checked individually.
\n

Two releases, two different purposes

The first point of comparison is chronology. LiveContainer 3.8.0 was released on July 17, 2026 and is presented as the stable release. The September 18, 2026 entry is labeled “Nightly Release @ 20260918” and “Pre-release.” It was created automatically by a GitHub Actions workflow, so it should not be read as a replacement stable release merely because it is newer by date.

The nightly entry identifies the associated commit as 4dbe0f9 and gives the message: “Update litehook: add arm64e_x1 dsc suffix.” That is the release-specific change documented for the snapshot. Nothing in that entry says that the July stable feature list was re-released or expanded in September. The practical distinction is straightforward: 3.8.0 is the documented feature baseline, while the nightly is an experimental snapshot aimed at a particular litehook change.

  • Stable 3.8.0: released July 17, 2026, with a broad feature and bug-fix changelog.
  • September 18 nightly: released September 18, 2026, marked pre-release, with the litehook arm64e_x1 DSC-suffix update.
  • The release dates are not build dates or the publication date of this article; readers should use the release label and commit information when comparing snapshots.

What LiveContainer 3.8.0 adds for everyday management

The stable release’s most visible user-facing addition is Storage Management. Its new view breaks down app bundles, containers, temporary files, app-group data, tweaks, and other files. The release notes specifically state that the size of hidden apps remains in the “other” category until those apps are unlocked. This gives users a more useful explanation of where LiveContainer data is being used without suggesting that every category can be removed safely or automatically.

Per-app storage details include the app bundle size, container sizes, and the last-used date. The release also adds actions for cleaning temporary files and caches, including guest-app caches and LiveContainer’s own caches. Those controls matter for users maintaining several isolated app containers, but the changelog does not promise that clearing caches will fix every launch problem or recover a particular amount of storage.

Sharing is also more integrated. LiveContainer 3.8.0 adds a share extension: when a URL or file is sent from the iOS share sheet, LiveContainer asks which app should open it. This replaces the older share-to-LiveContainer shortcut approach. When the shared item is an IPA file, LiveContainer asks whether to install it in LiveContainer or in the built-in SideStore, if that component is installed.

  • Storage Management covers bundles, containers, temporary files, app-group data, tweaks, and other files.
  • Per-app views show bundle and container sizes plus the last-used date.
  • Cleanup actions cover temporary files and caches, including guest-app and LiveContainer caches.
  • The share extension can route URLs and files to a selected app and can offer an installation destination for shared IPA files.

Multitasking, multiple instances, and JIT-related controls

For users running more than one LiveContainer instance, 3.8.0 adds configurable launch priority. Shared-app shortcuts can use available instances in the order selected by the user. The release also improves multitask dock behavior: the dock can be made smaller, hidden more cleanly, and displayed with improved padding. Additional window animations and native-window scene handling are included in the stable changelog.

Multitasking preferences are now configurable per app. An app can follow the global setting, always launch in multitask mode, or avoid multitask mode. URL schemes and open-url payloads can be passed to already-running multitask apps and native windows. The release notes also describe fixes for multitasking keyboard focus on iOS 17.4 and later, including cases involving the keyboard, Passwords, and video playback. These are documented fixes, not a guarantee that every app will behave identically.

The stable release adds StosDebug support as a JIT enabler and includes fixes for some multitask and JIT app launches. However, the project’s own description presents JIT as optional, and the release material does not promise JIT for every device, operating-system version, or app. LiveContainer should not be described as a full jailbreak. Its project description calls it an app launcher that runs iOS apps inside a sandbox, and the documentation separately describes it as neither an emulator nor a hypervisor.

  • Per-app multitasking can follow the global preference, force multitask mode, or avoid it.
  • Instance launch priority helps shared-app shortcuts select among multiple LiveContainer instances.
  • StosDebug is included as a JIT enabler in 3.8.0, but JIT remains optional and compatibility is app- and environment-dependent.
  • The project describes LiveContainer as a sandboxed app launcher, not a full jailbreak.

Tweak controls, signing, and compatibility notes

The stable release adds the ability to disable tweaks from LiveContainer’s Tweaks page. It also adds manual container-IDFV configuration and states that IDFV spoofing works even when TweakLoader is not loaded. Signing logic for tweaks and app installation was reworked, with multithreaded signing support.

Several fixes target reliability and operating-system-specific behavior. The release notes mention app-launch compatibility fixes on iOS 26.5 beta, support for the iOS 27 developer beta, fixes for cold-start livecontainer://open-url handling, improved behavior when a busy instance is selected, and a correction for background downloads in multitask apps. The notes say that choosing “Keep App Extensions (Register App ID for Each Extension)” is required for those background downloads.

These statements describe the conditions and fixes recorded by the project; they do not establish universal compatibility. Users should check the app’s needs, their iOS version, whether multitasking or JIT is involved, and whether extensions or tweaks are required. The project also warns about closed-source third-party builds: because apps run within LiveContainer, such builds may have access to app data, including keychain items and login credentials. Official-source provenance is therefore an important part of the installation decision.

  • Tweaks can be disabled from the in-app Tweaks page.
  • Manual container-IDFV settings and IDFV spoofing without TweakLoader are listed stable-release changes.
  • Background downloads in multitask apps require the specified app-extension signing choice.
  • The project warns that closed-source third-party builds can access data held by apps inside LiveContainer.

Installation requirements and choosing a release channel

The standalone LiveContainer version has an exact requirement: SideStore 0.6.2+ or AltStore 2.2.1+. That requirement should be treated as a prerequisite, not as an optional suggestion. The project also provides a version with built-in SideStore. For that package, named LiveContainer+SideStore.ipa, the 3.8.0 release instructs users to use Impactor or iloader. These are separate installation paths, and the standalone requirement should not be silently applied to the bundled package or vice versa.

The release pages supplied for this comparison do not document a separate nightly-specific installation requirement. That does not make the nightly equivalent to stable: it remains marked pre-release, and its only listed change is the litehook update. Before using it, readers should confirm the asset, signing method, device architecture, iOS version, and any current installation guidance from the project’s original release and documentation pages.

For most users, 3.8.0 offers the clearest choice when the priority is the documented feature set and a stable release channel. A nightly may be relevant when the arm64e_x1 DSC-suffix change addresses a user’s particular environment, but the source material does not claim broader performance, reliability, or compatibility. The sensible comparison is therefore not “old versus faster,” but documented stable behavior versus a targeted pre-release snapshot.

  • Standalone: SideStore 0.6.2+ or AltStore 2.2.1+ is required.
  • Bundled package: LiveContainer+SideStore.ipa is installed through Impactor or iloader.
  • The September nightly has no separately documented requirement in the supplied release entry.
  • Readers should verify the official asset, signing path, device architecture, iOS version, and app-specific needs before installing.

Frequently asked questions

Is the September 18 nightly a new feature release after LiveContainer 3.8.0?

No. It is a pre-release nightly whose entry identifies one change: updating litehook to add an arm64e_x1 DSC suffix. The storage, sharing, multitasking, tweak, and StosDebug features belong to the July 17 stable 3.8.0 changelog.

What does LiveContainer 3.8.0 require?

The standalone version requires SideStore 0.6.2+ or AltStore 2.2.1+. The release also documents a bundled LiveContainer+SideStore.ipa installation path using Impactor or iloader.

Does LiveContainer provide a full jailbreak?

No. The project describes LiveContainer as an app launcher that runs iOS apps inside a sandbox and says it is not an emulator or hypervisor. The release material does not describe it as a full jailbreak.

Does StosDebug guarantee JIT for every app?

No. StosDebug is listed as a JIT enabler in 3.8.0, while the project describes JIT as optional. The release does not promise universal JIT availability or compatibility.

What should I check before choosing the nightly?

Check that the targeted litehook change is relevant to your device or environment, then confirm the official asset, signing route, iOS version, architecture, and app requirements. The nightly is a pre-release, so its narrower change list should not be treated as evidence of broader compatibility.
