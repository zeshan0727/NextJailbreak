Rootless vs Rootful vs RootHide Jailbreaks: How to Identify Your Setup

Rootful, conventional rootless and RootHide packages are not interchangeable labels. Identify the jailbreak environment first, then check the package build, iOS range and dependencies before installing a tweak.

By Zeeshan Barvi · Updated October 5, 2026 · Verified against Theos, RootHide and Dopamine documentation

The short answer

Rootful is the traditional jailbreak layout and normally uses packages marked iphoneos-arm. Rootless keeps jailbreak files under a separate prefix—Theos documents /var/jb—and normally uses iphoneos-arm64 packages. RootHide is also rootless in principle, but it uses a randomized jailbreak-root directory and RootHide-specific loader paths and packages.

Those labels describe the package and filesystem environment. They do not prove that a jailbreak exists for your iPhone, chip or iOS version. Determine device support from the jailbreak project first; only then evaluate tweak compatibility.

The architecture field is useful, but it is only one filter. A package can have the right architecture and still fail because its supported iOS range, dependencies, injection target or hard-coded paths do not match your setup.

How to identify your jailbreak environment

  1. Start with the jailbreak or bootstrap name. Read its official documentation. Dopamine describes itself as a rootless jailbreak. RootHide Bootstrap identifies a RootHide environment and is installed through TrollStore.
  2. Check the package description. Reputable repositories normally state rootful, rootless or RootHide support. Prefer an explicit statement over an icon, screenshot or community guess.
  3. Inspect package details in Sileo or Zebra. A package architecture of iphoneos-arm64 indicates a rootless build; Theos documents iphoneos-arm for rootful iOS packages.
  4. Use paths only as a supporting clue. A conventional rootless jailbreak commonly exposes /var/jb. RootHide deliberately uses a randomized jailbreak root, so a tutorial that assumes a fixed /var/jb path may be wrong for it.
  5. Do not probe by deleting or moving files. If the environment is still unclear, check the project documentation or ask the tweak developer with your exact jailbreak, device and iOS version.

Why ordinary rootless and RootHide are different

Theos’s conventional rootless scheme relocates packages under /var/jb and adjusts linking so binaries can find rootless libraries. RootHide avoids a fixed public jailbreak path: its developer documentation says each jailbreak uses a randomized jailbreak-root directory, with generated .jbroot links and a jbroot API for code that must locate jailbreak files.

That is why “supports rootless” is not always enough. A tweak that assumes /var/jb, ships incompatible install scripts or accesses jailbreak files without RootHide’s path handling may need a separate RootHide build. RootHide’s official Theos instructions use THEOS_PACKAGE_SCHEME=roothide; conventional rootless projects use THEOS_PACKAGE_SCHEME=rootless.

RootHide Bootstrap injection is opt-in

RootHide Bootstrap’s official README says it does not inject tweaks into third-party apps by default. The user enables injection for selected apps in Bootstrap’s App List. If a RootHide tweak installs but does nothing inside an app, first confirm that the package supports RootHide and that injection is enabled for the intended target. Do not assume the missing behavior proves the package is broken.

The project currently documents Bootstrap for iOS 15.0 through 17.0 on A8 through A17 Pro and M1/M2 devices, installed with TrollStore. That is Bootstrap’s own stated range, not a promise that every tweak supports every device or firmware in it.

Choose the correct package build

  • Match the environment: rootful, rootless or RootHide must be stated by the developer or package repository.
  • Match the iOS range: a rootless build may still target only certain iOS versions.
  • Check dependencies: every required library must also exist for the same environment.
  • Check app versions: app-specific tweaks may depend on a particular version of the target app.
  • Avoid blind conversion: changing a package label or moving files does not repair hard-coded paths, install scripts, dynamic-library references or incompatible code.

If a repository offers multiple files, install through a current package manager and let it choose the declared compatible build. Do not install a rootful .deb on rootless merely because its package name is familiar, and do not assume a generic rootless .deb works on RootHide.

Package compatibility is not jailbreak availability

A listing that says “iOS 16–18” describes the package developer’s intended software range. It does not mean every device on those versions can be jailbroken. Jailbreak availability also depends on the device chip, exact firmware and the official project’s support matrix.

For example, Dopamine’s official README calls Dopamine rootless and publishes separate device-and-firmware ranges. A tweak can support Dopamine’s rootless environment while your particular device or iOS build remains outside Dopamine’s supported range. Check both layers independently.

Five checks before installing any tweak

  1. Record the exact iPhone or iPad model, iOS version and jailbreak or bootstrap name.
  2. Confirm the environment: rootful, conventional rootless or RootHide.
  3. Read the tweak developer’s stated iOS, environment and target-app requirements.
  4. Verify that dependencies come from trusted repositories and match the same environment.
  5. Install one change at a time and keep a removal or recovery path.

For a broader pre-install process, use the jailbreak tweak compatibility checklist. To compare modern package managers, see Sileo vs Zebra. If you use Dopamine, the current Dopamine compatibility guide separates jailbreak availability from tweak support.
