SideInstaller 1.0.0 brings PC-free SideStore and LiveContainer setup to iPhone

SideInstaller has reached version 1.0.0, according to the official release metadata. The project is designed to install SideStore and LiveContainer directly on an iPhone without a PC. Its README describes an on-device workflow covering pairing, provisioning, and installation, while requiring an iPhone or iPad running iOS 27, Wi-Fi during first-time setup, and Apple account credentials. The project also strongly warns users to obtain builds only from its official website or repository because visually identical forks or redistributed copies could be modified to steal Apple account information.

Key points

  • The official release metadata identifies SideInstaller 1.0.0 as an app for installing SideStore and LiveContainer on an iPhone without a PC.
  • The README lists iOS 27, first-time Wi-Fi access, and Apple account credentials as requirements.
  • The documented workflow uses LocalDevVPN or an alternative, an official install page, Apple account sign-in, and an in-app installation choice.
  • The project says credentials are used locally for signing and installation and are not transmitted, logged, or collected by the official build.
  • The maintainer explicitly warns against third-party sites, mirrors, app repositories, Telegram or Discord distributions, and a similarly named fake website.
  • Recent repository changes include an iOS 27/Xcode upgrade, a timer-capture fix, and comment simplification; the supplied release metadata does not provide a detailed 1.0.0 change log.

What SideInstaller 1.0.0 is

The official release page identifies SideInstaller 1.0.0 and describes it as an app that installs SideStore and LiveContainer directly on an iPhone without requiring a PC. That is the central purpose of the project: moving the setup process that ordinarily involves desktop tools onto the iOS device itself.

The project’s README says SideInstaller handles pairing, provisioning, and installation on-device. It presents the app as a simplified front end rather than a command-line workflow, with users selecting whether to install SideStore alone or SideStore together with LiveContainer.

The source describes the project as free and open source. Its stated benefit is accessibility for users who want to sideload but do not have access to a Mac or PC. The repository layout identifies a SwiftUI iOS app, a Rust core compiled into an XCFramework, scripts for building and signing, and workflows for publishing the installation page.

What the supplied release information confirms—and does not

The release metadata confirms the 1.0.0 version and the official description, but the supplied release-page material does not include a detailed list of changes for version 1.0.0. It would therefore be inaccurate to attribute a specific new feature or bug fix to the release without additional release notes.

There is, however, relevant recent repository activity. A commit titled “xcode os 27 upgrade” indicates a project upgrade associated with iOS 27 development. Another recent change adjusts a repeating location timer to capture its manager weakly, addressing a potential ownership problem described in the code comment. A separate commit rewrites comments across several Swift files to simplify documentation. These are repository changes, not a complete 1.0.0 changelog.

The code areas touched by the recent commits include account storage, account setup, certificate management, provisioning-profile display, installed-app matching, and location handling. The patches show documentation and implementation adjustments in those areas, but the supplied material does not establish that every change shipped specifically as part of the 1.0.0 release.

  • Confirmed: official release version 1.0.0.
  • Confirmed: PC-free installation of SideStore and LiveContainer is the project’s stated purpose.
  • Not confirmed from the supplied release page: a full feature-by-feature 1.0.0 changelog, performance measurements, or device-testing results.

Requirements and compatibility

The README lists an iPhone or iPad running iOS 27 as a requirement. It also lists Wi-Fi for the first-time setup and Apple account credentials. The source does not provide a broader supported-device matrix, an older-iOS compatibility list, or a statement that every iOS 27-compatible device will work identically.

The documented first step is connecting the device to LocalDevVPN or an alternative. The README then directs users to the official install page, where the app can be installed using one of the available certificates. After opening SideInstaller, the user signs in with an Apple account and chooses either “Install SideStore” or “Install SideStore + LiveContainer.”

Because the project’s process depends on certificates, pairing, provisioning, and Apple account sign-in, users should treat those requirements as part of the setup rather than assuming that downloading the app alone completes the installation. The source specifically says Wi-Fi is needed the first time, but it does not promise that every subsequent operation is independent of network access.

  • Supported platform stated by the README: iOS 27 on an iPhone or iPad.
  • First-time requirement stated by the README: Wi-Fi.
  • Account requirement stated by the README: Apple account credentials.
  • Connection step stated by the README: LocalDevVPN or an alternative.

How the official workflow is described

The README provides a seven-step process. First, connect the device to LocalDevVPN or an alternative. Next, use the official installation page and install SideInstaller with one of the listed certificates. Once the app is installed, open it and enter Apple account credentials. The final choice is between installing SideStore or installing SideStore together with LiveContainer, followed by waiting for the selected setup to finish.

This workflow is intentionally presented as a no-PC process. The README says there are no command-line steps or additional configuration requirements in the normal flow. That claim describes the intended user experience; it should not be read as a guarantee that every device, certificate, account, or network environment will complete setup without an error.

The repository asks bug reporters to include their iOS version, app version, and the step where the failure occurred. That gives users a practical way to document problems without assuming that all failures have the same cause.

Credential handling and the major security warning

SideInstaller’s README says Apple credentials remain on the device, are used locally to sign and install apps, and are not transmitted, logged, or collected by the official build. It also says the app has no server, analytics, or account-registration requirement, and that the source is available for auditing.

Those claims apply to the repository and builds published from it, according to the warning in the README. They do not automatically apply to forks, re-signed IPAs, or copies distributed elsewhere. The project specifically explains that an altered fork could look identical while adding credential-stealing behavior.

The maintainer therefore instructs users to use only the official website or repository. The README warns against third-party websites, AltStore sources, Telegram channels, Discord servers, app repositories, and mirrors. It also identifies a similarly named website as unofficial and potentially malicious. Readers should compare the source they are using with the official project identity before entering an Apple account password.

  • Do not enter Apple account credentials into a build obtained from an unverified distributor.
  • Do not assume that open-source availability makes every redistributed IPA trustworthy.
  • Check the official project source and its published installation path before proceeding.
  • Treat re-signed copies and mirrors as separate, unverified software.

What to verify before installing

Before starting, confirm that the device is running the required iOS version listed by the README and that Wi-Fi is available for first-time setup. Confirm that the installation page and app came from the official project source, not from a similarly named domain or an unsolicited repost.

Users should also understand which account they are entering and why it is needed: the README says the credentials are used for signing and installation. If a copy asks for credentials in a different context, redirects them to an unfamiliar service, or makes claims that do not match the official documentation, stop rather than continuing.

Finally, record the iOS version, SideInstaller version, and exact setup step if something fails. The source explicitly requests those details for bug reports and they can help distinguish an installation-page, certificate, pairing, provisioning, or account-related problem.
