Deck 1.1.0 Reimagines the Jailbroken iOS App Switcher With Cards, Pins and Control Center Controls

Deck 1.1.0 introduces a redesigned app switcher for jailbroken iPhone, iPad and iPod touch devices running iOS 15.0 through 18.7. The tweak replaces the standard app-switching presentation with configurable cards arranged in either a grid or carousel, while adding app pinning, per-card close buttons, activity labels, app counts and integrated Control Center controls. The package is sold through Chariz for $2.99 and requires MobileSubstrate, PreferenceLoader and firmware version 15.0 or newer.

Key points

  • Deck 1.1.0 is listed as the package’s initial release, despite using the 1.1.0 version number.
  • The tweak supports jailbroken iPhone, iPad and iPod touch devices running iOS 15.0–18.7.
  • Users can choose between grid and carousel app-switcher layouts.
  • Cards can be customized by size, shape, style and corner treatment.
  • Pinned apps remain open when Close All is used.
  • Control Center functions can appear as individual cards or as a compact bar beneath the app cards.

Deck 1.1.0 turns multitasking into a configurable card interface

Deck is a new app-switcher customization from Antony .M that replaces the conventional recent-app presentation with a card-based interface. The official package description presents it as a redesigned app switcher built around two primary viewing modes: a grid of cards or a carousel of larger cards.

The grid is intended to show several applications at once, while the carousel presents larger cards that users swipe through. This gives the tweak two distinct approaches to app switching rather than simply changing the appearance of the existing switcher. The available configuration options also make the interface more than a fixed visual replacement.

Grid and carousel layouts are only the starting point

Deck’s card system includes several layers of customization. Card size can be set to Small, Medium or Large. Users can also select Full, Tile or Square shapes. According to the official description, Tile and Square cards show the top portion of an app and unfold into the application as it opens.

The card styling options are Plain, Header, Framed and Floating. The Header option places the app icon and name across the top of the card, while the other choices provide different visual treatments. Corner settings include Normal, Rounded and Extra, allowing the appearance of the switcher to be adjusted independently of its layout.

These options matter because the tweak is aimed at users who want to change both how many apps are visible and how those apps are represented. A grid with smaller cards prioritizes overview, while larger carousel cards emphasize one application at a time. The source material does not claim that one mode is faster or more efficient, so the practical choice will depend on the user’s preferred workflow.

  • Layouts: Grid or Carousel
  • Card sizes: Small, Medium or Large
  • Card shapes: Full, Tile or Square
  • Card styles: Plain, Header, Framed or Floating
  • Corner treatments: Normal, Rounded or Extra

Pinned apps and Close All add more control

Deck adds a pinning feature for users who want certain applications protected from bulk-closing. Pinned apps receive a green outline and remain open when the Close All action is used. This is a specific behavioral distinction from ordinary cards, which can be closed individually or through the bulk action.

Every card includes a close button and the app’s name. The interface also displays an app count and a Close All control at the top, making it easier to see the current switcher state and perform a broad cleanup without swiping through every card.

The tweak additionally includes a pill that indicates what an app is doing, with the official description giving music playback as an example. This provides activity context directly in the switcher, although the source does not provide a complete list of supported activity types.

  • Pinned apps receive a green outline.
  • Pinned apps stay open when Close All is used.
  • Each card includes a close button and app name.
  • An activity pill can show information such as music playback.
  • The top of the interface displays the app count and Close All.

Control Center controls sit beneath the app cards

One of Deck’s more substantial additions is the integration of quick controls below the app cards. The official listing describes these as Control Center cards, placing app switching and a selection of system controls in one interface.

The listed controls include Airplane Mode, Cellular Data, Wi-Fi, Bluetooth, the music player, brightness, volume, flashlight, rotation lock, Low Power Mode, Dark Mode, Timer, Calculator, Camera and Control Center. The listing does not state that these controls replace or modify Apple’s underlying Control Center; it describes them as cards presented within Deck’s app-switcher interface.

For users who prefer a less expansive arrangement, Deck can instead show a single bar containing brightness, volume, music and Control Center. This gives users a choice between a larger collection of individual controls and a more compact presentation. The source does not specify whether every control is available in both presentation modes, so that detail should be checked in the tweak’s current settings or documentation.

  • Individual cards can expose connectivity, brightness, volume and media controls.
  • Additional listed options include flashlight, rotation lock, Low Power Mode and Dark Mode.
  • Timer, Calculator, Camera and Control Center are also listed.
  • A compact bar can show brightness, volume, music and Control Center.

Compatibility, dependencies and purchase details

The official Chariz listing says Deck supports iPhone, iPad and iPod touch running iOS 15.0 through 18.7. Jailbreak access is required. The package stanza separately declares firmware version 15.0 or newer, matching the listed minimum operating-system version.

The package depends on MobileSubstrate and PreferenceLoader. These are package-level requirements and should be considered before installation, particularly on a setup where either dependency is missing or supplied by a package manager in a different form. The source material does not name specific jailbreak tools, architectures beyond iphoneos-arm, or device models, so those details should not be inferred from the stated iOS range alone.

Deck 1.1.0 is listed at $2.99, with prices shown in U.S. dollars and possible sales tax depending on location. The seller is Antony .M, and the official version history labels 1.1.0 as the initial release. That means readers should treat this as the first published release described by the listing rather than assume that 1.1.0 follows an earlier public Deck release.

The official listing also says that changes apply instantly and do not require a respring. This is useful for configuration changes, but it should not be read as a guarantee that every package installation, update or system-level change avoids a respring. Before proceeding, users should confirm the package version, device operating system, jailbreak environment, required dependencies and the current purchase terms in the official Chariz listing.

  • Supported devices: iPhone, iPad and iPod touch.
  • Supported operating systems: iOS 15.0–18.7.
  • Jailbreak required.
  • Declared dependencies: MobileSubstrate and PreferenceLoader.
  • Listed price: $2.99, before any applicable sales tax.
  • The listing identifies 1.1.0 as the initial release.

What readers should verify before installing

The compatibility range is broad, but the official material does not identify individual device models or every jailbreak configuration. Users should therefore verify that their exact device and jailbreak environment meet the package manager’s requirements before buying or installing Deck.

It is also worth distinguishing Deck’s documented features from expectations about system behavior. The listing specifies the available layouts, card customization, pinning, controls and no-respring configuration changes, but it does not promise performance improvements, reduced memory use, compatibility with every other switcher modification or support for future iOS releases beyond 18.7.

Finally, readers should use the official package listing and their package manager’s normal purchase and installation flow rather than unofficial mirrors or modified packages. Checking the package identifier, version number and declared dependencies can help ensure that the selected package matches the release described here.
