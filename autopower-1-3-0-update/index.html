AutoPower 1.3.0 adds automatic Low Power Mode triggers for iOS 18 devices

AutoPower 1.3.0 is a jailbreak tweak designed to automate Low Power Mode around the device’s locked and unlocked states. According to the official package depiction, the release enables Low Power Mode after the screen is locked or turned off and exits Low Power Mode when the screen is turned on or unlocked. The update also adds a bilingual Chinese-English control interface. The package metadata lists iOS 18.0 through 18.7.9, an arm64 device architecture, and dependencies on MobileSubstrate and PreferenceLoader.

Key points

  • AutoPower 1.3.0 enables Low Power Mode when the screen locks or turns off.
  • Low Power Mode is disabled again when the screen turns on or the device is unlocked.
  • The screen-off trigger includes a slight delay, and the official description recommends lock-screen mode instead.
  • The package depiction lists compatibility with iOS 18.0 through 18.7.9.
  • The update adds a bilingual Chinese-English control interface.
  • Package metadata requires firmware 17.0 or newer, MobileSubstrate 0.9.5000 or newer, and PreferenceLoader 2.2.3 or newer.

What AutoPower 1.3.0 changes

AutoPower 1.3.0 targets a simple battery-management problem: Low Power Mode normally requires a manual decision, while many users only want it active when the device is not actively being used. The official description says the tweak automatically enables Low Power Mode after the screen is locked or turned off. It then exits Low Power Mode when the screen is turned on or unlocked.

That makes the release state-based rather than time-based. The supplied information does not describe battery-percentage rules, schedules, application-specific profiles, charging-state logic, or a custom delay setting. Its documented behavior is tied to screen and lock events. Readers should therefore treat AutoPower as an automatic screen-state switch, not as a broader battery automation platform.

  • Screen locked: AutoPower enables Low Power Mode.
  • Screen turned off: AutoPower enables Low Power Mode, with a documented delay.
  • Screen turned on: AutoPower exits Low Power Mode.
  • Device unlocked: AutoPower exits Low Power Mode.

The screen-off delay matters

The official depiction warns that the screen-off path does not activate Low Power Mode immediately. If the screen is turned off and then turned on again right away, the device may not enter Low Power Mode because the tweak waits briefly before applying the state change.

That behavior is important for users who frequently check the phone immediately after pressing the side button or who use short screen-off intervals. The source specifically recommends using the lock-screen mode instead of the screen-off mode. This is a recommendation from the package author, not an independent performance assessment, so users should review the available control options and decide which trigger better matches their routine.

The source does not state the exact duration of the delay. It also does not promise that every screen-off transition will result in Low Power Mode if the display is quickly reactivated. Those details should be treated as open implementation behavior rather than assumed settings.

  • The delay applies to the screen-off trigger.
  • The exact delay length is not specified in the supplied source.
  • The author recommends lock-screen mode over screen-off mode.
  • Quickly waking the device may prevent the screen-off transition from taking effect.

A bilingual interface is part of the release

The 1.3.0 changelog lists a bilingual Chinese-English control interface as a new feature. This is a user-interface change rather than a change to the documented automation rules. The source does not enumerate every translated label, identify the language-selection mechanism, or provide a complete control-panel walkthrough.

For users already familiar with the tweak, the practical significance is that the release is intended to make its controls available in both Chinese and English. However, the available material does not establish whether every description, warning, or preference is translated equally. That is something to inspect in the installed preference pane before relying on a particular label.

  • The changelog identifies Chinese-English interface support.
  • The source does not list individual translated controls.
  • The language-selection process is not documented in the supplied material.

Compatibility and package requirements

The package metadata identifies AutoPower as run.cheng.autopower, version 1.3.0, with an arm64 iPhoneOS architecture. Its dependency list requires MobileSubstrate version 0.9.5000 or newer, PreferenceLoader version 2.2.3 or newer, and firmware version 17.0 or newer. The package also conflicts with run.cheng.autopower.debug, meaning the debug package should not be treated as a parallel installation option where the package manager enforces that conflict.

The official depiction separately lists iOS versions 18.0 through 18.7.9. That is the release’s stated compatibility range in the supplied package information. It should not be expanded to other iOS versions, device architectures, or jailbreak environments without additional documentation. The depiction also says the author is unsure whether compatibility extends to other devices and invites users to test the source themselves; that is a clear reason to avoid assuming support beyond the listed range.

The metadata reports a package size of 20.19 KB in the depiction and an archive size of 20,676 bytes in the package stanza. The installed size is listed as 188 KB. These are package measurements, not an indication of battery impact or runtime resource usage.

  • Package identifier: run.cheng.autopower.
  • Version: 1.3.0.
  • Listed architecture: iphoneos-arm64.
  • Listed iOS range: 18.0–18.7.9.
  • Required firmware: 17.0 or newer.
  • Required dependencies: MobileSubstrate 0.9.5000 or newer and PreferenceLoader 2.2.3 or newer.

What to verify before installing

Before installing, confirm that the device is within the iOS range shown in the official depiction and that the jailbreak environment provides the required MobileSubstrate and PreferenceLoader versions. The firmware dependency is stated as 17.0 or newer in package metadata, while the depiction presents a narrower iOS 18.0–18.7.9 compatibility range; users should consider both statements rather than relying on the dependency line alone.

It is also worth checking whether the debug variant is already present, since the package declares a conflict with run.cheng.autopower.debug. If the package manager reports a dependency, architecture, or conflict problem, the source material does not provide a workaround and users should not bypass those checks.

Finally, decide whether the lock-screen trigger or screen-off trigger is appropriate. The source specifically cautions about the screen-off delay and recommends lock-screen mode. Since no exact timing or complete preference guide is supplied, users should review the tweak’s own controls and avoid assuming that a quick display wake will behave like a completed screen-off transition.

The supplied package information does not include a step-by-step installation procedure. Readers should use the package manager and repository entry supplied by their jailbreak setup, obtain the package from the official distribution channel, and verify the displayed identifier and version before proceeding. No unofficial mirrors or bypass methods are necessary or recommended.

  • Check the device’s iOS version against 18.0–18.7.9.
  • Check for the required substrate, preference-loader, and firmware versions.
  • Remove or account for the conflicting debug package if present.
  • Review the available trigger controls after installation.
  • Do not assume support for unlisted devices or versions.
  • Confirm the package identifier is run.cheng.autopower and the version is 1.3.0.

A note about the supplied source material

The source bundle also contains an unrelated repository description for a project called thermeq3, described as a boiler-control device for the ELV/EQ-3 MAX! cube. Its README and commit history concern Linux, Arduino, Raspberry Pi, heating control, weather services, and Max!Cube data processing. Those details do not describe AutoPower 1.3.0 and provide no evidence about this iOS tweak’s behavior or compatibility.

For this release, the relevant evidence is the AutoPower package stanza and its official package depiction: automatic Low Power Mode behavior, the screen-off delay warning, the bilingual interface change, package requirements, and the listed iOS range.
