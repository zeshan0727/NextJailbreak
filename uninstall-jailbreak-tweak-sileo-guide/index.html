How to Uninstall a Jailbreak Tweak Safely in Sileo

Removing a normal tweak should be a reviewed package-manager transaction—not a manual file-deletion job. Sileo queues the uninstall so you can catch unexpected dependency removals before confirming.

By Zeeshan Barvi · Published October 16, 2026 · Verified against the official Sileo 2.5.1 source

Important: uninstalling one tweak is different from removing a jailbreak. Stop if Sileo proposes deleting your package manager, APT/dpkg, the jailbreak bootstrap, a hooking framework, or other core packages you did not intend to remove.

Quick answer

Open Sileo → Packages → Installed, select the exact tweak, choose Modify → Uninstall, and review the queue before confirming. Sileo’s official 2.5.1 source also exposes a destructive uninstall swipe action in the installed-package list; either route adds the package to the uninstall queue rather than silently deleting it.

After the transaction, use only the action Sileo requests—such as returning to Sileo, respringing, or restarting userspace. A full reboot can return a semi-untethered jailbreak to a non-jailbroken state and is not automatically required for every tweak removal.

Before you remove the tweak

  1. Confirm the package. Record its display name, package identifier, version and developer. Similar names can belong to unrelated packages.
  2. Check whether it is a dependency. A library or framework may be required by several installed tweaks even if it has no visible icon or Settings pane.
  3. Identify the active environment. Rootful, conventional rootless and RootHide package layouts differ. Run the removal inside the same active jailbreak environment that installed the package.
  4. Save settings only if they matter. Removing a package can leave preference files behind; that can help preserve settings for a reinstall, but it can also preserve a bad configuration. Do not delete jailbreak directories by hand.

Uninstall a tweak safely in Sileo

  1. Open Sileo while the jailbreak environment and package manager are working normally.
  2. Go to Packages, select Installed, and search for the exact tweak. You can also open its installed package page from Search.
  3. Open the package page, tap Modify, then choose Uninstall. In list views that expose it, the destructive swipe action reaches the same uninstall queue.
  4. Open the queue and read every proposed operation. The target tweak should appear under removals; a documented companion package may also appear if nothing else requires it.
  5. If the queue includes an unrelated package—or any core component—cancel and investigate before confirming.
  6. Confirm the transaction only when the removal list matches your intent.
  7. Follow the exact completion action Sileo displays. Then reopen Sileo and check that the package no longer appears as installed.

How to read the removal queue

Queue resultWhat it meansSafe response
Only the target tweakThe ordinary, low-surprise case.Confirm after checking the identifier and version.
Target plus a clearly named companionA helper may be installed solely for that tweak.Verify it on the developer’s official package page before confirming.
Many unrelated tweaksThe target may provide a shared library or dependency.Cancel. Remove dependent packages deliberately or keep the shared package.
Sileo, APT, dpkg, Procursus/base packages, bootstrap components or the tweak-hooking frameworkThe transaction reaches the package-management or jailbreak foundation.Cancel. Use the jailbreak project’s official repair or removal process instead.
Unexpected upgrades or downgradesRepository state is changing more than the requested tweak.Cancel and resolve dependency errors first.

Package names vary by jailbreak. Do not rely on one universal “safe list”; the decisive evidence is the installed package’s role and the transaction Sileo actually proposes.

If Sileo cannot open normally

If a bad tweak sends SpringBoard into Safe Mode or a crash loop, use the jailbreak’s documented option to start with tweak injection disabled. On Dopamine, reboot if needed, open Dopamine, disable tweak injection before jailbreaking, then launch Sileo and remove the suspected package. Follow our Dopamine bad-tweak recovery guide for that workflow.

Do not repeatedly respring into the same failure and do not delete random dylibs over SSH. Disabling injection provides a controlled way to reach the package manager while keeping the transaction database involved.

Uninstall, purge and remove the jailbreak are different

ActionRemovesUsually keeps
Uninstall a tweakThe selected package files and registered package state.The jailbreak, Sileo and sometimes the tweak’s preference file.
Purge a packageThe package plus configuration files known to the package manager.The rest of the jailbreak environment.
Remove the jailbreakThe jailbreak’s bootstrap/environment through its official removal workflow.User data outside that scope, subject to the project’s documented process.

Sileo’s APT parser recognizes separate remove and purge operations, but the package interface may not offer both for every package or transaction. Never imitate a purge by manually deleting system or bootstrap paths.

What if the Settings pane remains?

First respring if Sileo requested it. If the preference pane still appears, verify that the package is no longer installed and check whether a separate preference bundle package remains. A leftover preferences file alone does not mean the tweak is still injecting. Reinstalling the same tweak may reuse those settings.

For dependency failures, held packages or architecture conflicts, use the Sileo dependency-error guide. For an interrupted dpkg transaction, use the Sileo and dpkg repair guide rather than deleting lock files.

Compatibility boundary

Sileo 2.5.1 is a package-manager release, not a jailbreak for every iPhone or iOS version. An iOS compatibility line on a tweak also does not prove that your device has a jailbreak for that firmware. Confirm the jailbreak, device, firmware, package architecture and rootful/rootless/RootHide environment separately.

Official sources

  • Sileo 2.5.1 release — GitHub records the stable release on October 8, 2024.
  • Official package-page queue action — exposes the uninstall action.
  • Official installed-list uninstall swipe — adds the selected package to uninstallations.
  • Official APT operation parser — distinguishes remove and purge operations.

Source checked October 16, 2026. Sileo 2.5.1 remained the latest official stable GitHub release at verification time. This guide describes the project’s source-defined transaction flow and does not claim hands-on testing with every tweak or jailbreak.

Queue checklist

Target: exact package ID and version.

Expected: the tweak and documented companion only.

Stop if: core package-manager, bootstrap or injection packages appear.

Finish with: the action Sileo requests.
