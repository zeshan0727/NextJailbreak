iSponsorBlock 1.3.3 Fixes Crashes on Newer YouTube Player Bars

Version 1.3.3 updates iSponsorBlock for YouTube’s newer player-bar structure, preventing the sponsor-marker path from crashing when old internal views are missing.

By Zeeshan BarviPublished October 30, 20267 min read
Current release: iSponsorBlock 1.3.3 was published October 25, 2026. Update first if YouTube crashes when sponsor markers appear or when playback starts on a video with SponsorBlock data.

What iSponsorBlock 1.3.3 changes

The version bump follows a source-level fix for newer YouTube player bars. Older builds expected a legacy accessibility delegate and a particular segment-view array when drawing SponsorBlock markers. Newer YouTube layouts may not expose those objects, causing the marker path to fail.

The fix now prefers the owning player controller, walks the responder chain when necessary, safely falls back to the legacy delegate, and searches visible player-bar subviews if the old segment list is unavailable. It also exits early when there are no segments. This is a targeted compatibility repair; it does not add a new ad blocker or change YouTube’s own advertisements.

Who should update?

  • Update now if YouTube crashes when opening a video, sponsor markers load or the player bar appears on a recent YouTube version.
  • Update normally if 1.3.2 works: 1.3.3 is the current maintenance release and preserves the same SponsorBlock feature set.
  • Do not install blindly if your package manager offers a build for a different architecture or if YouTube is already modified by another bundled SponsorBlock implementation.

What the tweak actually skips

iSponsorBlock uses the community SponsorBlock API for creator-inserted segments inside videos. Its source includes controls for sponsor messages, intros, outros, interaction reminders, self-promotion, music outside a music video, tangents or filler, and highlight markers. Each category can be handled according to the tweak’s settings rather than treating every segment identically.

This is separate from YouTube’s server-delivered or app-delivered advertising. If regular ads still appear, that does not prove the SponsorBlock integration is broken. A video may also have no submitted community segments.

Install or update safely

  1. Add https://repo.icrazeios.com to Sileo or Zebra, or refresh it if already present.
  2. Open iSponsorBlock and confirm the candidate version is 1.3.3 and that the architecture matches your jailbreak environment.
  3. Review the dependency transaction. Do not remove core bootstrap packages to satisfy a tweak dependency.
  4. Install the update, close YouTube completely, then respring if requested.
  5. Open YouTube and use the iSponsorBlock button in the top-right area to review category behavior and channel-whitelist settings.

If you need another package manager, see how to install Zebra alongside Sileo. If the queue reports unresolved packages, follow the rootless dependency repair guide before forcing anything.

Troubleshooting after 1.3.3

YouTube still crashes

Confirm the installed iSponsorBlock version, force-close YouTube, and respring so the old injected process is gone. Disable other YouTube tweaks temporarily, especially another SponsorBlock implementation or anything that replaces the player bar. If the crash stops, re-enable tweaks one at a time.

Sponsor markers appear but nothing skips

Open the in-app settings and check the action assigned to that segment category. A category may be configured to show a prompt or marker rather than skip automatically. Also try another well-known video: SponsorBlock depends on community submissions and may have no data for a new or obscure upload.

The iSponsorBlock button is missing

Verify that the jailbreak is active, the correct rootful/rootless build is installed, Alderis is present, and YouTube falls within the developer’s documented range. A future YouTube layout change can move or break private interface hooks even when the iOS package itself installs successfully.

Settings work but Picture in Picture or overlay buttons do not

Those features may come from separate YouTube tweaks. Check the current YouPiP compatibility notes and YTVideoOverlay update rather than attributing every player control to iSponsorBlock.

Unsupported or unverified situations

  • RootHide compatibility is not stated by the current project documentation.
  • Sideloaded YouTube bundles that include their own iSponsorBlock copy may lag behind 1.3.3; installing the jailbreak package on top can create duplicate injection.
  • The project’s YouTube 17.30.1–21.x.x statement is a developer-tested range, not a guarantee for every intermediate or future release.
  • iSponsorBlock cannot skip a segment that has not been submitted to SponsorBlock or when the API is unavailable.

Frequently asked questions

Does iSponsorBlock block normal YouTube ads?

No. It uses SponsorBlock data to skip creator-inserted segments such as sponsors, intros and self-promotion. YouTube advertisements are a separate system.

Does version 1.3.3 add new segment categories?

No new category is documented for 1.3.3. Its verified change is the newer-player-bar crash fix; the broader category set comes from earlier current source.

Is iSponsorBlock 1.3.3 rootless?

The source Makefile contains a rootless packaging path and the repository has historically served rootful and rootless builds. Confirm the architecture shown by your package manager before installing.

Does iOS 13+ mean it works on my device?

No. That is the package’s minimum firmware dependency. Your device and firmware still need a compatible jailbreak and injection environment.
