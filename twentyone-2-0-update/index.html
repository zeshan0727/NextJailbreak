TwentyOne 2.0 Reworks Apple Music’s Interface With Animated Artwork and Last.fm Scrobbling

The open-source TwentyOne project has reached version 2.0 with a broad rewrite of its Apple Music customization code. The update is described by its developer as faster and adds full-screen animated album artwork in Now Playing and on the lock screen, alongside native Last.fm scrobbling. Its source also includes album-driven color tinting, separate tweak components for Music, SpringBoard and MediaRemoteUI, a preferences bundle, and packaging workflows for rootless, rootful and roothide variants.

Key points

  • TwentyOne 2.0 is identified in the package control file as version 2.0 and uses package identifier com.pisknk.twentyone.
  • The project’s v2 commit describes refactored code intended to run faster, full-screen animated album artwork, and native Last.fm scrobbling.
  • The source contains artwork color analysis and album-detail tinting logic, including light/dark interface-style selection.
  • The package declares mobilesubstrate and firmware version 16.0 or newer as dependencies.
  • The build workflow produces rootless arm64/arm64e, rootful arm64 and roothide arm64e package variants.
  • The repository does not provide a detailed user-facing compatibility matrix or documented release notes beyond its commit messages and package metadata.

What changed in TwentyOne 2.0

TwentyOne is an Apple Music visual customization tweak whose stated project goal is to port or recreate the iOS 26 Apple Music interface. The project’s version 2 commit describes three headline changes: refactored old code intended to run faster, full-screen animated album artwork in Now Playing and on the lock screen, and native Last.fm scrobbling.

The repository metadata identifies the package as TwentyOne, version 2.0, with the identifier com.pisknk.twentyone. That version is also present in the package control file. The source does not describe this as an official Apple Music release; it is a third-party tweak project implemented through separate components that integrate with system and Music-related processes.

  • Refactored code, according to the developer’s v2 commit message.
  • Full-screen animated album cover support in Now Playing and the lock screen.
  • Native Last.fm scrobbling.
  • A packaging fix in the following commit makes the DEBIAN post-install script executable.

Animated artwork and album-driven visual styling

The source provides more detail about the visual work behind the update. Its artwork code can extract images from several catalog- and view-related sources, record recently tapped artwork, and calculate a dominant color from the image. The color routine reduces artwork to a small thumbnail, averages its pixels, and adjusts saturation and brightness before producing a tint color.

That result is used by album-detail logic to create a list surface, choose foreground colors, and select a light or dark user-interface style. The code also searches selected or highlighted cells in collection and table views for artwork, allowing it to derive a tint when a user opens an album or other artwork-driven detail view.

This is more specific than a simple global color theme. The implementation is designed to associate an album’s artwork with the surrounding detail interface, while also handling cases where the artwork cannot be found. In the fallback path shown in the source, the detail view can use the system background color.

  • Artwork is sampled to derive a dominant color.
  • Album detail surfaces and text colors can be adjusted from that color.
  • The implementation considers selected and highlighted artwork in collection and table views.
  • The source includes brightness, saturation, luminance and contrast-related helpers.

Where the tweak integrates

The Makefile defines three tweak targets: TwentyOne, TwentyOneScrobbler and TwentyOneLockScreen. The main target includes files for home-tab changes, artwork painting, Now Playing overlays, immersive Now Playing behavior, model utilities, preferences storage and scrobble state. It links against UIKit, Core Image, Core Graphics, Quartz Core, AVFoundation, Security and MediaPlayer.

The scrobbler target contains Last.fm manager and scrobbling code, shared preferences support and lock-clock-related integration. The lock-screen target includes motion and artwork resolver components. The Makefile also lists Music, SpringBoard and MediaRemoteUI under the processes to install the tweak into, which indicates the project is designed to affect both the Music experience and system surfaces such as the lock screen.

A separate TwentyOnePrefs bundle is included under the preference-bundle installation path. Its source references UIKit, Core Graphics, Safari Services and the private Preferences framework. The supplied material does not enumerate every setting exposed by that bundle, so users should not assume that every implementation detail is configurable.

  • Main target: TwentyOne.
  • Additional targets: TwentyOneScrobbler and TwentyOneLockScreen.
  • Preferences are packaged as TwentyOnePrefs.
  • The declared install target processes include Music, SpringBoard and MediaRemoteUI.

Last.fm scrobbling is a notable functional addition

The v2 commit explicitly calls native Last.fm scrobbling a new feature. The repository includes dedicated Last.fm manager, shared-state, badge-view and scrobbler files, rather than treating scrobbling as a small cosmetic option. The source also includes a scrobble-state client and preferences storage components.

The supplied material does not document account-linking steps, authentication behavior, scrobble timing, retry handling or which playback states are submitted. Those details should be checked in the project’s current preference interface and source before relying on the feature. The presence of native Last.fm code confirms the feature is part of the project, but it does not by itself establish that every Last.fm workflow is supported.

  • Last.fm support is explicitly listed in the v2 commit.
  • Dedicated Last.fm manager and scrobbler source files are present.
  • Authentication and account-setup instructions are not documented in the supplied README.

Compatibility and package variants

The package control file declares a dependency on mobilesubstrate and firmware version 16.0 or newer. That is the project’s explicit package-level firmware requirement. The build configuration targets iPhoneOS 16.5 SDK tooling and uses a deployment target of 16.0 in the workflow commands, while the Makefile’s default target references an iPhoneOS 16.2 toolchain with a 16.0 deployment target.

The automated build workflow is configured to create three package variants. The rootless build uses the iphoneos-arm64 package architecture and compiles for arm64 and arm64e. The rootful build uses iphoneos-arm and arm64. The roothide build uses iphoneos-arm64e and the repository’s roothide module path.

These build settings should not be treated as a complete device-support list. The source establishes package architectures, build targets and a firmware dependency, but it does not identify jailbreak tools, bootstrap versions, device models or exact iOS releases beyond the stated 16.0-or-newer requirement. Users should match the package variant to their environment rather than selecting one solely by processor architecture.

  • Declared package dependency: mobilesubstrate.
  • Declared firmware dependency: 16.0 or newer.
  • Workflow variants: rootless, rootful and roothide.
  • The workflow checks that three DEB artifacts are present before uploading build artifacts.
  • The project does not publish a complete jailbreak- or device-specific compatibility matrix in the supplied README.

Packaging fix after the v2 commit

A follow-up commit changes the mode of layout/DEBIAN/postinst from 100644 to 100755. The commit message explains that dpkg-deb requires maintainer scripts to be executable and that the repository’s core.fileMode setting is disabled, so the executable bit had to be set explicitly in the Git index.

This is a packaging correction rather than a user-facing feature. It matters because a correctly packaged maintainer script can prevent installation-time failures related to file permissions. However, the supplied source does not include a published binary checksum, a release asset, or a statement that a package was successfully installed on a particular device. Readers should therefore treat the packaging workflow as build information, not as proof of universal installation success.

  • The corrected file is layout/DEBIAN/postinst.
  • The change sets executable mode 100755.
  • The commit specifically addresses DEB packaging requirements.

What to verify before installing

TwentyOne is distributed as jailbreak-oriented package source, and its package metadata declares both mobilesubstrate and firmware 16.0 or newer. Before using it, confirm that the intended environment supplies the required substrate and that the package architecture matches the available jailbreak setup.

It is also worth checking whether the current Music and system frameworks match the assumptions in the source. The tweak uses hooks and internal interfaces across Music, SpringBoard and MediaRemoteUI, while several source files reference private or implementation-specific classes and selectors. The supplied project description does not promise compatibility across all later Apple Music or iOS builds.

Finally, review the project’s current source and build output rather than relying on an old package. The repository contains no releases according to the supplied page data, and the README consists only of a short project description. That makes the commit history, package control file and build configuration especially important when identifying the current state.

  • Confirm firmware and substrate requirements.
  • Choose the correct rootless, rootful or roothide variant for the target environment.
  • Check the package architecture before installation.
  • Review current source changes because the project uses system and Music-related hooks.
  • Do not infer device-wide compatibility from the 16.0 package dependency alone.
