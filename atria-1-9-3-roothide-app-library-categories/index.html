Atria 1.9.3 Adds Native RootHide Support and Custom App Library Categories

CySxL’s Atria fork replaces the dormant original package with native RootHide and rootless builds, iOS 16–17 fixes and a new App Library category editor. Version 1.9.3 also makes category exports optional because they reveal the installed-app list. The compatibility labels need care: the repository describes iOS 16–17 use, declares firmware 15.0 or later, marks the rootless build untested and does not confirm iOS 26 support.

By Zeeshan Barvi · Published November 12, 2026 · Official release commit: 89a8339

Atria is a tweak, not a jailbreak. Its package compatibility does not create jailbreak support for an otherwise unsupported device or firmware.

What is actually new in Atria 1.9.3

The official repository records Atria 1.9.3 in commit 89a8339 on November 12, 2026 at 14:23:31 UTC. The 1.9.3 changelog is focused on privacy and state handling:

  • Category export choice: Atria now asks whether App Library categories should be included when exporting settings, because that data lists installed apps.
  • Saved category edits: changes from Edit Categories are retained if Settings is closed from the app switcher.
  • Version guard: Custom Categories stays inactive on iOS versions that lack the required behavior.
  • Hide Actions polish: the developer lists refinements without claiming a broader compatibility change.

The larger change is the maintained fork itself. Versions 1.8.2 through 1.9.2 added native RootHide and rootless packages, label offsets, dock labels, per-page dot positions, custom App Library categories, category ordering, category hiding controls and multiple SpringBoard fixes.

Both official packages depend on MobileSubstrate and PreferenceLoader. They share package ID com.cysxl.atria but use different architectures for conventional rootless and RootHide environments.

How the fork replaces the original Atria

The new package does not install beside ren7995’s me.lau.atria. Official metadata says it replaces and provides that package and also conflicts with the original Atria, Boxy 4 and HomePlus Pro. That prevents two layout engines from trying to control the same Home Screen at once.

Existing Atria layout and per-page settings are intended to carry over, but export the original settings first. Version 1.9.3’s export prompt matters if custom App Library categories are enabled: including them can expose the names of installed apps in the exported string.

Custom App Library categories

The maintained fork can move apps between App Library categories, rename and reorder categories, create new categories and restore Apple’s stock grouping with Reset Categories. It can also hide Suggestions and Recently Added and choose which category the Floating Dock’s App Library icon opens.

These controls are more invasive than changing rows or icon spacing because they maintain a separate category map. Make one small change, return to the App Library, and verify the result before reorganizing the full library. Keep a settings export without category data as a privacy-conscious fallback.

Safer migration from Atria 1.4.1

  1. Open the original Atria settings and export the current layout. Store the string privately.
  2. Confirm the exact jailbreak environment: RootHide or conventional rootless. Do not install both package architectures manually.
  3. Add CySxL’s official repository in Sileo or Zebra and select Atria 1.9.3.
  4. Review the package-manager transaction. It should replace the original Atria rather than leave two Atria packages installed.
  5. After respringing, test the stock layout first. Then restore layout settings before enabling Custom Categories.
  6. Enable category features gradually and keep the Reset Categories action available.

Troubleshooting

SpringBoard enters safe mode after installation

Restart without tweak injection or use your jailbreak’s safe mode, then remove Atria or disable other Home Screen layout tweaks before respringing. The package explicitly conflicts with the original Atria, Boxy 4 and HomePlus Pro; do not bypass those conflict rules.

The editor crashes on iOS 17

Confirm that version 1.9.3 is actually installed. The fork’s 1.8.5 changelog records a fix for SpringBoard entering safe mode when the editor opened on iOS 17.

Custom Categories is unavailable

Version 1.9.3 intentionally leaves it inactive on iOS versions missing required behavior. That guard should not be interpreted as a failed installation, and forcing the setting is not a verified workaround.

Categories or app positions look wrong

Use Reset Categories to restore Apple’s grouping, then import only the layout portion of a known-good export. Avoid importing someone else’s category data because it can reference apps that are not installed on your device.

Frequently asked questions

Is Atria 1.9.3 the same package as the old Chariz release?

No. CySxL’s fork uses package ID com.cysxl.atria and is configured to replace and provide the original me.lau.atria package.

Is the rootless build confirmed stable?

No. The official repository publishes a rootless arm64 package but explicitly labels that build “not yet tested.”

Does Atria 1.9.3 support iOS 26?

Full support is not confirmed. The changelog says three iOS 26 SpringBoard launch crashes were fixed and Dynamic Widget Sizing was disabled there, which is narrower than a compatibility guarantee.

Why does category export need a warning?

Custom category data contains the installed-app list. Version 1.9.3 asks whether to include it so users can omit that information from shared settings exports.
