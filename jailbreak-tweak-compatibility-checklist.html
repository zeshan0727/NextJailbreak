How to Check Jailbreak Tweak Compatibility Before Installing

A package can appear in Sileo and still be wrong for your bootstrap, firmware, target app or tweak-injection framework. Use this preflight to distinguish rootful, conventional rootless and RootHide builds, interpret the package fields that matter and prepare a recovery path before you tap Install.

By Zeeshan Barvi · Published September 10, 2026 · Materially updated November 2, 2026 from current official Theos, Dopamine and RootHide documentation

The two checks people most often confuse: package compatibility does not create a jailbreak, and a matching architecture does not guarantee runtime compatibility. Confirm both the jailbreak path for your device and the tweak’s own package requirements.

Step 1: identify the environment you actually have

Record the exact device model, iOS or iPadOS build, active jailbreak and bootstrap—not just “iOS 17” or “Dopamine-compatible.” A rebooted semi-untethered device may still have Sileo installed while tweak injection is inactive. RootHide is a distinct environment, not another name for conventional rootless.

If a terminal is already available in the active jailbreak, this command reports dpkg’s native package architecture:

dpkg --print-architecture

Treat that output as one input, not the entire decision. A package can contain the right architecture and still require a different firmware, injection framework, app version or bootstrap behavior. If the setup itself is unclear, start with the rootful vs rootless vs RootHide guide.

Step 2: match the package identifier and current version

Open the developer’s official repository, GitHub release or store page and compare three values: package identifier, version and developer. A familiar display name or icon is not enough. Mirrors can retain both while serving a modified or stale build.

  • Use the newest official version intended for your environment; do not assume the highest number shown by an unrelated repository is newer or safer.
  • For paid packages, use the authorized repository tied to the purchase. Do not substitute cracked or re-signed packages.
  • If the developer supplies different rootful, rootless and RootHide files, keep their exact package lanes separate.
  • If you downloaded a loose .deb, use the read-only dpkg-deb inspection guide before installing it.

Step 3: read Architecture—then keep reading

Theos currently documents iphoneos-arm for rootful packages and iphoneos-arm64 for conventional rootless packages. Its rootless scheme uses /var/jb and can include relocated-jailbreak-root runtime paths. That is why renaming a file or forcing a rootful package into Sileo does not convert its paths or binaries.

The official RootHide repository contains iphoneos-arm64e packages, while RootHide Patcher 2.1.4 itself states that it converts eligible rootless packages and “not work for all packages.” Therefore:

  • Do not install an iphoneos-arm package on rootless merely because the tweak supports the same iOS version.
  • Do not call an iphoneos-arm64 build RootHide-compatible unless the developer documents it or an official conversion workflow supports it.
  • Do not infer RootHide support from the word rootless. The filesystem and runtime assumptions differ.
  • Do not force an architecture with dpkg options to bypass the package manager. That suppresses a useful safety check without fixing the package.

Step 4: translate firmware dependencies literally

Theos documents the firmware meta-package as the normal way to express iOS limits in Depends. For example:

Depends: firmware (>= 15.0), firmware (<< 18.0), mobilesubstrate

This means the package metadata permits iOS 15 through 17.x and requires a compatible injection provider. It does not mean every device on those versions has a public jailbreak. As of November 2, Dopamine 3.0.12’s official matrix lists arm64e on iOS 15.0–17.3.1, A12/A13 on iOS 15.0–18.7.1 and 26.0–26.0.1, and arm64 on iOS 15.0–18.7.1. It does not list other iOS 26 releases, and another jailbreak can have different boundaries.

Also watch for missing upper bounds. A package that says only firmware (>= 15.0) can remain installable on a later iOS release even when the developer has not tested new frameworks or interface changes.

Step 5: inspect the whole Sileo transaction

Before confirming, expand the queue and read the relationships Theos documents for Debian packages:

FieldQuestion to answer
Depends / Pre-DependsAre the required libraries, firmware range, PreferenceLoader and injection provider expected?
ConflictsWill this package remove or block another tweak you rely on?
Replaces / ProvidesIs it intentionally taking over another package’s files or virtual role?
Install / Upgrade / Remove queueIs Sileo proposing changes to bootstrap, package-manager or injection components that the tweak does not explain?

Cancel if a cosmetic tweak unexpectedly wants to replace core packages, add an unknown repository, downgrade the bootstrap or remove the package manager. Do not use --force-depends to turn an unresolved transaction into an installed but inconsistent one. Use the Sileo dependency-error guide instead.

Step 6: check the target app or system process

App-specific tweaks have two compatibility layers: iOS and the target app. YouTube, Instagram and WhatsApp can change internal classes without changing your jailbreak. A package may install successfully and then crash only the newer app build.

  • Match the exact App Store app version to the developer’s tested range.
  • For SpringBoard, Lock Screen, Control Center or keyboard tweaks, check the exact iOS range and whether the package targets iPhone, iPad or both.
  • Check whether the developer requires ElleKit, Substitute, libhooker or another injection provider; provider packages are not interchangeable merely because they satisfy a virtual dependency.
  • If two installed tweaks hook the same view or process, test them separately even when each is individually supported.

Step 7: prepare recovery before installation

  1. Install one major system tweak at a time.
  2. Screenshot or export the Sileo transaction and note the last known-good package version.
  3. Know how to start the jailbreak with tweak injection disabled or enter its Safe Mode.
  4. For one problematic app, use a supported per-app injection control rather than removing unrelated packages; see the Choicy guide.
  5. If SpringBoard loops or crashes, follow the Dopamine bad-tweak recovery guide and remove the newest change first.

A rollback plan does not make an unsupported tweak safe, but it limits the cost of an honest compatibility mistake.

Pre-install checklist

  • Exact device, firmware build, jailbreak and active bootstrap recorded.
  • Official package identifier and current version matched.
  • Architecture matches rootful, conventional rootless or explicitly supported RootHide packaging.
  • Minimum and maximum firmware dependencies read literally.
  • Dependencies, conflicts, replacements and removals reviewed.
  • Target-app version or affected iOS process confirmed.
  • Conflicting tweaks considered and only one major change queued.
  • Safe Mode, injection-disable or removal path understood.

Official sources

  • Theos packaging documentation — control fields, firmware dependencies and rootful/rootless architecture names.
  • Theos rootless documentation — /var/jb, rootless v2 paths and package-manager architecture filtering.

  • RootHide Patcher 2.1.4 control metadata — current architecture, firmware requirement and explicit conversion limitation.
