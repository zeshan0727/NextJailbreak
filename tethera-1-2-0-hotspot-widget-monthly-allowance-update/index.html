Tethera 1.3.0 Adds Hotspot-Wide Ad Blocking and Recent Sites

Tethera 1.3.0 can filter ads, trackers and malware domains for every device on an iPhone hotspot, show each client's recent DNS lookups locally, and repair a no-internet failure seen with some unrecognized travel eSIMs. All three changes have limits worth checking before you update.

By Zeeshan BarviUpdated November 28, 20268 min read
Confirmed release: Havoc's embedded package data lists Tethera 1.3.0, updated November 27, 2026 at 13:30:01 UTC. The listing gives package ID com.aadios.tethera, price $7.99, iOS 15.0–26.0.1, jailbreak required and rootless support.

What changed in Tethera 1.3.0

ChangePractical benefitImportant limit
Ad BlockFilters ads, trackers and malware domains for all clients on the hotspot, using maintained blocklists plus custom block/allow rules.Off by default; a device can be exempted. Domain filtering cannot remove every ad or tracker.
Recent SitesShows DNS lookups made by each hotspot client during the previous 24 hours, with quick block and allow actions.Off by default and stored on the iPhone. It is not a full page-level browser history.
Travel-eSIM fixLets clients use the iPhone's data connection when iOS does not recognize the SIM carrier and the hotspot previously came up without internet.Targets that failure mode; it does not promise support for every carrier policy or eSIM.

The update builds on 1.2.0 rather than replacing its hotspot widgets, monthly allowance, Wi-Fi departure automation or IPv6 switch. The new value is network-wide filtering and a more useful diagnosis trail for devices that share the connection.

How the new Ad Block feature works

AADiOS says the filter uses well-known blocklists kept current to stop ad, tracking and malware domains for devices connected to the iPhone hotspot. Tethera also tries to prevent clients from bypassing the filter with encrypted DNS. That wording matters: it is a mitigation, not a guarantee against every encrypted-DNS app, VPN, first-party ad or hard-coded IP address.

Start with the supplied lists before adding custom domains. If an app, captive portal or payment flow stops loading, allow the required domain rather than disabling the whole feature. For a game console, work laptop or another client that needs its own DNS policy, use the per-device exemption documented in the changelog.

Recent Sites is local DNS history, not full browsing history

Recent Sites appears on the main Ad Block page and on each connected-device page. It shows sites the device looked up during the last 24 hours, lets you block or allow an entry, and is disabled until the user turns it on. The developer says the data stays on the iPhone.

A DNS lookup can reveal a service domain but not necessarily the exact page, search query or person using a shared client. Conversely, apps can contact many background domains without someone opening them directly. Treat the list as troubleshooting evidence, not a complete or infallible browsing log, and only enable it where the device owners understand the monitoring.

The travel-eSIM fix has a narrow scope

Before 1.3.0, a SIM or eSIM whose carrier iOS did not recognize could produce a misleading state: Personal Hotspot was on and clients connected, but those clients had no internet. The changelog says Tethera now shares the iPhone's own data connection in this case.

This does not create free tethering or override a carrier plan. Carrier terms, network provisioning and hotspot allowances still apply. If the iPhone itself has no data, or the carrier blocks tethering at the account level, this specific fix does not establish that Tethera can change those conditions.

Compatibility: package range is not jailbreak availability

  • Havoc package range: iOS 15.0–26.0.1, jailbreak required, marked rootless.
  • Current version: 1.3.0, 2,496,244 bytes in the official package metadata.
  • Home/Lock Screen widgets: still require iOS 16.1 or later, according to the 1.2.0 changelog.
  • Control Center: the product page documents iOS 15–17 with CCSupport.
  • RootHide: version 1.1.0 fixed an app/settings issue for packages converted with RootHide Patcher on iOS 26. That historical conversion fix is not proof of a native RootHide build or universal support.

Havoc's iOS range says where the package is designed to run; it does not say that every device on every listed firmware has a public jailbreak. Check the exact iPhone, iOS build and jailbreak environment first with the Next Jailbreak compatibility checklist.

Safe update and setup checklist

  1. Verify AADiOS as the seller, com.aadios.tethera as the package ID and 1.3.0 as the offered version in the official Havoc source.
  2. Confirm your jailbreak and package architecture. Do not infer device jailbreak support from the iOS 15.0–26.0.1 package range.
  3. If Personal Hotspot was active during installation, restart the iPhone; this is the developer's stated post-update step.
  4. Enable Ad Block deliberately—it is off by default—then test a normal website, a streaming app, a captive portal if relevant and any work VPN.
  5. Enable Recent Sites only if its 24-hour local DNS record is useful and appropriate for the people using the hotspot.
  6. Add allow rules one at a time when something breaks. Exempt a client only when its own filtering or encrypted-DNS setup is intentional.

Practical troubleshooting

A site or app stops working after Ad Block is enabled

Open Recent Sites for the affected device, look for a domain blocked at the time of failure and allow only the necessary domain. Temporarily exempting that device can confirm the filter is involved, but it should not be the first permanent fix.

Recent Sites is empty

Confirm both Ad Block and Recent Sites are enabled and that the device is actually using the iPhone hotspot. A VPN, private relay or encrypted-DNS client can also change what the iPhone can observe.

The hotspot connects but still has no internet

First verify that cellular data works on the iPhone itself. Then restart after the update if the hotspot was active during installation. The 1.3.0 fix addresses unrecognized-carrier SIMs; it does not cover every carrier restriction, roaming policy or VPN configuration.

SpringBoard or networking becomes unstable

Disable the new feature, reproduce once, and record the exact iPhone, iOS build, jailbreak, Tethera version, uplink and affected client before contacting AADiOS. If the device cannot reach a stable state, follow the bad-tweak recovery and Safe Mode guide.
