RootHide Bootstrap Main Branch Preserves Core Functions When Tweaks Are Disabled

RootHide’s latest Bootstrap source changes link the tweak-enabled state to basebin dependencies so the environment’s core functions remain available when users turn tweaks off after installing a problematic package.

By Zeeshan Barvi · Published October 15, 2026 · Verified with RootHide’s official repository and release page

Release status: this change landed on RootHide Bootstrap’s main branch on October 12, 2026. It is newer than the current 2.2.1 release and is not a new downloadable version. Regular users should not install an unofficial build that claims to contain it.

What changed on the main branch

The official commit says its goal is to keep bootstrap functionality intact when tweaks are disabled, including the recovery case after a problematic Substrate package. The patch makes three connected changes:

  • Tweak toggle: after the app writes or removes its .tweakenabled marker, it now calls setBasebinDependency(enable) with the new state.
  • Bootstrap setup: the same dependency function runs during bootstrap using the currently selected tweak state.
  • Basebin presence marker: rebuilding basebin now creates basebin/present as a link to /var/mobile/.present inside the bootstrap root.

The commit also advances RootHide’s Bootstrap-basebin submodule. That associated basebin commit changes process-spawn wrappers so a supplied PID pointer is passed through to the original spawn call instead of always being replaced by a local pointer.

Why the tweak-disabled state matters

Disabling tweak injection is a common recovery step after an incompatible package causes app crashes, a broken user interface or an unstable userspace reboot. Turning tweaks off should suppress injected tweak code without making the underlying bootstrap tools unusable.

This patch explicitly synchronizes the basebin dependency with the toggle state and again during bootstrap setup. The developer’s commit message frames the result as preserving the environment’s functionality while tweaks are disabled. It does not claim that every bad package can be repaired automatically or that disabling tweaks removes the package.

This is development work, not RootHide Bootstrap 2.2.2

The official releases page still lists version 2.2.1, published June 12, 2026, as the newest tagged build. The October 12 commit has no attached TIPA and does not assign a new version number.

Users should therefore keep the official 2.2.1 release unless RootHide publishes a newer tagged build. A file labeled 2.2.2 or “nightly” from an unrelated mirror is not validated by this commit.

Project scope and requirements remain unchanged

The current RootHide README describes Bootstrap for iOS 15.0–17.0 on A8 through A17 Pro devices and M1/M2 iPads. It also says the Bootstrap app must be installed with TrollStore and recommends TrollStore 2.0.9 or later for enabling developer mode on-device.

Those project ranges do not prove that every device and firmware combination has the same jailbreak, exploit or installation path. RootHide Bootstrap is a bootstrap environment, not a new kernel exploit. This commit does not add firmware support, extend TrollStore compatibility or turn unsupported hardware into a supported jailbreak.

For the difference between RootHide, conventional rootless and rootful setups, see the environment comparison guide. Users deciding between complete jailbreak and bootstrap options can also read Dopamine vs NathanLR vs RootHide Bootstrap.

What to do after a problematic package

  1. Open the official RootHide Bootstrap app and disable tweak injection rather than deleting bootstrap files manually.
  2. Accept the app’s userspace-reboot prompt when it is safe to do so; the source still presents a reboot requirement when the system is bootstrapped and launchctl is supported.
  3. Remove or downgrade the suspected package using the package manager while injection is disabled.
  4. Re-enable tweaks only after the environment is stable and the incompatible package is gone.
  5. If the app cannot reach its bootstrap tools, do not replace basebin files from an unofficial archive. Wait for an official release containing the fix or seek support through RootHide’s documented channels.

For app-by-app controls and the project’s default injection behavior, use the existing RootHide tweak-injection guide.

Frequently asked questions

Is RootHide Bootstrap 2.2.2 available?

No tagged 2.2.2 release was available when this article was verified. Version 2.2.1 remains the newest official release.

Does disabling tweaks uninstall them?

No. Disabling injection prevents tweak code from loading; it does not remove the installed package. Use the package manager to remove or downgrade the suspected package.

Does this commit add new iOS support?

No. The patch concerns basebin dependencies and process-spawn handling. It does not claim new firmware, device or exploit support.

Is RootHide Bootstrap itself a full jailbreak?

No. It provides a RootHide bootstrap environment and depends on a valid TrollStore installation and supported setup. It should not be treated as proof of a jailbreak for every device in the README’s broad project range.

Should I install a main-branch build?

Most users should wait for an official tagged release. Source commits are useful for tracking development but are not the same as a tested release package.
