NoSafariFormKeyboard 1.0.0 Removes Safari’s Prev, Next and Done Keyboard Buttons

Cadence has released NoSafariFormKeyboard 1.0.0, a small iOS jailbreak tweak designed to remove the Prev, Next and Done form buttons displayed above the Safari keyboard. The project also states that the change applies to Web Clips. Version 1.0.0 is an initial release, and the package metadata lists firmware version 4.0 or later as its dependency. However, the developer’s hands-on testing is limited to an iPhone 4 running iOS 6.1.3, so broader compatibility remains a possibility rather than a confirmed guarantee.

Key points

  • NoSafariFormKeyboard 1.0.0 removes Safari’s Prev, Next and Done form buttons above the keyboard.
  • The project says the tweak also applies to Web Clips and offers no configuration options.
  • The package declares a firmware dependency of version 4.0 or later and no longer declares a separate MobileSubstrate dependency in the current package stanza.
  • The developer says testing was performed only on an iPhone 4 running iOS 6.1.3.
  • The project suggests the relevant hooked files, classes and messages exist from iOS 4 through iOS 26, but explicitly presents operation on those versions as potential compatibility, not completed testing.
  • The project warns that an incompatible iOS version may prevent Safari from rendering web views and may cause Safari to crash; its stated remedy is to uninstall the tweak.

A focused change to Safari’s form keyboard

NoSafariFormKeyboard is built for a narrow annoyance: the form-navigation controls that appear above the keyboard when entering information in Safari. Its official description says the tweak removes the Prev, Next and Done buttons from that area. The repository describes the same behavior as removing the form buttons above the Safari keyboard.

The stated scope is not limited to ordinary Safari tabs. The project’s description says the tweak also applies to Web Clips, so users who launch web content through saved Home Screen web shortcuts may see the same change there. The available source does not claim that the tweak changes Safari’s underlying form behavior, modifies website code, or removes any other keyboard controls.

The developer explains that these controls could not be hidden with website code and therefore required a tweak. That makes NoSafariFormKeyboard a system-level solution to a presentation issue rather than a Safari setting or a per-site customization.

What version 1.0.0 contains

Version 1.0.0 is identified in the official package metadata as the initial package release. The package is named NoSafariFormKeyboard and uses the identifier moe.cadence.nosafariformkeyboard. The package architecture is iphoneos-arm, and the recorded installed size is 168 units, with an archive size of 2,192 bytes.

There are no user-facing settings listed for the tweak. The original description explicitly says there are no options to configure, so users should not expect a preference pane or a switch for selectively restoring the buttons. The available source also does not describe a whitelist, per-site control, alternative keyboard layout, or gesture-based replacement.

Recent repository work added a screenshot and an HTML description. It also added a depiction entry to the package metadata. These are presentation and packaging improvements rather than evidence of a new runtime feature. The release commit introduced the package release and the project’s installation instructions point users toward the official releases area because the project states that no Cydia repository is currently available.

  • Release: 1.0.0.
  • Developer: Cadence, also identified in the repository as Cadence Ember.
  • Primary behavior: remove Safari’s Prev, Next and Done form buttons above the keyboard.
  • Additional stated scope: Web Clips.
  • Configuration: none listed.

Compatibility: broad theory, narrow testing

Compatibility is the most important qualification for this release. The package metadata requires firmware version 4.0 or later. The project’s older description similarly says it was tested on iOS 6.1.3 but could theoretically work on everything above iOS 4.

The current README is more specific about the evidence behind that claim. The developer says the tweak was tested only on an iPhone 4 running iOS 6.1.3. The developer also says the hooked files, classes and messages appear to exist from iOS 4.0 and later through iOS 26, described as the latest version for which headers were available while writing. That is an observation about available interfaces, not a statement that the tweak has been tested across every listed iOS release.

For that reason, iOS 6.1.3 on an iPhone 4 is the only explicitly reported test configuration in the supplied material. Devices and versions outside that configuration should be treated as unconfirmed, even when they fall inside the project’s theoretical range. The firmware dependency also should not be read as a guarantee that every firmware version at or above 4.0 will work correctly.

The project includes a serious failure warning: if the tweak does not work with a particular iOS version, Safari may fail to render web views and then crash. The README’s stated instruction in that situation is to uninstall the tweak. Users should therefore have a recovery plan before installing, particularly when using an iOS version that is not the developer’s tested configuration.

  • Explicitly tested configuration: iPhone 4 running iOS 6.1.3.
  • Package dependency: firmware version 4.0 or later.
  • Theoretical interface range stated by the developer: iOS 4.0 through iOS 26.
  • Confirmed testing across that entire range: not stated.
  • Reported risk on an incompatible version: Safari web-view rendering failure followed by a crash.

Dependency change in the current package metadata

A recent repository commit modified the package control file. The previous dependency line listed both MobileSubstrate at version 0.9.5000 or later and firmware at version 4.0 or later. The updated line retains only the firmware requirement. The current official package stanza likewise lists Depends: firmware (>= 4.0) and does not list MobileSubstrate separately.

This is a packaging-level change, not a documented change to the tweak’s user-facing behavior. The supplied material does not explain why the separate MobileSubstrate dependency was removed, nor does it establish that every jailbreak environment provides an equivalent runtime or that the tweak is independent of all substrate-style infrastructure. Users should rely on the package manager and their jailbreak environment to resolve dependencies rather than assuming the metadata change guarantees universal injection support.

The current package also includes a depiction field, while the repository’s installation note directs users to the official release distribution rather than a Cydia repository. Readers should compare the package identity and version before installing and avoid substituting unofficial copies.

What to verify before installing

The safest pre-installation check is to compare the package details with the official project information. Confirm that the package is NoSafariFormKeyboard, version 1.0.0, with the identifier moe.cadence.nosafariformkeyboard. Check that the package manager recognizes the firmware requirement and does not report unresolved dependencies.

Next, compare the device and iOS version with the project’s evidence. The only explicit hands-on test is iPhone 4 on iOS 6.1.3. The developer’s broader iOS 4-to-iOS 26 statement is theoretical, so it should not replace device-specific validation or recovery preparation.

Finally, consider the effect of having no configuration options. Installing the tweak means accepting its global stated behavior for Safari and Web Clips; the supplied source does not describe a toggle to restore the buttons temporarily. If Safari begins failing to render web views or crashing after installation, the project instructs users to uninstall the tweak. Keep that possibility in mind before making the change.

  • Verify the package name, identifier and version.
  • Review the firmware dependency shown by the package manager.
  • Treat versions outside iOS 6.1.3 on the tested iPhone 4 as unconfirmed.
  • Remember that no configuration options are provided.
  • Use only the official release distribution identified by the project.
  • Be prepared to uninstall if Safari web views fail or Safari crashes.
