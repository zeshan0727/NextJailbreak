IconOrder 1.0.5 Adds Home Screen Layout Backup and Restore

IconOrder can already preserve a custom Home Screen arrangement after a SpringBoard crash or reboot. Version 1.0.5 turns that automatic state into something users can manage: dated backups, one-tap restore, Files import and export, and a master enable switch.

By Zeeshan BarviPublished October 22, 20267 min read
Release snapshot: Havoc lists IconOrder 1.0.5 as a free tweak released October 17, 2026 for iOS 12.0–26.0.1. A jailbreak is required and rootless support is marked Yes.

What changed in IconOrder 1.0.5

The official changelog has two entries: new backup, restore, import and export controls in Settings; and a new Enabled option that the developer recommends leaving on for general use. The public source code makes the behavior of those controls clear.

  • Create Backup copies the currently saved icon state into a dated entry. Multiple backups made on the same day receive numbered names.
  • Restore replaces the current saved layout with the selected backup, then prompts for a respring.
  • Delete removes an individual backup. The list also supports swipe-to-delete.
  • Export to Files creates an IconOrder-YYYY-MM-DD.plist copy containing the current layout and all saved backups.
  • Import from Files validates a property list, merges new backups without overwriting identical entries, and can accept either an IconOrder export or a raw IconState layout.

This is a meaningful reliability upgrade for anyone who spends time arranging folders, widgets and icons. Automatic preservation helps after an unexpected SpringBoard restart; explicit backups help when the user intentionally experiments with a different layout.

How to make and restore a layout backup

  1. Update IconOrder to 1.0.5 from its official Havoc listing.
  2. Open Settings → IconOrder and keep Enabled on.
  3. If IconOrder has not saved a layout yet, respring once. The source code requires an existing saved state before it can create a backup.
  4. Tap Create Backup. A dated item appears under Saved Backups.
  5. To restore it, tap the backup name, choose Restore, and accept the respring prompt.

Restoring affects icon placement. It is not a device backup and does not preserve app data, tweak packages, photos or jailbreak files. For broader package and preference backups, compare SetupManager and IAmLazy; IconOrder solves a narrower Home Screen problem.

Exporting to Files gives backups an off-device path

The new export control copies IconOrder’s settings file to the Files picker with a date-based filename. Because the export includes both the current layout and the saved-backup collection, it can be moved to iCloud Drive, another provider exposed in Files, or a computer without manually browsing the jailbreak filesystem.

Import performs basic structural validation before writing anything. It accepts an IconOrder export or a raw IconState property list containing recognizable icon-layout keys. When names collide, the importer creates a unique name; identical backups are skipped. If an imported current layout is present, IconOrder prompts for a respring so SpringBoard can apply it.

What the enable switch does

Version 1.0.5 adds a master switch, enabled by default. The tweak’s source reads this preference when SpringBoard loads. When disabled, IconOrder does not install its layout-preservation hooks; when re-enabled, a respring is required. The developer’s changelog says to keep it on in ordinary use.

If a restored layout appears not to apply, first confirm the switch is enabled and then respring. The Settings code specifically warns about this condition after a restore.

IconOrder versus IconState and IconSupport

IconOrder describes itself as an alternative to IconState, IconSupport and IconSupportFix. Its package metadata declares that it provides, conflicts with and replaces those layout-support packages. Do not queue IconOrder beside them: review the transaction in Sileo or Zebra and allow the package manager to remove a conflicting implementation.

The developer says IconOrder stores its state outside com.apple.springboard.plist, avoiding changes to SpringBoard’s main preference file. Tweak developers can also declare an IconOrder dependency when their layouts require persistent icon ordering.

Compatibility: package range is not jailbreak availability

Havoc lists iOS 12.0–26.0.1, requires a jailbreak and marks rootless support. Those are package claims, not a promise that every iPhone or iPad on every listed firmware can currently be jailbroken. Confirm that the exact device and firmware have a working jailbreak and compatible tweak injection first.

RootHide users should note that the Havoc listing points to a separate RootHide build on ichitaso’s repository. Use the package appropriate to the active environment; do not mix standard rootless and RootHide builds. If uncertain, identify the environment before installing with the rootless jailbreak basics guide.

Safe update checklist

  1. Take a screenshot of the current Home Screen pages and folders.
  2. Refresh the official source and confirm the queue shows IconOrder 1.0.5.
  3. Remove or avoid IconState, IconSupport and IconSupportFix conflicts.
  4. Install, respring, and verify that the Enabled switch remains on.
  5. Create one backup, move a nonessential icon, then restore and respring as a controlled test.
  6. Export the settings file to Files only after the local restore test succeeds.

The safe Sileo installation guide covers queue review and recovery. If SpringBoard enters Safe Mode, disable the most recent conflicting tweak and use the site’s KrashKop guide to capture a useful crash report.

Frequently asked questions

What is new in IconOrder 1.0.5?

Settings now includes dated backup creation, restore and deletion, Files import and export, and a new master enable switch.

Can IconOrder export more than one backup?

Yes. The source describes the exported settings file as containing the current layout and all saved backups.

Can it import an old IconState layout?

The 1.0.5 source accepts a raw IconState property list when it contains recognized icon-layout keys. Back up the current layout first and treat the import as a migration, not a universal format converter.

Does it support rootless jailbreaks?

Havoc marks rootless support as Yes. A compatible jailbreak and tweak-injection environment are still required for the exact device and firmware.

Where should RootHide users get it?

The official Havoc listing directs RootHide users to ichitaso’s repository at cydia.ichitaso.com for the environment-specific package.
