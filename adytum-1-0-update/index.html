Adytum 1.0 brings four-mode backgrounding controls to jailbroken iOS 15–17.7 devices

Kernelrw’s Adytum 1.0 is now listed as a jailbreak tweak for iPhone, iPad and iPod touch running iOS 15.0 through iOS 17.7. Its central purpose is application backgrounding management, with four selectable modes: Prevent Termination, Prevent Suspension, Fast Freeze and a combined mode. The release also includes per-app controls, profile backup and restore, action logging, purge controls, a global bypass and memory-pressure warnings. The package is an initial release and requires a jailbroken device, while its package metadata lists iOS 15.0 or newer as a dependency.

Key points

  • Adytum 1.0 is an initial release from Kernelrw focused on managing how selected apps behave after leaving the foreground.
  • The tweak provides four modes: Prevent Termination, Prevent Suspension, Fast Freeze and Combined PT+FF.
  • The Chariz listing states compatibility with iPhone, iPad and iPod touch running iOS 15.0 through iOS 17.7, with a jailbreak required.
  • Prevent Termination can increase memory pressure; the listing warns that enabling many apps may cause severe lag and repeated memory warnings.
  • Known issues are documented for Facebook version 561 and later, WhatsApp under specific protection modes, and multi-scene apps such as Safari.
  • The package depends on MobileSubstrate, PreferenceLoader, AltList and firmware 15.0 or newer, and conflicts with several similarly named immortalizer packages.

Adytum 1.0 targets a specific iOS limitation

Adytum 1.0 is presented as “true application backgrounding management” for modern jailbroken devices. Rather than offering a single keep-alive switch, the tweak lets users assign different backgrounding behaviors to individual apps. The Chariz description says those assignments can be made through 3D Touch or Haptic Touch context menus, or through the tweak’s settings page as app selections.

The release is marked as an initial release, and the listing identifies Kernelrw as the developer. The package metadata identifies the tweak as Adytum, with package identifier com.kernelrw.adytum and version 1.0. The available release information does not describe an earlier public version or a separate upgrade path, so users should treat this as the first release rather than a maintenance update.

Four backgrounding modes are the main feature

The most significant part of Adytum is its four-mode model. Each mode addresses a different point in the usual lifecycle of an iOS application, so the choice matters more than simply enabling backgrounding globally.

Prevent Termination is intended to stop iOS from closing a protected app, including under memory pressure. The developer specifically warns that applying this mode to many apps can exhaust available memory, produce severe system lag and trigger frequent memory warnings. This is the most aggressive option described in the release and should be approached with particular caution.

Prevent Suspension makes enabled apps behave as though they remain in the foreground instead of being suspended. The listing gives file transfers, downloads and music playback as examples of activities that may benefit from this behavior.

Fast Freeze immediately freezes an app when it leaves the foreground and allows it to return to the point where it was left without reloading. Adytum includes a delay slider in settings, with a 10-second period available for adjusting the Fast Freeze delay. The fourth option, Combined PT+FF, combines instant freezing with keeping the app in memory as a prevented-termination app.

  • Prevent Termination: keeps selected apps from being closed, but may increase memory pressure.
  • Prevent Suspension: keeps enabled apps behaving like foreground applications.
  • Fast Freeze: freezes an app after it leaves the foreground and aims to resume it without reloading.
  • Combined PT+FF: combines immediate freezing with prevented termination.

Settings include safeguards and recovery tools

Adytum’s supporting features are aimed at managing the consequences of per-app backgrounding. A toast notification banner reports the selected state and app name when a mode is changed from a 3D Touch or Haptic Touch context menu. This gives users an immediate indication of which protection was applied.

A Global System Bypass can exclude a targeted app from all four protection modes if that app behaves unexpectedly. The tweak also provides Profile Backup, which can export and import configurations for protected apps and their four modes. The listing specifically describes this as useful for users who frequently restore rootfs, because the profile can be restored later.

Purging lets users remove unmanaged backgrounded apps from within the settings interface so that new modes can be applied without a respring. Optional Action Logging records backgrounding events for the four modes and global bypasses. Finally, Memory Pressure Guard displays warnings in the toast banner and may scale allocations or reduce protections to preserve memory and avoid system lag.

Compatibility and package requirements

The official Chariz listing states that Adytum supports iPhone, iPad and iPod touch running iOS 15.0 through iOS 17.7. A jailbreak is required. The package stanza separately declares a firmware dependency of 15.0 or newer, which aligns with the stated minimum version but does not by itself expand the published upper bound of iOS 17.7.

The package architecture is listed as iphoneos-arm. Its declared dependencies are MobileSubstrate, firmware at version 15.0 or newer, AltList and PreferenceLoader. The package also declares conflicts with several packages whose names include Immortalizer, including com.sergy.immortalizer, com.sergy.immortalizerjailed, com.sergy.immortalizers, com.dao.immortalizer, com.evgeniy.immortalizerreborn and xyz.cypwn.immortalizer. Users should check for those installed packages before proceeding, because the package metadata explicitly marks them as conflicts.

The developer’s listing names five tested device and software combinations: iPhone 7 on iOS 15.8, iPhone X on iOS 16.6, iPhone 13 Pro on iOS 17.0, iPhone 13 Pro Max on iOS 16.3.1 and iPad Air 5 on iPadOS 17.0. These are the combinations identified by the source; they should not be interpreted as a guarantee that every jailbreak environment or device configuration will behave identically.

Known issues to review before enabling protection

The release documentation calls out several app-specific and system-behavior limitations. Facebook version 561 and later may open to a black screen the first time Prevent Termination is applied. The listing says resetting the app’s data or reinstalling it resolves that issue permanently, but those actions may have consequences for local app data and should be considered before using them.

WhatsApp can flash to a black screen in a narrower situation: when Prevent Termination or Combined PT+FF is used, the app is returning from a Prevented Termination state, and other protected apps are present in the App Switcher. The source says WhatsApp is safe with the other modes, but that does not remove the documented risk associated with these two modes.

Multi-scene apps, including Safari, may require a userspace reboot before Prevent Termination works correctly. This is an important distinction from a normal settings change: the source does not promise that selecting the mode alone will immediately produce the intended behavior for every multi-scene application.

  • Facebook 561 or newer: possible first-use black screen with Prevent Termination.
  • WhatsApp: possible black screen under the documented Prevent Termination and Combined PT+FF conditions.
  • Multi-scene apps such as Safari: a userspace reboot may be required for Prevent Termination.

What users should verify before installing

First, confirm that the device is jailbroken and falls within the published iOS 15.0–17.7 compatibility range. The release is not described as a stock-iOS utility, and the source explicitly states that a jailbreak is required.

Next, check package dependencies and conflicts. MobileSubstrate, AltList and PreferenceLoader are listed requirements, while the firmware dependency begins at iOS 15.0. The conflict list is especially relevant for users who already rely on an Immortalizer package or a similarly named rebuild; those packages should be identified before attempting an installation.

Users should also decide which apps genuinely need backgrounding and which mode fits that purpose. The developer warns about memory pressure for Prevent Termination, and the feature description says Memory Pressure Guard may degrade protections. That means selecting a protection mode is not a promise that an app will remain active indefinitely under all conditions.

Finally, read the known-issues list for the apps that matter most. Facebook, WhatsApp, Safari and other multi-scene applications may require additional recovery steps or reboot behavior. The release page provides support contact information for Kernelrw and asks users reporting problems to include error messages and as much detail as possible.

A note about the similarly named Adytum repository

The supplied official repository metadata for a project named Adytum describes a cryptic online puzzle game, not the iOS backgrounding tweak. Its README discusses rooms, questions, keys, codes, PHP, MySQL, AJAX and leaderboards, while its most recent listed commits concern hosting, login redirects, session data and navigation. The repository metadata also identifies the project description as “Web Tech Project.”

That material does not document the jailbreak tweak’s implementation, compatibility or release behavior. For Adytum 1.0 users, the relevant release information is the package and Chariz listing: those sources identify the tweak as a backgrounding manager, document its modes and known issues, and provide the published device and iOS compatibility range.

Frequently asked questions

What is Adytum 1.0?

Adytum 1.0 is a jailbreak tweak from Kernelrw for managing the backgrounding behavior of selected iOS applications. It offers four modes: Prevent Termination, Prevent Suspension, Fast Freeze and Combined PT+FF.

Which iOS versions does Adytum support?

The Chariz listing states support for iPhone, iPad and iPod touch running iOS 15.0 through iOS 17.7. A jailbreak is required.

Does Adytum work on stock iOS?

No stock-iOS support is documented. The official listing explicitly says that a jailbreak is required.

What is the difference between Prevent Termination and Prevent Suspension?

Prevent Termination is described as preventing protected apps from being closed, even under memory pressure. Prevent Suspension makes enabled apps behave as though they remain in the foreground and are never suspended.

Can Adytum cause memory problems?

Yes. The developer warns that enabling Prevent Termination for many apps may cause the device to run out of memory, resulting in severe system lag and frequent memory warnings. Adytum also includes a Memory Pressure Guard that can warn users and scale back protections.
