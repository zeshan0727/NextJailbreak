Eagle 1.0.5 Refines DarkSword Island and Dock Personalization

Eagle 1.0.5 build 92 is the current official release of the open-source personalization app. It refreshes the Island and Dock galleries, adds quarter-point positioning, improves result messages and tightens operation-lifetime checks—while keeping its device and firmware limits explicit.

By Zeeshan Barvi · Published October 6, 2026 · Eagle 1.0.5 was released September 26, 2026

Important: Eagle is a sideloaded personalization utility, not a jailbreak, and its private operations are not universal. The developer warns that incompatible operations can respring or reboot a device. Back up first, follow Eagle’s own compatibility screen and test one change at a time.

What changed in Eagle 1.0.5

The developer’s September 26 release notes call 1.0.5 a stable update to 1.0.4. The visible focus is the Dynamic Island and Dock experience, but the release also changes navigation, progress feedback and safety handling.

  • Island and Dock Galleries: clearer Live, Static and Saves controls, smoother focused previews and quarter-point artwork positioning.
  • Aura Studio: new Island and Dock position controls without replacing the existing apply engine.
  • Navigation and feedback: a native translucent Access/Customize bar and result notices that no longer push content down; a later result replaces the previous notice.
  • Prepare: the rainbow progress animation remains, with a green action button and a smoother transition to Ready.
  • Settings: general Settings and Laboratory Tools now have distinct roles, and the Updates screen reflects the 1.0.5 work.
  • Legibility and gallery cleanup: light action buttons use dark text. Duck Mood, Blue Screen and Walking Flame were removed from Island Gallery only and remain in Dock Gallery.
  • Safety checks: gallery media and operation-lifetime checks were tightened without changing the documented Prepare, theme Apply, Hide Dock or Aura paths.

What Eagle can personalize

Eagle combines several private-system customization surfaces in one SwiftUI app: wallpapers, supported Wallet card artwork, passcode themes, Home Screen elements, Dynamic Island and Dock lighting, Island and Dock gallery artwork, and per-page app-name color. Icon Studio is still marked coming soon; users should not interpret its place in the interface as a finished icon-theming feature.

The app is a modified descendant of Lara and credits DarkSword for private system access. That relationship does not make Eagle a Dopamine extension or a jailbreak. For the distinction, see our DarkSword and Dopamine explainer and the broader iOS 27 jailbreak status.

The most important distinction is that passing Prepare does not prove that every gallery, Aura or Home Screen operation is verified on that device. Eagle’s README says other supported models may still need model-specific validation, and it intentionally blocks operations when its safety conditions are not met.

Download and verify the official IPA

Eagle’s release IPA is unsigned. Download it only from the project’s official GitHub release and sign it with a personal-device installation method you already trust. The official 1.0.5 asset is Eagle-1.0.5-92.ipa, 18,327,350 bytes, with this GitHub-published SHA-256 digest:

82e90b50cc43e15284ecb47eed9deec862f912d7571136571da32ecfa12cacf9

  1. Back up important data and record the exact device model, iOS version and build.
  2. Download the unsigned IPA from the official release page.
  3. Sign and install it using your usual sideloading method.
  4. If installation was performed through Xcode, stop the Xcode session before running Prepare; Eagle blocks kernel or SpringBoard operations while the debugger is attached.
  5. Read Eagle’s compatibility screen, then test one modification at a time and keep the exact result message if an operation fails.

Bottom line

Eagle 1.0.5 is a meaningful polish and safety update for users already inside the project’s supported matrix. The redesigned galleries and precise positioning make the customization workflow more coherent, but the current release still depends on private system behavior and model-specific validation. It should be treated as an experimental personalization tool—not evidence of a new jailbreak or broad iOS 26 support.
