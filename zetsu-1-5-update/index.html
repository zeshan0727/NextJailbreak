Zetsu 1.6.6 Fixes Window-Mode Flicker on Newer iOS Versions

The latest Chariz depiction for Zetsu lists version 1.6.6 and describes a focused bug fix: an issue that could cause an app’s view to flicker momentarily when launching in Window mode. The note identifies iOS 18 through iOS 26 as affected operating-system versions. Zetsu remains a jailbreak-required multitasking tweak offering Window mode, Split View, app scaling, landscape rotation, Control Center controls, and background camera-app support. However, the supplied repository package stanza still identifies version 1.5 and declares a firmware minimum of iOS 15.0, so users should confirm that their package manager is presenting the same release as the current Chariz depiction before installing.

Key points

  • Chariz’s current version history lists Zetsu 1.6.6.
  • The documented change is a fix for momentary view flickering when an app launches in Window mode.
  • The release note specifically mentions iOS 18 through iOS 26.
  • The Chariz compatibility text lists iOS 15.0 through iOS 26.0 on iPhone, iPad, and iPod touch, with a jailbreak required.
  • The supplied package stanza identifies version 1.5 and depends on MobileSubstrate, PreferenceLoader, libjailbreak-related CC support, and firmware 15.0 or newer; verify the package version and dependencies shown by your own repository client.

What changed in Zetsu 1.6.6

Zetsu’s Chariz depiction lists version 1.6.6 as a new release and gives it a narrowly targeted change: “Fixed an issue where the app’s view would flicker momentarily when launching in Window mode.” The release note associates that issue with iOS 18 through iOS 26.

This is a presentation and stability fix rather than a newly announced multitasking mode. The source does not describe changes to Window mode controls, Split View behavior, scaling options, or the tweak’s external notification interface in this version. Users who already rely on Zetsu’s Window mode should therefore view 1.6.6 primarily as a corrective update for launch-time visual flicker.

  • Release: Zetsu 1.6.6.
  • Reported fix: momentary app-view flicker during Window-mode launch.
  • Operating-system range named in the change note: iOS 18–iOS 26.
  • Released by: Dcsyhi.

Why the fix matters

Window mode is one of Zetsu’s central features: the tweak can turn an app into a windowed interface instead of leaving it in a conventional full-screen presentation. A brief flicker at launch may not prevent an app from opening, but it can make the transition look broken or reduce confidence that the window has initialized correctly.

The documented fix is particularly relevant to users on the newer operating-system versions explicitly named in the changelog. The source does not quantify how long the flicker lasted, identify every affected device, or claim that all visual issues have been eliminated. Those details should not be inferred from the one-line release note.

  • The update addresses the launch transition into Window mode.
  • The source does not claim broader performance improvements.
  • No new feature is listed in the 1.6.6 changelog entry.

Zetsu’s multitasking feature set

According to the official Chariz description, Zetsu supports two primary multitasking layouts: Window mode and Split View. It also supports horizontal screen rotation in both modes. The feature list includes app selection for scaling in Window mode and an option controlling the keyboard’s display position, although the developer notes that scaling does not apply to some applications.

Zetsu also exposes controls through Control Center, where users can select an application window to show or hide. The app switcher can launch Window mode or Split View mode, and the feature list includes permission for the camera app to operate in the background. These are the capabilities documented for the tweak generally, not changes newly introduced by 1.6.6.

  • Window mode for app multitasking.
  • Split View support.
  • Horizontal rotation in Window and Split View modes.
  • Window scaling with application selection.
  • Keyboard display-position control.
  • Control Center show and hide controls for application windows under the tweak’s model of operation.

Compatibility: read the source details carefully

The current Chariz depiction states that Zetsu supports iPhone, iPad, and iPod touch running iOS 15.0 through iOS 26.0, and it clearly marks the package as requiring a jailbreak. The older compatibility information in the same depiction describes iOS 15–16.7 and arm64 and arm64e, alongside two listed test devices: an iPhone Xs on iOS 15.0 using Dopamine and an iPhone 14 Pro Max on iOS 16.0 using Dopamine.

There is an important version discrepancy in the supplied source material. The official repository package stanza identifies the package as version 1.5, with architecture iphoneos-arm and a firmware dependency of 15.0 or newer. Meanwhile, the Chariz page and its depiction data list version 1.6.6 and the newer iOS 15.0–26.0 compatibility text. The material provided does not include a separate 1.6.6 package stanza or checksum, so readers should not assume that the version 1.5 metadata describes the exact binary represented by the 1.6.6 page.

Before installing, check the version displayed by the repository client, the package architecture, the declared firmware requirement, and the dependency list. The supplied stanza names MobileSubstrate, PreferenceLoader, and com.opa334.ccsupport as dependencies. It also identifies iphoneos-arm as the package architecture. A package manager may resolve dependencies automatically, but the source material does not guarantee that every jailbreak environment will meet them.

  • Chariz listing: iOS 15.0–26.0; jailbreak required.
  • Older detailed compatibility note: iOS 15–16.7; arm64 and arm64e.
  • Package stanza supplied: version 1.5, iphoneos-arm, firmware 15.0 or newer.
  • The supplied sources do not provide a separate 1.6.6 package manifest or checksum.

Developer-facing integration

Zetsu documents notification-based integration for external tweaks. Window mode can be requested with the ZetsuSwitcher notification and an application bundle identifier. Split View can be requested with ZetsuSplitSwitcher, with position values documented for the upper position, lower position, and automatic placement.

Those interfaces are useful to developers building launch or multitasking controls around Zetsu, but the 1.6.6 release note does not say that the notification names or position values changed. Existing integrations should therefore be checked against the current package and the developer’s documentation rather than assuming an API change.

  • Window-mode notification name: ZetsuSwitcher.
  • Split View notification name: ZetsuSplitSwitcher.
  • The documentation provides upper, lower, and automatic position values.
  • No API change is announced for 1.6.6.

What to verify before installing

The safest installation decision depends on matching the package shown in the package manager with the release information on the official Chariz depiction. In particular, users should confirm whether their client offers 1.6.6 or the older 1.5 package metadata supplied here. They should also review the listed dependencies and ensure their device is already in a supported jailbroken state.

Compatibility statements can evolve independently from an older package stanza. The current depiction’s broad iOS 15.0–26.0 range is not accompanied in the supplied material by device-by-device testing for every operating-system version. The explicitly named tested examples are limited to the iPhone Xs on iOS 15.0 and iPhone 14 Pro Max on iOS 16.0 using Dopamine.

  • Confirm the displayed package version before proceeding.
  • Check that the device and operating system fall within the current depiction’s stated range.
  • Review dependency availability, especially MobileSubstrate, PreferenceLoader, and com.opa334.ccsupport.
  • Keep in mind that jailbreak access is required.
  • For problems, use the developer’s stated support route and include error details, as requested on the package page.
