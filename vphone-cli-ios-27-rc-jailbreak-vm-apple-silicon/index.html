vphone-cli 2.8.0 Adds Host Location Sync and Restores Xcode Installs on iOS 27

The open-source vphone-cli project released version 2.8.0 on October 8 with per-machine host-location sync, an iOS 27 locationd recovery path, repaired Xcode app installation and better package registration inside virtual guests. It remains a virtual-iPhone research platform for Apple Silicon Macs—not a jailbreak for physical iPhones.

What vphone-cli 2.8.0 changes

Developer Lakr Aream published vphone-cli 2.8.0 on October 8, 2026, one day after 2.7.0. The new release concentrates on location behavior, Xcode and CoreDevice integration, package-installed apps and Launchpad maintenance. The 2.7.0 snapshot, independent-clone and DeviceHub features remain part of the current 2.8-series bundle.

These changes matter to jailbreak and security researchers working with patched virtual guests. They do not add a physical-device exploit, and they do not make iOS 27 jailbreakable on an iPhone.

Host location sync is now a per-machine option

Version 2.8.0 adds vm config <name> --sync-host-location on|off. The same switch appears under Location › Sync Host Location in the VM window and in Launchpad. It is disabled by default, and a headless launch shares the Mac’s location only when that specific virtual machine has opted in.

If Location Services is disabled inside the guest, the VM window now explains the problem once instead of failing silently. The project also says machines using different Core Bundles can sync concurrently.

iOS 27 location hangs and DeviceHub GPU deadlocks are fixed

The guest daemon now restarts locationd when it deadlocks during startup on iOS 27.0—a failure that previously left Maps and every other location request waiting indefinitely. This is a recovery fix for the virtual guest, not a change to location services on a physical iPhone.

The release also fixes a host-GPU deadlock triggered when a DeviceHub stream split frames into bands. That follows 2.7.0’s initial Xcode 27 DeviceHub screen-streaming support and directly addresses a stability fault in that workflow.

Xcode can install apps on iOS 27 guests again

A new standard patch named system-installcoordination_proxy-cfw-persona_lookup allows only the CoreDevice installation proxy to look up UserManager. According to the official changelog, this restores Xcode app installation on iOS 27 guests.

The guest’s device name now follows the VM name, so Xcode, devicectl and Finder display the same identity. Renaming a VM applies on its next connection; a name that cannot be used as a device name leaves the guest’s current name unchanged.

Package-installed apps now register on iOS 27

Apps installed by a package through Irisin, APT or dpkg are now registered on iOS 27, where the traditional uicache path is unavailable. vphone-cli builds the same registration record for both initial registration and refresh.

While a bootstrap is installed, spawned processes receive three times their normal jetsam memory limit. The release also adds libsigninfix and libprefsfix for signed-out guests: the first makes Apple Account, iCloud, store and Game Center sign-in sheets inert, while the second hides follow-up suggestion groups in Settings.

Launchpad 2.8.0 improves concurrent maintenance

  • CFW installation and updates can run on different machines at the same time, while each machine still allows only one operation.
  • Cancelling an operation now stops only the selected machine’s job.
  • A machine can be deleted even if its own Core Bundle is missing or belongs to another series.
  • File › Downloaded IPSWs… lists cached IPSWs, shows which machines use them and removes files that no unfinished creation needs.
  • iPad guests are labeled as iPadOS in the machine table and inspector.

Snapshots and independent clones remain available

The 2.7.0 release introduced vm snapshot create|list|revert|delete for stopped machines, covering the disk, Secure Enclave storage and NVRAM as APFS clones. It also added vm clone --new-identity so a clone can receive its own ECID, UDID and MAC address and run beside the source.

Those workflows remain useful in 2.8.0 for returning a research guest to a known state or duplicating a setup without inheriting conflicting network identity. Snapshots still do not include VM settings or device identity.

Keep Launchpad and VPhone.bundle on 2.8.x

The developer requires Launchpad 2.8.0 with VPhone.bundle 2.8.x because the machine settings now call the new location-sync configuration command. The documented upgrade path is to install vphone-launchpad-2.8.0-notarized.zip, install Core Bundle 2.8.0, then move existing machines with Change Core Bundle….

Enable Update guest environment to receive the device-name behavior, locationd restart, banded-stream fix, package-app registration and iOS 27 Xcode-install fix. The separately listed CI build is unsigned.

Requirements and jailbreak limits

  • Host: a physical Apple Silicon Mac running macOS 15 or later; the project says it does not work inside a macOS VM.
  • Host setup: free disk space, network access for signing tickets and the project’s documented macOS Recovery security adjustment are required.
  • Guest: a virtual iPhone or iPad created through vphone-cli’s research workflow; guest support does not establish support on physical hardware.
  • Jailbreak mode: the project documents a patched jb guest variant with Sileo and TrollStore, but it exists inside the VM.
  • Physical iPhones: version 2.8.0 does not announce a kernel exploit, sandbox escape or public iOS 27 jailbreak for consumer devices.

For physical-device availability, use the separate iOS 27 jailbreak status report. Readers comparing current device-side tools can also consult Dopamine 3 versus palera1n 3.

Bottom line

vphone-cli 2.8.0 is a focused follow-up that makes its virtual iPhone lab more practical: location can be shared deliberately per VM, iOS 27 location failures recover, Xcode installation works again and package-installed apps register correctly. The project’s scope is unchanged—it is a Mac-hosted virtual research environment, not a physical-iPhone jailbreak.
