vphone-cli 2.12.0 Adds Apple Watch Guests and iOS 18/26 Research Boards

The 2.12 release expands vphone’s Mac-hosted research lab with a documented Apple Watch guest, iOS 18 and iOS 26 research-board paths, peer communication on NAT networks and tighter safeguards around privileged firmware work. It is a virtual-machine platform, not a jailbreak for retail hardware.

What changed in vphone-cli 2.12.0

Lakr Aream published vphone-cli 2.12.0 on October 23, 2026 at 05:08 UTC. The release merges the project’s Minimal preset, research-board boot work, Apple Watch support and iOS 18/26 contribution stack into the stable Core Bundle and Launchpad line.

The scope is important: vphone-cli runs Apple operating-system research guests through virtualization on a physical Apple Silicon Mac. It can patch a guest and provide a package environment inside that VM, but it does not exploit or jailbreak a physical iPhone, iPad or Apple Watch.

Apple Watch guests can pair with a virtual iPhone

Version 2.12 adds an Apple Watch guest identified as Watch7,18 on watchOS 26.4. The tagged compatibility table records a restore, boot and vphoned ping for build 23T240 using the new watchos preset.

The project’s pairing note documents a successful initial sync with a virtual iPhone17,3 on iOS 26.4 build 23E246. Both guests used cloudOS 26.4 build 23E244 on the NAT network, with peer reachability enabled. Pairing takes place through the phone’s Watch app; the developer notes that no Bluetooth hardware is involved because the virtual-machine builds provide the required plumbing.

This is a research configuration, not general watchOS virtualization for arbitrary devices or versions. The release’s validation note explicitly says the new Apple Watch path was not rerun across a complete firmware matrix on the build machine.

Research-board support reaches iOS 18 and iOS 26

vphone-cli previously relied heavily on cloudOS images containing the project’s expected vphone600 components. The 2.12 stack adds research-board boot chains for releases where those components are absent, and introduces a minimal preset that can restore a guest without the full standard customization set.

The tagged matrix documents iOS 26 research-board guests for iPhone17,3 on iOS 26.4, 26.5 and 26.6. It also lists iPhone11,6 test paths for iOS 18.1, 18.5 and 18.7.2 using the Minimal preset. Those iOS 18 paths rebuild a kernelcache with virtualization kexts and may require a suitable IPSW plus a macOS builder for kmutil; they are not one-click compatibility claims for every host and firmware pair.

Researchers should follow the project’s exact compatibility table and creation guide. A package manager appearing inside one supported guest does not expand Dopamine, palera1n, TrollStore or RootHide support on physical devices. For real hardware, see the Dopamine versus palera1n comparison and iOS 27 jailbreak status.

NAT guests can reach one another

The NAT backend now lets virtual guests communicate with peers on the same host. That change is what enables the documented virtual iPhone and Apple Watch pairing flow. Administrators can apply per-machine isolation controls, and the release corrects fixed-address reporting. If the host lacks the required isolation API, vphone-cli is designed to fail safely instead of silently weakening the requested boundary.

Privileged firmware work is more tightly contained

The release keeps privileged firmware operations inside private workspaces, rejects untrusted native patch-set code when running as root, and confines kernel-cache access and guest-filesystem writes. These are hardening changes around the build and patch pipeline; they do not turn research firmware into production-trusted software.

Version 2.12 also fixes SSH transfers that could hang while sending input and collecting error output—relevant to the remote macOS builder path used by some iOS 18 kernelcache workflows.

Upgrade rules for the 2.12 series

  • Match major-minor versions: use Launchpad 2.12.x with VPhone.bundle 2.12.x.
  • Choose the notarized archive: the official release provides vphone-launchpad-2.12.0-notarized.zip, signed with Developer ID, notarized and stapled by Apple.
  • Install the new Core Bundle: replace Launchpad, then install Core Bundle 2.12.0 from inside the app.
  • Existing machines do not change automatically: installing a new default bundle leaves each VM’s current bundle binding and guest components untouched. Update machines individually when ready.
  • Helper build 20 may prompt: updating the helper can request administrator authorization.
  • Core Bundle trust differs: the bundle retains the project’s ad hoc signatures and private-entitlement admission flow even though Launchpad itself is notarized.

What the developer validated

The merged release commit passed CI plus 812 related CoreKit, ArchiveKit and firmware tests, Launchpad regression checks and all five native guest-component test groups. Packaging also verifies release builds, bundle admission, code signatures and architectures.

That is strong automated coverage, but the developer states that the build machine lacked the reference images needed for complete firmware and guest-boot coverage. Treat the new research-board and Apple Watch routes as documented research features, and keep a recoverable copy of important VM data before changing bundles or guest environments.

Bottom line

vphone-cli 2.12.0 is a substantial platform update: it broadens the firmware research matrix to iOS 18 and newer iOS 26 paths, adds an Apple Watch guest that can pair with a virtual iPhone, and strengthens the boundaries around privileged firmware tooling. None of those additions constitutes a jailbreak for a physical Apple device.
