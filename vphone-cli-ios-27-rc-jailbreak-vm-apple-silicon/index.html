vphone 2.16.1 Update: Safe Upgrade, SHA-256 and Guest Fixes

vphone 2.16.1 fixes virtual-device rotation behavior, GLES depth rendering and an iOS 26 TXM app-launch failure, while improving automation metadata. Existing machines need a guest-environment update to receive those changes; installing the Mac bundle alone is not enough.

By Zeeshan Barvi · Originally published September 15, 2026 · Updated November 14, 2026 · Current version verified: 2.16.1

Verified release: vphone 2.16.1, published November 10, 2026 at 17:53:41 UTC. The official release provides a Core Bundle and an unnotarized Launchpad ZIP; their locally calculated SHA-256 values are listed below.
This is not a physical-device jailbreak. vphone runs patched research guests on a physical Apple Silicon Mac. A RootHide or rootless environment inside a VM does not prove that the same iOS version or hardware can be jailbroken on a retail iPhone.

What changed in vphone 2.16.1

  • Rotation state: a refused display.rotation request no longer snaps the device back. The virtual device keeps the requested pose and the interface follows when the app, Rotation Lock or sleeping display allows it. display.orientation now reports device_degrees.
  • GLES depth rendering: dyld-cfw-gles_depth_clip keeps negative clip-space geometry visible and prevents farther geometry from appearing through nearer geometry. Unsupported layouts are refused; TV-family presets leave it off.
  • TXM app launching: an app whose executable retains an Apple Development signature no longer fails with NSPOSIXErrorDomain 85 when the trust-cache bypass skips profile association. The project checked cloudOS 26.1–26.4 TXM images.
  • Automation metadata: display.metrics no longer needs interface orientation, display.layout returns Boolean monitor flags, and methods.list documents methods and parameters.
  • Shared-module builds: Linux builds import CoreFoundation where needed and avoid a Swift optimizer crash in GLES context matching.

The bundled vphoned uses icli 1.0.0, but the release says its new passcode-unlock and InterfaceGeometry APIs are not used yet. Those capabilities should not be attributed to vphone 2.16.1.

Safe upgrade from 2.15.x

  1. Stop every important VM and create a snapshot, clone or export.
  2. Download both official 2.16.1 ZIPs and compare their SHA-256 values with the table.
  3. Keep the 2.15 bundle until one test machine boots, stops and answers the control API on 2.16.1.
  4. Install Launchpad 2.16.1 and the 2.16.1 Core Bundle as one series.
  5. Bind one stopped test VM to the 2.16.1 bundle.
  6. Run cfw update-environment, or choose Update Guest Environment in Launchpad.
  7. Test rotation, one GLES workload and an Apple Development-signed app if those fixes matter.
  8. Retain the older bundle until all machines pass their normal checks.

The release says 2.16.1 was not regression-tested on guests as a whole. Individual changes were tested by their authors. Upgrade one guest first rather than treating the patch number as universal stability proof.

Verify the guest environment updated

  • methods.list should return self-describing method and parameter information.
  • display.layout should report monitor flags as Booleans instead of numeric values.
  • display.orientation should include device_degrees.
  • A rotation requested while the screen is off or Rotation Lock is active should preserve the device pose while the VM window waits for the guest interface.

Troubleshooting vphone 2.16.1

Launchpad is blocked by macOS

The official 2.16.1 Launchpad is not notarized. Confirm the full ZIP hash is c3a3d6266426288ebf9c3d893d00d23294dc658a27eb99ae4c89a924102d0c59, then use the documented Open Anyway route. Do not weaken host protections for an unverified copy.

Apps still fail with NSPOSIXErrorDomain 85

Confirm the VM is bound to 2.16.x and the guest environment—not only Launchpad—was updated. The TXM fix was checked against cloudOS 26.1–26.4; the release does not promise every signature layout works.

The VM window does not rotate immediately

This can be expected. The device preserves the requested pose while the guest interface waits for the foreground app, Rotation Lock or screen state to permit rotation.

GLES depth is still wrong

Update the guest environment and confirm the layout accepts dyld-cfw-gles_depth_clip. The patch refuses unsupported layouts and is disabled for TV presets.

Launchpad says the bundle is too old

Launchpad 2.16 requires bundle 2.16.0 or later. Install the 2.16.1 Core Bundle instead of combining the new UI with 2.15.x.

Frequently asked questions

Is vphone 2.16.1 a physical iPhone jailbreak?

No. It runs patched research guests on an Apple Silicon Mac.

Is Launchpad 2.16.1 notarized?

No. The official release says the CI-built ZIP is not notarized.

Can Launchpad 2.16 use a 2.15 bundle?

No. Its minimum bundle is 2.16.0.

Does installing the bundle update an existing guest?

Not fully. Run cfw update-environment or Update Guest Environment.
