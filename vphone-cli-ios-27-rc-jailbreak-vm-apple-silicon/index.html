vphone 2.17.1 Fixes iPad Pointer Rotation and Accessibility App Crashes

vphone 2.17.1 corrects iPad pointer behavior after display rotation and fixes startup faults in 35 accessibility plug-ins on hosts without FEAT_PAuth_LR. Existing machines can receive the patch without a restore, but they must update the guest environment.

By Zeeshan Barvi · Originally published September 15, 2026 · Updated November 16, 2026 · Current released version verified: 2.17.1

Verified release: vphone 2.17.1 was published November 13, 2026 at 09:01 UTC from commit 1316940. It is a patch on top of 2.17.0, released earlier the same day.
This is not a physical-device jailbreak. vphone runs patched research guests on a physical Apple Silicon Mac. Guest support for iOS 27, RootHide or injected code does not establish jailbreak availability for a retail iPhone or iPad.

What vphone 2.17.1 fixes

  • iPad pointer after rotation: the framebuffer now remains panel-native. The project says this restores correct pointer operation when an iPad guest is used in landscape.
  • Accessibility startup faults: the remaining 35 standalone accessibility plug-ins now receive ARM64E_X1 lowering. This targets hosts without FEAT_PAuth_LR, where enabling accessibility could previously fault at startup.
  • Read-only audit: vphone-cli cfw audit-arm64e-x1 <volume-root> checks a prepared volume for affected instructions. It supports --json for automation and --strict for a non-zero result when findings remain.
  • No restore required: the release directs existing-machine users to run vphone-cli cfw update-environment.

Launchpad 2.17 and VPhone.bundle 2.17.x remain interchangeable. The minimum bundle stays at 2.16.0, so Launchpad can still control a 2.16.x bundle; however, the new guest-side fixes require the updated environment.

Safe update from vphone 2.16.x or 2.17.0

  1. Stop important VMs and create a snapshot, clone or export.
  2. Download only from the official vphone 2.17.1 release.
  3. Keep the previous bundle until one stopped test machine boots and answers the control API.
  4. Install Launchpad 2.17 and bind that machine to the intended 2.17.x bundle.
  5. Run vphone-cli cfw update-environment; the release says a restore is unnecessary.
  6. If accessibility is enabled, run vphone-cli cfw audit-arm64e-x1 <volume-root> --strict.
  7. Test iPad pointer movement in portrait and landscape, then the accessibility workflow that previously failed.
  8. Retain the prior snapshot and bundle until required guests pass their normal checks.

Troubleshooting vphone 2.17.1

The pointer is still offset after rotating an iPad guest

Confirm both the bound bundle and guest environment are on 2.17.1. Updating Launchpad alone does not replace guest components. Re-run cfw update-environment, then cold-start the test VM.

Accessibility still crashes at startup

Run the read-only ARM64E_X1 audit against the prepared volume. Use --json for a machine-readable report and --strict when a remaining finding should fail automation. A clean audit does not prove unrelated plug-ins are compatible.

An injected app still fails admission on iOS 27

The 2.17.0 option is txm-exp-precheck_admission. It is selectable, not a blanket default, and mutually exclusive with the remap alternative. Check the machine configuration before blaming ElleKit or RootHide.

Launchpad 2.17 accepts a 2.16 bundle, so why are fixes missing?

That pairing is supported for control compatibility. It does not backport the 2.17.1 guest environment. Bind the correct bundle and update the environment.

Newer main-branch work is not part of 2.17.1

Three changes merged after the tag: dynamic kmutil download in PR #930, minimal iOS 27.2 support in PR #931, and trusted darwinOS/Cryptex handling in PR #932. They are useful development signals, but they are not 2.17.1 release features or a newer stable release.

Frequently asked questions

Is vphone 2.17.1 a physical iPhone jailbreak?

No. It runs patched research guests on a physical Apple Silicon Mac.

Does the patch require restoring the VM?

No. The release says to update the existing guest environment.

Can Launchpad 2.17 control a 2.16 bundle?

Yes. Its minimum remains 2.16.0, but 2.17.1 guest fixes are not backported.

Is merged iOS 27.2 work included in 2.17.1?

No. It landed after the tag and remains unreleased main-branch development.
