vphone-cli 2.12.1 Fixes macOS 26 Hosts and Research-Board Booting

The Core Bundle update removes several blockers found after 2.12.0: it validates every supported guest family on macOS 26.6.2, repairs iOS 18 and watchOS restore paths, makes research-board kernelcache preparation self-contained and prevents unsupported macOS 27-only OTAs from downloading on older hosts.

What changed in vphone-cli 2.12.1

Lakr Aream published vphone-cli 2.12.1 on October 23, 2026 at 20:09 UTC, only hours after 2.12.0. This is a Core Bundle update. Launchpad itself is unchanged.

The release focuses on firmware preparation and host compatibility. It does not add a physical-device exploit: vphone-cli remains a virtualization research platform for a physical Apple Silicon Mac, and its patched guests do not establish jailbreak availability for retail iPhones, iPads, Apple Watches, Apple TVs or HomePods.

Research-board kernelcache preparation is now native

The research-board flow now extracts its kernelcache mix natively. The developer says fw kernelcache no longer needs an IPSW built from unmerged branches. Existing --ipsw and VPHONE_IPSW inputs are accepted for compatibility but ignored by this path.

The update also handles mixes linked by the kmutil included with macOS 27. Those outputs retain authentication stubs; 2.12.1 branches past them so the research-board guest can boot. The developer did not have a macOS 27 host in the validation run, so that specific link path is implemented but was not rechecked in the published matrix.

Every listed guest family was created on macOS 26.6.2

The official validation used Mac mini M4 hosts running macOS 26.6.2 build 25G83. Each listed machine was created from scratch with Core Bundle 2.12.1 and booted twice headlessly. The acceptance checks required vphoned to answer, device.info to report the expected release and the serial log to show no guest panic.

The tested set included default pairings for iPhone17,3, iPhone18,2, iPad16,1, iPhone11,6 on iOS 18.7.2, Watch7,18, Apple TV HD, Apple TV 4K and AudioAccessory5,1. The developer also exercised iOS 26.4, 26.5 and 26.6.2 research-board pairings, plus iOS 18.6, 18.7 and other documented combinations.

This is a concrete validation matrix, not a promise that every firmware and cloudOS pairing will work. Follow the tagged compatibility table rather than substituting arbitrary images.

iOS 18 and watchOS restore fixes

  • Minimal and watchOS images: the mount point is now created before diskutil image attach, and a system-image container that already fills its file is grown before sealing.
  • IPSW cache ownership: the research-board flow no longer stops with “Operation not permitted” when an earlier sudo run created the cache.
  • iOS 18.7 and 18.7.2 restores: partial socket writes are completed instead of corrupting the ASR stream and ending with “Unable to send data to ASR.”
  • Template setup boots: the service profile is applied again when launchd refuses an early-boot change.

These fixes address VM creation and restore failures. They do not change which physical devices Dopamine, palera1n, TrollStore or RootHide support. Readers comparing real jailbreaks should use the Dopamine versus palera1n guide.

tvOS 27 and HomePod Software 27.2 require macOS 27

The project now makes this host boundary explicit. The tvOS 27.0 and HomePod Software 27.2 OTA payloads use LZRAVEN compression, which vphone-cli says only macOS 27 can unpack.

On macOS 26 or earlier, fw catalog omits those choices. Launchpad therefore offers tvOS 26.6 for the Apple TV 4K path and HomePod Software 27.0 for AudioAccessory5,1. If a user manually names one of the unsupported 27.x OTAs, vphone-cli refuses it before downloading anything.

The release validation did not include a macOS 27 host, so neither LZRAVEN OTA was retested there. The iOS 26.7 research-board recipe also remains incomplete: no corresponding iPhone release was available to boot, and the developer records one missing custom-firmware kernel patch site.

Use Core Bundle 2.12.1 with the notarized Launchpad 2.12.0

Launchpad did not change. The recommended upgrade is:

  1. Keep or install vphone-launchpad-2.12.0-notarized.zip.
  2. Open Launchpad’s Core Bundle page and install VPhone.bundle 2.12.1.
  3. Move existing machines to the new bundle individually when ready; installing the default bundle does not silently change their bindings.

The release also publishes vphone-launchpad-2.12.1.zip, but the developer identifies it as an unsigned CI build of unchanged Launchpad 2.12.0. It is not a newer notarized app. Download only from the official release page and preserve recoverable VM data before changing a machine’s bundle or guest environment.

Bottom line

vphone-cli 2.12.1 is the correct version for researchers who adopted 2.12.0. It turns the earlier feature expansion into a more reproducible macOS 26.6.2 workflow, fixes several restore failures and clearly blocks guest images that need macOS 27. Its results apply to Mac-hosted virtual machines—not physical-device jailbreak support.
