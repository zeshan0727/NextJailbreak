vphone-cli 2.7.0 Adds VM Snapshots and Xcode DeviceHub Streaming

The open-source vphone-cli project released version 2.7.0 on October 7 with APFS-backed snapshots, clones that can receive independent device identities, and live guest-screen viewing in Xcode 27 DeviceHub. It remains a virtual-iPhone research platform for Apple Silicon Macs—not a jailbreak for physical iPhones.

What vphone-cli 2.7.0 changes

Developer Lakr Aream published vphone-cli 2.7.0 on October 7, 2026. The release focuses on safer VM experimentation and a more useful Xcode workflow: stopped machines can be snapshotted and restored, clones can receive distinct device identities, and Xcode 27 DeviceHub can display a guest’s live screen on supported iOS and iPadOS versions.

These changes are relevant to jailbreak and security research because vphone-cli can run patched guest firmware and a package environment inside Apple’s virtualization stack. The boundary is important: the release contains no physical-device exploit, and it does not make iOS 27 jailbreakable on an iPhone.

Snapshots cover the disk, SEP storage and NVRAM

The new vm snapshot create|list|revert|delete commands save a stopped machine’s disk, Secure Enclave storage and NVRAM as APFS clones. That gives researchers a fast way to return a guest to a known state after changing packages, boot files or test data without performing a full restore.

The official notes identify two limits: snapshots do not include settings or the device identity, and vm export and vm clone leave snapshots behind. Launchpad 2.7.0 adds a Snapshots… sheet for taking, reverting and deleting snapshots while the machine is stopped.

Clones can run beside their source

vm clone --new-identity gives a copy its own ECID, UDID and MAC address without forcing a restore, allowing the clone to run beside the source. It also clears a fixed IPv4 address, port-forward rules and a manually chosen mDNS name so the copy does not inherit conflicting network settings.

Launchpad exposes the option as a New device identity switch and enables it by default. Every clone operation now refuses to proceed while the source VM is running, which protects the APFS cloning operation from a changing source.

Xcode 27 DeviceHub gains live guest screens

A new guest library named libdevicehubfix allows the Developer Disk Image to mount on iOS 27, gets dtremotedisplayd to offer a stream and supplies the iPhone bezel mask. The release also adjusts the iOS 27 display patch so DeviceHub’s own view is no longer black. The project says this works with iOS 26, iPadOS 26 and iOS 27 guests after the guest environment is updated.

There are two documented caveats. Several simultaneous streams—or heavy host restoring and downloading—can make DeviceHub briefly freeze or lag by up to a couple of seconds, though the VM window is unaffected. iPadOS 27 guests currently refuse pairing, so the project marks DeviceHub on that guest version as untested.

Guest shutdown is now graceful by default

Closing a VM window, pressing Command-Q, running vm stop or interrupting vm launch now asks the guest to shut down first. vphone-cli turns the VM off only when the guest cannot be asked or has not halted within 15 seconds. This reduces the chance of treating every ordinary quit like a hard power cut.

The release also adds two optional, build-specific patches for iOS 27.0 build 24A435: one hides selected account-related Settings rows and another hides the Software Update row. Both are off in the standard preset and reject other builds.

Keep Launchpad and VPhone.bundle on 2.7.x

The developer explicitly requires Launchpad 2.7.0 with VPhone.bundle 2.7.x. The new Launchpad calls vm clone --new-identity and vm snapshot, so mixing it with an older bundle will leave those controls unsupported.

The official upgrade path is to install the notarized vphone-launchpad-2.7.0-notarized.zip, install Core Bundle 2.7.0, use Change Core Bundle… for existing machines and enable Update guest environment to receive DeviceHub viewing. The separately listed CI build is unsigned.

Requirements and jailbreak limits

  • Host: a physical Apple Silicon Mac running macOS 15 or later; the project says it does not work inside a macOS VM.
  • Host setup: free disk space, network access for signing tickets and the project’s documented macOS Recovery security adjustment are required.
  • Guest: a virtual iPhone created through vphone-cli’s research workflow; support for a package inside the VM does not establish support on a physical device.
  • Jailbreak mode: the project documents a patched jb guest variant with Sileo and TrollStore, but it exists inside the VM.
  • Physical iPhones: version 2.7.0 does not announce a kernel exploit, sandbox escape or public iOS 27 jailbreak for consumer hardware.

For physical-device availability, use the separate iOS 27 jailbreak status report. Readers comparing current device-side tools can also consult Dopamine 3 versus palera1n 3; neither guide should be read as vphone-cli compatibility.

Who should update

The strongest reasons to move to 2.7.0 are repeatable experiment checkpoints, side-by-side cloned guests and Xcode-based screen observation. Users who only launch one disposable VM gain less from snapshots and new identities, but the graceful shutdown behavior and matching 2.7-series tooling still make this a practical maintenance release.

Bottom line

vphone-cli 2.7.0 makes the virtual-iPhone lab easier to preserve, duplicate and inspect. Snapshots are the headline safety feature, independent clone identities improve parallel testing, and DeviceHub streaming brings the guest into Xcode’s device workflow. For ordinary iPhone owners, the key boundary remains unchanged: this software runs a modified virtual iPhone on a Mac and does not jailbreak the phone in your pocket.
