vphone-cli 2.4.0 Fixes iOS 27 App Extensions and Adds Guest Network Controls

The open-source vphone-cli project released version 2.4.0 on October 3 with fixes for iOS 27 guest app extensions and display rotation, plus configurable guest networking and a long-running screen-capture memory leak fix. It is a substantial upgrade for virtual-iPhone research on Apple Silicon Macs—not a new jailbreak for physical iPhones.

What vphone-cli 2.4.0 changes

Developer Lakr Aream published vphone-cli 2.4.0 on October 3, 2026. The release concentrates on making virtual iPhone guests behave more like complete devices during app testing: app extensions are registered correctly, iOS 27 display rotation works, network identity and forwarding can be configured, and long-running screenshot sessions no longer accumulate a display-sized image in memory.

Those changes matter to jailbreak and security researchers because vphone-cli can run patched guest firmware—including the project’s documented jb virtual-firmware mode—inside Apple’s virtualization stack. The host remains an Apple Silicon Mac; nothing in this release supplies a physical-device exploit or jailbreak chain.

App extensions now register on iOS 27 guests

Before 2.4.0, apps installed through apps.install or Launchpad’s Install App Package flow could launch while bundled extensions failed to register. The project specifically names VPN tunnel providers, share extensions, widgets and custom keyboards as affected examples. On iOS 27, the old temporary IPA-path registrations could disappear immediately, producing failures such as NEAgentErrorDomain Code=2.

The 2.4.0 toolchain copies extension bundles to stable locations before registering them. The apps.install result also reports discovered plug-ins and any plug-ins that could not be registered, which gives developers a concrete diagnostic instead of a silent failure. The release notes attribute this work to icli 0.7.12 and 0.7.13.

Display rotation works with iOS 27

The project’s display.rotation and display.rotation_lock controls now work on iOS 27 guests. According to the release notes, SpringBoard requires the com.apple.accessibility.physicalinteraction.client entitlement for this behavior on iOS 27, and the updated vphoned helper now carries it. That change arrived in icli 0.7.14.

This is particularly useful for automated interface testing: a host-side workflow can rotate a guest and lock its orientation without relying on manual interaction inside the VM.

Guest networking becomes configurable

Version 2.4.0 adds persistent networking options to each machine’s config.plist. The project documents fixed MAC addresses, fixed IPv4 addresses, gateway and DNS settings, host-to-guest port forwarding and mDNS behavior. A new vm network --link up|down command can also simulate connecting or disconnecting the guest’s virtual cable.

The settings take effect the next time the machine starts. The release also says the Mac’s .local hostname should resolve promptly from the guest, reducing friction when a test app needs to reach a service running on the host.

The screenshot leak fix matters for long runs

vphone-cli exposes host controls for screenshots and other automated input. In earlier builds, each screen capture could leave behind an image roughly the size of the display. That might be hard to notice in a short session but significant during multi-day automation. The 2.4.0 release notes say this leak is fixed in icli 0.7.11.

Other quality-of-life changes include a per-VM hardware-keyboard setting, an Auto-Lock: Never option that keeps the Lock Screen lit, the VM name on the Dock tile and app menus, clearer bootstrap messages and network configuration in Launchpad Settings.

Upgrade Launchpad and VPhone.bundle together

The developer calls out one important pairing rule: Launchpad 2.4.0 expects VPhone.bundle 2.4.x. A 2.3-series bundle does not contain the new vm config options. The bundled helper can update itself the next time a machine starts, and the official release page provides the notarized 2.4.0 distribution.

If a new network or display command appears missing after updating the app, verify the bundle version before treating it as an iOS guest compatibility problem.

Requirements and jailbreak limits

  • Host: an Apple Silicon Mac running macOS 15 or later, with Xcode and an iOS SDK as documented by the project.
  • Guest: a virtual iPhone created through vphone-cli’s research workflow; support for a package inside the VM does not establish support on a physical device.
  • Jailbreak mode: the project documents a patched jb guest variant with Sileo and TrollStore, but it exists inside the VM.
  • Physical iPhones: version 2.4.0 does not announce a kernel exploit, sandbox escape or public iOS 27 jailbreak for consumer hardware.

Who should update

The strongest reasons to move to 2.4.0 are testing apps with extensions on iOS 27, scripting orientation changes, building reproducible guest-network configurations or running screen-capture automation for long periods. Researchers using only short-lived guests without extensions will see fewer headline changes, but keeping Launchpad and the bundle on the same release line avoids tool mismatch.

Bottom line

vphone-cli 2.4.0 is a practical research-platform update rather than an exploit release. Correct extension registration makes VPNs, widgets, keyboards and share extensions testable again on iOS 27 guests; rotation and networking controls expand automation; and the screenshot leak fix improves stability for long sessions. For ordinary iPhone owners, the key boundary remains unchanged: this work runs a modified virtual iPhone on a Mac and does not jailbreak the phone in your pocket.
