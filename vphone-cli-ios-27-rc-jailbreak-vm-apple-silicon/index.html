vphone-cli Adds iOS 27 RC Support With a Full Jailbreak VM Mode on Apple Silicon

The open-source vphone-cli project has added iOS 27.0 RC build 24A435 to its tested firmware catalog. More unusually, the same project includes a dedicated jb virtual-firmware variant that patches the guest boot chain and installs Sileo and TrollStore inside a virtual iPhone. It is one of the more interesting iOS 27 research developments this week—but it is a Mac-hosted virtual machine, not a jailbreak for a physical iPhone.

What changed on September 10

The newest firmware-focused vphone-cli commit adds two catalog pairings, including iOS 27.0 RC build 24A435 for the iPhone17,3 firmware profile. The project pairs that image with cloudOS 26.4 and exposes it through its firmware-preparation picker, catalog command and JSON report. The project also added the same build to its Tested Environments table, where the iOS 27 RC pairing is shown as tested on a Mac16,6 host running macOS 26.6.1.

This is a meaningful update because vphone-cli is not just listing a download URL. Its purpose is to boot a virtual iPhone using Apple's Virtualization.framework and research-VM infrastructure, and the tested-environment entry indicates the project has taken the iOS 27 RC image through its virtualization workflow.

Why this belongs in jailbreak news

The project's current README documents five firmware-patching variants. The most relevant is named jb. According to the project, that mode applies 113 boot-chain patches and performs a 14-phase custom-firmware installation. The documented result includes automatic installation of Sileo and TrollStore on first boot.

That is a legitimate jailbreak-style environment: the guest operating system is modified beyond Apple's normal trust configuration, package-management tools are installed, and the project exposes SSH access to the running jailbroken VM. It is useful for tweak development, compatibility testing, reverse engineering and automated research without requiring the same kind of experimentation on a daily-use phone.

This is not an iOS 27 jailbreak for your physical iPhone

The distinction matters enough to state plainly: vphone-cli does not mean an iPhone running iOS 27 final can now be jailbroken by installing an app or connecting it to a normal jailbreak utility. The project runs on an Apple Silicon Mac and creates a virtual iPhone through Apple's virtualization technology. Its patched firmware and jailbreak components exist inside that guest environment.

Nothing in the September 10 commit claims a new iOS 27 kernel exploit, sandbox escape or physical-device jailbreak chain. The update is specifically a firmware-catalog and tested-environment expansion for the VM project. Readers should therefore avoid treating screenshots of Sileo running under vphone-cli as proof that iOS 27 has been publicly jailbroken on modern iPhones.

What the jailbreak VM actually includes

The project's README describes a spectrum of patch modes. Its lighter variants preserve more of the normal iOS security model, while the regular and developer modes progressively bypass AMFI, SSV, Img4, TXM and debugging restrictions. The jb profile sits above those and is described by the project as its full-jailbreak option. An experimental profile adds further anti-VM-detection research patches.

The jailbroken guest can be reached over SSH, and the project also documents VNC access. That makes the VM more than a static boot demonstration: it is intended to be an interactive research and testing environment. vphone-cli additionally exposes a host control socket for automated screenshots, touches, swipes, hardware-key actions and clipboard control, which can support automated testing workflows.

Requirements keep this firmly in the research category

The host requirements are substantial. The project calls for an Apple Silicon Mac, macOS 15 or later, Xcode and an iOS SDK. It also requires host security relaxation for private virtualization entitlements. Those requirements alone make it very different from a consumer jailbreak utility.

The project is therefore best understood as a developer and security-research platform. It can help researchers inspect iOS behavior, test jailbreak packages and experiment with patched guest firmware while keeping the work inside a virtualized environment. For ordinary iPhone owners waiting for an iOS 27 jailbreak, it is interesting progress around the platform—but not a release they can use on their handset.

Why iOS 27 RC support is useful now

Apple released the iOS 27 generation this week, so an environment capable of working with the release-candidate firmware gives researchers a near-final baseline for comparison. Developers can use that environment to study compatibility changes and test how tooling behaves against the new operating-system generation without presenting the result as a physical-device exploit.

The exact build also matters. The commit adds 24A435, which is the release-candidate build represented in the project's catalog. It should not be confused with a claim that every later iOS 27 build has been validated in the same configuration. Next Jailbreak will treat future firmware additions as separate updates when the project documents them.

What this means for jailbreak users

  • Researchers: vphone-cli now has a documented path for experimenting with the iOS 27 RC firmware in its virtual-iPhone environment.
  • Tweak developers: the jb guest can provide Sileo/TrollStore-based testing without claiming support on a physical iOS 27 device.
  • Everyday users: there is still no general public physical-device iOS 27 jailbreak implied by this project.
  • News tracking: the next important milestone would be support for newer final builds, major patch changes, or an independent physical-device exploit chain.

Bottom line

vphone-cli's September 10 update is exactly the kind of development that is easy to overstate. The impressive part is real: an open-source Apple Silicon project now catalogs and has tested iOS 27 RC, while its existing jailbreak VM mode can create a heavily patched guest with Sileo and TrollStore. That gives jailbreak developers and security researchers a powerful new iOS 27-era laboratory.

What it does not do is jailbreak the iPhone in your pocket. Keeping those two facts together makes the update more useful than either dismissing the project or presenting it as a consumer jailbreak release.
