vphone-cli 2.10.1 Adds iPhone 18 Pro Guests and Open Boot ROMs

The latest stable vphone-cli release moves new virtual machines to open-source boot ROMs and adds a verified iPhone 18 Pro research guest on iOS 27.0.1. It also improves remote display efficiency and iPad input, but it remains a Mac-hosted laboratory—not a jailbreak for a physical iPhone.

What changed in vphone-cli 2.10.1

Lakr Aream published vphone-cli 2.10.1 on October 18, 2026 at 14:01 UTC. The stable release replaces 2.9.5 and makes four changes especially relevant to jailbreak and iOS security researchers: open-source boot ROMs for new virtual machines, an iPhone 18 Pro guest profile, encoded remote-screen video, and native pointer input for iPad guests.

The scope matters. vphone-cli runs iOS, iPadOS and tvOS research guests through Apple’s Virtualization framework and PCC research infrastructure on a physical Apple Silicon Mac. The project can install a package environment inside a patched guest, but it does not exploit or jailbreak a retail iPhone.

New VMs start with OpenAVB and OpenSEP

Version 2.10.1 replaces two closed Virtualization.framework components for newly created machines. OpenAVB takes the place of AVPBooter on the application-processor side, while OpenSEP replaces AVPSEPBooter for the Secure Enclave side. Both ROMs ship in VPhone.bundle from pinned upstream commits and can be rebuilt and checked byte for byte with the project’s scripts.

The developer describes the boundary precisely: with both open ROMs selected, no Apple-written code runs before iBoot and SEPOS. That does not make the entire guest stack open source, and it does not remove Apple code after those handoffs. It gives researchers inspectable first-stage components and removes the need to patch AVPBooter’s image-digest check on those machines.

Existing VMs keep Apple’s ROMs after the upgrade. A stopped machine can switch in either direction without a restore:

vphone-cli vm config myphone --rom openavb --seprom opensep
vphone-cli vm config myphone --rom apple --seprom apple

vm info reports the selected ROMs. Restoring a machine through OpenAVB requires VPhone.bundle 2.10.1 or newer.

iPhone 18 Pro joins the iOS 27 research matrix

The release adds an iPhone 18 Pro (iPhone19,2) guest, whose firmware uses the ARM64E_X1 architecture. The official compatibility table records a successful boot of iOS 27.0.1 build 24A446 paired with cloudOS 26.4 build 23E5207q on a Mac17,7 M5 Max host. The developer’s acceptance checks included a clean offline restore, a validated root seal, a vphoned response, and successful launches of Settings, Safari and Calculator.

vphone-cli can also run that guest on hosts without native X1 instruction support. On those Macs, the standard preset lowers unsupported instructions. The release notes warn that this weakens PC-bound pointer authentication, so the fallback is useful for compatibility research but should not be mistaken for security-equivalent execution.

This guest does not establish jailbreak availability for the physical iPhone 18 Pro or every iOS 27 device. Firmware compatibility is a documented VM pairing, not a device exploit. Readers tracking real hardware should use the iOS 27 jailbreak status page instead.

Remote display uses encoded video

The local HTTP API’s GET /v1/host/screen endpoint now serves the VM display as HEVC or H.264 video encoded by vphone-vm, rather than repeatedly collecting guest screenshots. In the developer’s iPad guest measurement at 60 frames per second, the new stream added roughly one quarter of the CPU load of the screenshot path.

That should make browser-based monitoring and automation less wasteful during long test sessions. The API remains optional and local; researchers should keep its listener and token restricted rather than expose VM control to an untrusted network.

iPad guests gain native scroll and hover

For iPadOS guests, vphoned now provides input.pointer and input.scroll through a virtual pointing device. The VM window uses the new pointer_scroll capability, so trackpad scrolling carries momentum like a native Mac app and pointer hover reaches the guest directly.

Upgrade rules for 2.10.1

  • Launchpad and bundle must match: Launchpad 2.10.x works only with VPhone.bundle 2.10.x.
  • A notarized build exists: the release includes vphone-launchpad-2.10.1-notarized.zip; the similarly named CI archive without -notarized is unsigned.
  • 2.9 machines need rebinding: stop each machine, choose Change Core Bundle…, select 2.10.1 and enable Update guest environment. No restore is required.
  • Helper build 17 installs once: Launchpad asks for an administrator password when it installs the new helper.
  • Old VMs keep their ROM choice: upgrading does not silently switch an existing machine from Apple’s ROMs to OpenAVB and OpenSEP.

Host and firmware requirements

  • Mac: a physical Apple Silicon Mac running macOS 15 or newer; a macOS VM is unsupported.
  • Disk: each VM uses a 64 GB virtual disk by default, with additional space needed for firmware.
  • Network: restore requires an internet connection to obtain signing tickets.
  • Recovery setup: the host setup relaxes debugging restrictions and enables research guests while leaving SIP enabled.
  • Firmware pairing: use the project’s compatibility table rather than assuming any iOS IPSW and cloudOS image will work together.

Those requirements are independent of jailbreak package compatibility. A package manager in the guest does not expand Dopamine, palera1n, TrollStore or RootHide support on physical devices. See the Dopamine versus palera1n comparison.

Bottom line

vphone-cli 2.10.1 is a substantial research-platform release. OpenAVB and OpenSEP make the earliest VM boot stages inspectable, while the iPhone 18 Pro profile extends the project’s iOS 27 testing matrix to ARM64E_X1 firmware. Encoded screen streaming and native iPad pointer input improve everyday lab use. These capabilities live inside a Mac-hosted virtual environment and do not provide a physical-device jailbreak.
