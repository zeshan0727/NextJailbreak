vphone-cli Setup Guide: Run a Virtual iPhone on Apple Silicon

Set up vphone Launchpad on a physical Apple Silicon Mac, choose a documented iOS and cloudOS pairing, keep host security as tight as the official workflow allows, and add a package environment inside the guest. vphone is a research VM, not a jailbreak for your physical iPhone.

By Zeeshan Barvi · Originally published September 15, 2026 · Updated November 22, 2026 · Latest tagged release verified: vphone 2.17.1

Current release: vphone 2.17.1 is the latest official tagged release checked on November 22, 2026. It was published on November 13 at 09:01:22 UTC. The current upstream manual has newer documentation than the tag; this guide uses that manual for setup instructions and attributes release-specific fixes only to 2.17.1.
This is not a physical-device jailbreak. vphone runs iOS research guests through Apple’s Virtualization.framework and PCC research virtual machines on a physical Apple Silicon Mac. A RootHide-layout package environment inside a guest does not establish Dopamine, palera1n, TrollStore or RootHide availability on a retail iPhone.

What you need before installing

  • A physical Apple Silicon Mac: the project requires Apple Silicon and macOS 15 or newer. PV=3 research guests do not run inside a nested macOS virtual machine.
  • Storage headroom: each VM uses a 64 GB virtual disk by default, and downloaded firmware, templates and caches need additional free space.
  • Internet access: restore requests need to reach Apple for signing tickets. An offline Mac cannot complete the normal restore workflow.
  • Host security setup: vphone’s signed VM process uses Apple-private virtualization entitlements. macOS must accept that process before the guest can start.

A prebuilt VPhone bundle does not need Xcode, Python or Homebrew at runtime. Building vphone from source is different: the upstream manual requires Xcode and the iPhoneOS SDK to compile the guest daemon.

Prepare macOS without defaulting to a full SIP or AMFI disable

The current vphone host guide documents a less-permissive path that keeps System Integrity Protection enabled while relaxing its debugging restrictions and enabling Research Guests. From macOS Recovery, open Terminal and run:

csrutil enable --without debug
csrutil allow-research-guests enable

Restart into macOS. In Launchpad, open Host Setup, grant Developer Tools access when requested, and install the helper. Launchpad runs the bundle preflight and handles the current vphone-vm code-signature allowlist when AMFI refuses it. A new signature has a new cdhash, so a rebuilt binary must be allowed again.

If you use the standalone CLI instead of Launchpad, run vphone-cli host preflight; it reports the exact allowlist command for the bundle in use. Do not copy older tutorials that tell every user to disable SIP and AMFI. The upstream manual lists that as a more permissive alternative, not the default path in this guide; its boot-argument command also replaces existing boot-args.

Install Launchpad and create the first virtual iPhone

  1. Open the official vphone 2.17.1 release. The release provides the Core Bundle and Launchpad archives, including a -notarized Launchpad ZIP. Prefer that notarized archive. Not every release is notarized; if a future release lacks one, check the project's Downloads and notarization table before opening an unnotarized build.
  2. Unzip and open Launchpad, then complete Host Setup. Follow the app's prompts for Developer Tools access and its helper.
  3. Open Core Bundle and choose Download and Install. Keep Launchpad 2.17 with a matching VPhone.bundle 2.17.x series; do not mix arbitrary bundle generations.
  4. Open Machines, choose New Machine, select an exact firmware pairing from the available catalog, and choose Create.
  5. Let Launchpad prepare firmware, patch the boot chain, restore the guest and complete its first boot. The creation check expects vphoned to answer; after creation, start the VM from Machines when you want to use it.

For a terminal workflow, the current manual also documents vphone-launchpad-cli vm create. The lower-level vphone-cli commands remain available inside the installed bundle. Use the official Quick Start and Create and Run pages for the exact current command options.

Firmware compatibility: check the exact model, build and cloudOS

Do not treat “iOS 27 support” as a blanket statement. vphone needs a compatible iPhone restore IPSW and PCC/cloudOS image. The project’s fw catalog and compatibility table are the authority for a particular pairing. The current documentation records these specific iOS 27.0.1 examples:

Important test-version caveat: the M4 test records above were made with Core Bundle 2.12.1/2.12.2, and the iPhone 18 Pro record is a separate host test. They are evidence for those exact combinations, not a claim that every device and firmware has been regression-tested on 2.17.1. The manual lists other device models and releases, but a model appearing in its device table does not prove every IPSW/cloudOS combination boots. Treat unlisted or untested pairs as unverified, not supported by assumption.

Before creating a VM, compare the exact build number and cloudOS in the official firmware compatibility matrix. If a pairing is absent from fw catalog, do not substitute a nearby cloudOS release or an unofficial IPSW mirror.

What vphone 2.17.1 changes on an existing VM

  • iPad pointer rotation: the framebuffer stays panel-native so the pointer is drawn correctly in landscape.
  • ARM64E_X1 accessibility: 35 remaining standalone accessibility plug-ins are lowered for hosts without native FEAT_PAuth_LR, fixing a documented startup fault when accessibility is enabled.
  • Read-only audit: vphone-cli cfw audit-arm64e-x1 <volume-root> reports libraries and plug-ins that still need lowering. The release supports --json and --strict.

For an existing stopped machine, the 2.17.1 release says to update its guest environment; a restore is not required for these guest-resource changes. In the current Launchpad CLI, use the documented vphone-launchpad-cli cfw update-environment <name> operation. Updating only the Mac app or changing a machine's bundle binding does not redeploy its guest resources.

Add a package environment inside the guest

A new VM is intentionally minimal. It does not start with Sileo, apt, TrollStore, an SSH server or a VNC server. If you need package management and command-line tools for research, the current vphone manual documents this guest-only flow:

  1. In the running VM window, open Apps → Install Bootstrap… and choose the roothide layout. The manual marks the old rootless layout as deprecated.
  2. This installs Irisin inside the VM. In Irisin, open the OwnGoal Packages repository.
  3. Find OwnGoal Bootstrap for vphone (owngoal-bootstrap-vphone) and install it with Bootstrap Install.
  4. After the bootstrap completes, install additional packages normally. To remove it, use Apps → Uninstall Bootstrap….

The bootstrap brings in apt and dpkg, shells, sudo, core command-line tools, OpenSSH server, curl, wget, vim, git and the OwnGoal apps. Do not install those packages one by one: the project warns that dependencies are interrelated and separate installs can fail partway. If the first bootstrap installation fails, uninstall the environment and start again rather than repairing a partial install.

Terminology matters: selecting the roothide layout here creates a package environment inside the virtual guest. It does not install RootHide on your physical iPhone and does not turn vphone into a public jailbreak.

Practical troubleshooting

SymptomWhat to check
vphone-vm is killed before the window opensRun Host Setup again in Launchpad. For CLI use, run vphone-cli host preflight and follow the allowlist command it prints. A changed signature means a changed cdhash.
“Virtualization is not available on this hardware”Use a physical Apple Silicon Mac. The project's PV=3 research guests do not run in a nested macOS VM.
Creation succeeds but no VM is runningThis can be expected: creation performs a first-boot vphoned check and stops that temporary boot. Start the machine from Launchpad's Machines page.
The guest is stuck at “Press home to continue”Click the Home button in the VM window's title bar, as documented by the upstream troubleshooting guide.
Restore or first boot failsCheck network access for Apple's signing-ticket request, confirm the exact iPhone/cloudOS pair, and avoid parallel VM creation when memory or disk space is tight.
Bootstrap installation fails partwayUse Apps → Uninstall Bootstrap… and repeat the documented Irisin and OwnGoal bootstrap sequence. Do not install its dependencies individually.

Frequently asked questions

Is vphone-cli a jailbreak for my physical iPhone?

No. It runs an iOS research guest on a physical Apple Silicon Mac. The guest can receive its own package environment, but that does not jailbreak the host iPhone or prove that the same iOS build can be jailbroken on retail hardware.

Does vphone need a Mac with SIP completely disabled?

Not for the documented default path. The current host guide shows how to keep SIP enabled while relaxing debugging restrictions and enabling Research Guests. Launchpad's helper manages the current VM binary allowlist. The separate full SIP and AMFI disable is a more permissive alternative and should not be copied casually.

Can I use every iOS 27 build?

No. The official compatibility table records exact model, build and cloudOS pairings. The examples in this guide are specific iOS 27.0.1 tests, some performed with earlier Core Bundle versions. Check the current catalog before creating a VM and treat unlisted combinations as unverified.

Does a new VM include Sileo, TrollStore or SSH?

No. The guest starts without a package manager, Sileo, apt, TrollStore, SSH server or VNC server. The documented Irisin and OwnGoal bootstrap is an optional guest-only setup that adds apt, dpkg, shells and OpenSSH.

Do I need to restore an existing VM for vphone 2.17.1?

The 2.17.1 release says the iPad pointer and accessibility plug-in changes are applied by updating the guest environment. Use the current Launchpad CLI's stopped-machine cfw update-environment operation; a full restore is not required for those guest-resource changes.
