vphone-cli 2.9.2 Adds Space-Saving VM Templates and Safer Imports

The official 2.9 series changes how vphone-cli creates, stores and imports virtual iPhones. Version 2.9.2 is the current release, fixing incomplete imports after 2.9.0 introduced reusable templates and 2.9.1 refined guest performance and Launchpad.

What changed from 2.8.0 to 2.9.2

Lakr Aream published vphone-cli 2.9.0 on October 9, 2026 at 06:10 UTC, followed by 2.9.1 at 17:22 UTC and 2.9.2 at 18:31 UTC. The newest release is therefore 2.9.2; readers should not install 2.9.0 or 2.9.1 as though they were still current.

The 2.9 series is a substantial storage and workflow update for the Mac-hosted virtual iPhone research platform. It does not announce a physical-iPhone exploit and does not make iOS 27 jailbreakable on consumer hardware.

Reusable templates cut new VM storage dramatically

Version 2.9.0 changes vm create so a machine can be cloned from a prepared template. The project keeps one template for each IPSW, device, preset and slimming combination, then shares identical disk blocks with machines created from it.

The official release notes estimate that a templated machine uses about 0.6 GB instead of roughly 20 GB. Once the matching template exists, creation takes under a second before the guest’s first boot. Templates live under the machine library’s .templates directory and are managed with vm template list|show|adopt|delete|trim|setup.

There is an important isolation tradeoff: machines cloned from the same template share its Secure Enclave root secret and Data-volume keys. Use --no-template when a machine must have its own keys and independent restore.

Slim System removes unused guest components

Template setup can trim about 1.2 GB from the System volume, delete the orig-fs snapshot, skip Setup Assistant, remove ten default system apps and apply a service profile that disables 141 launchd jobs. Camera and Phone stay installed.

Launchpad exposes these controls through New Machine’s Slim System and Advanced Options. Existing stopped machines can also share identical disk blocks with vm rebase <vm> --onto <base>; the release says this changes only the disk image.

Motion simulation and iOS 27 fixes arrive in 2.9.0

  • Motion sensors: gyroscope and device-attitude simulation gain live controls under Features › Motion Sensors.
  • Faster firmware preparation: fw prepare downloads IPSWs over four connections by default, configurable from one to sixteen.
  • iOS 27 location: another startup fix prevents locationd from crashing or hanging on cohort queues.
  • Flutter: AOT callbacks work again where vm_remap lost executable protection.
  • Large IPA installs: apps.install accepts IPAs that expand to 8 GiB or contain up to 400,000 entries.
  • macOS 27: clone, snapshot and revert no longer crash when a devfs device number exceeds a signed 32-bit value.

Version 2.9.1 improves reliability and Launchpad

Version 2.9.1 makes template creation wait through first-boot data migration on slower Macs, gives iOS 26 its own trimmed service list and clears the template’s crash reports before freezing it. It also reduces guest idle wakeups by polling device state only while an event socket is open and stopping camera, gyroscope and speaker timers when idle.

Other fixes include guest clipboard changes becoming visible to vphoned, right-click acting as secondary click instead of Home, ProMotion enabled in the standard preset and vm export ignoring the stale vphone.sock left by a stopped machine.

Launchpad’s New Machine flow becomes one page with Advanced Options, while export writes a .vpea archive without restore IPSWs. Menus add shortcuts for starting, stopping, snapshotting, exporting, renaming and cloning machines.

Version 2.9.2 makes VM imports safer

The current 2.9.2 release fixes an import failure that could occur when the process reading vm import output disappeared. Quitting Launchpad during an import previously could abort every import and leave a partly unpacked .import-* directory; the import can now finish independently.

vm import also handles Ctrl-C and SIGTERM cleanly, removing the files it had unpacked. Launchpad now shows an import as a machine-list row with progress, displays the archive and a Stop Importing button in the inspector, and queues several imports one at a time. Quitting during an import or export asks first and waits for cleanup.

If 2.9.1 or an earlier build crashed during import, the developer says leftover .import-* folders under ~/.vphone/machines are not machines and may be deleted. Only remove folders with that exact temporary-name pattern after confirming no import is active.

How to upgrade correctly

The official instructions pair Launchpad 2.9.2 with VPhone.bundle 2.9.x and helper build 16. Download the notarized vphone-launchpad-2.9.2-notarized.zip, then install VPhone.bundle 2.9.2 from Core Bundle.

For the 2.9.2 import correction, that bundle must be the default because the fix lives in its vphone-cli. The release explicitly says existing machines do not need to move or update their guest environment for this point release. The official release offers a notarized Launchpad archive; avoid treating an unsigned CI build from an older version as the recommended download.

Requirements and jailbreak boundaries

  • Host: a physical Apple Silicon Mac running macOS 15 or later. The project says it does not work inside a macOS VM.
  • Storage: templates reduce incremental machine size, but firmware, templates and virtual disks still require free space.
  • Network: restoring a guest fetches signing tickets online.
  • Host security: the README documents a macOS Recovery adjustment that keeps SIP enabled while relaxing debugging restrictions.
  • Guest scope: package environments and patched guests exist inside the virtual machine.
  • Physical iPhones: 2.9.2 does not provide an iOS 27 jailbreak, installation path or compatibility expansion for real devices.

For physical-device availability, see the separate iOS 27 jailbreak status report. Readers evaluating device-side jailbreaks should use the Dopamine versus palera1n comparison.

Bottom line

vphone-cli 2.9.2 is the version to use for the 2.9 series. The headline improvement is templated virtual machines that consume far less incremental storage, followed by better motion simulation, lower idle activity and a safer import pipeline. These are meaningful advances for Apple Silicon security-research labs, but they remain separate from physical-iPhone jailbreaking.
