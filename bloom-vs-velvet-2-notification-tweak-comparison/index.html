Bloom vs Velvet 2: Animation or Full Notification Styling?

Bloom and Velvet 2 both react to notifications, but they solve different problems. Bloom animates the display when an alert arrives; Velvet 2 redesigns the notification card itself. Firmware support, price and the kind of visual change you want determine the better choice.

By Zeeshan Barvi · Published October 17, 2026 · Verified against the current Havoc and Chariz product data, descriptions, screenshots and version histories

Compatibility note: package support is not the same as jailbreak availability. Confirm your exact device, iOS build and active jailbreak before installing either tweak. This comparison uses developer-listed behavior and does not claim hands-on testing.

The short answer

Choose Bloom if you want a visible animation when a notification arrives. It can color notch, Dynamic Island or screen-edge effects from the sending app’s icon, adjust speed and repeats, filter apps and keep the screen dark after an effect.

Choose Velvet 2 if you want to restyle the notification card. It can change the background, border, text, icon and corner treatment, add glow or side accents, use solid colors or gradients, preview changes live and override settings per app.

They are not direct substitutes: Bloom changes the arrival moment, while Velvet 2 changes the notification surface that remains on screen. On supported iOS 15–16.3 devices, the choice is primarily animation versus styling.

What Bloom changes

Bloom is about motion. When a notification arrives, it can run a colored animation shaped for the screen edge, notch or Dynamic Island. The official description exposes repeat-count, speed and color controls; color can follow the app icon or use a custom choice. Its Blackout option can leave a locked screen dark after the animation finishes, and it respects Do Not Disturb unless “Show in DND” is enabled.

Version 1.3 added three app-filter modes. Version 1.4 then moved the hooking engine from Orion to Shook and declared official iOS 18 support. The current 1.4.1 release fixes loading failures mainly on iOS 18, selects Dynamic Island animations for the iPhone 16 family instead of a generic fallback, and repairs LastLook integration.

What Velvet 2 changes

Velvet 2 is about the card itself. Its official feature list covers the background, border, title, message, time, app name and icon. Optional glow and side-line elements can be added, while overall controls include corner radius, border width, notification spacing, icon hiding and whether stacked notifications dim.

Colors can be automatic from the app icon, manually selected or gradient-based with a chosen direction. The settings page includes a live fake notification so changes can be reviewed without repeatedly generating alerts or respringing. Per-app settings override only the fields you change, leaving the global design in place for everything else.

The compatibility overlap is narrow

Velvet 2’s official range is iOS 15.0–16.3. Bloom’s developer description starts at iOS 14, and Havoc marks it rootless-compatible. That makes iOS 15 through 16.3 the clearly documented overlap. On iOS 14, Bloom is the only one of the pair with official support; above iOS 16.3, Velvet 2’s official listing no longer applies.

Bloom has one important documentation mismatch: its description and 1.4/1.4.1 changelogs explicitly discuss iOS 18, while Havoc’s structured compatibility field still ends at iOS 17.7.11. The version history is the more recent statement, but iOS 18 users should still confirm the exact device and jailbreak environment before purchasing.

Do not infer iOS support from a screenshot alone. A tweak can support a firmware family even when no public jailbreak exists for a particular processor or point release.

Could you use both?

The official pages do not declare a direct conflict, and their jobs are different enough that a combined setup is conceptually possible on overlapping firmware. That is not a compatibility guarantee. Both hook notification behavior, so install one first, verify normal alerts, and only then consider the second. If notifications disappear, duplicate effects occur or SpringBoard becomes unstable, remove the most recent package through Sileo.
