KillX Pro Neo 3.0 launches as an app-switcher cleaner for iOS 15 through iOS 26

KillX Pro Neo 3.0 is the initial release of cemck’s modernized app-switcher cleaner. The package is described as a successor to KillX and is designed to let users close running apps by swiping down once on an App Switcher card. Its listed feature set includes automatic music-app detection, app locking, configurable button appearances, animations, and haptic feedback on supported iPhones. The official package information lists iOS 15 through iOS 26 support, while the detailed information panel specifies iOS 15.0 through 26.0.1. It also explicitly rules out iPadOS compatibility.

Key points

  • KillX Pro Neo 3.0 is marked as an initial release, not a maintenance update with a detailed bug-fix changelog.
  • The central action is closing all running apps with one downward swipe on an App Switcher card.
  • Music detection can keep the app currently playing media alive and marks it with a music glyph.
  • Users can lock apps from the App Switcher or make locks permanent through settings.
  • The package supports iOS 15.0 through 26.0.1 according to its detailed information panel, but it is not compatible with iPadOS.
  • The package lists mobilesubstrate, PreferenceLoader 2.2.3 or newer, and AltList as dependencies.

What is new in KillX Pro Neo 3.0

KillX Pro Neo 3.0 has been published as a modern app-switcher cleaner for iOS. The package record identifies version 3.0, while the accompanying changelog describes it simply as an “Initial Release.” That means the available release notes do not document a sequence of incremental fixes or a migration from an earlier Neo build; version 3.0 is presented as the starting point for this package.

The developer’s description positions KillX Pro Neo as the successor to KillX. Its main purpose is to reduce the effort required to clear the App Switcher: instead of repeatedly swiping individual cards, users can swipe down once on one card to close all running apps. The description frames this as the core experience rather than as a background performance or storage-management tool.

One-swipe cleanup, with safeguards for important apps

The central feature is a bulk-closing gesture. According to the official description, swiping down once on an App Switcher card closes all running apps. This is intended to replace the repeated manual process of swiping through cards one by one.

The tweak also includes safeguards intended to prevent an important app from being closed accidentally. Its Music Detection feature automatically detects the app playing media and keeps that app alive. A music glyph identifies the currently playing app and indicates that it is locked. The source describes this behavior specifically for the app detected as playing media; it does not claim that every audio-related or background activity is preserved.

App Lock provides a broader manual option. Users can tap and hold app cards to lock them, preventing those apps from being killed or closed by mistake. The description also says apps can be locked permanently from the settings pane. This gives users two levels of control: a quick lock from the App Switcher and a persistent setting for apps that should routinely be protected.

  • Swipe down once on one App Switcher card to close running apps.
  • The detected media-playing app is kept alive and marked with a music glyph.
  • Tap and hold cards to lock them against accidental closure.
  • Permanent app locks are available from the settings pane.

Appearance and feedback options

KillX Pro Neo includes visual animations for several actions. The official depiction mentions animated lock glyphs when an app card is locked and additional animations when apps are killed. These effects are presented as part of the tweak’s appearance experience, rather than as changes to the underlying app-closing behavior.

Users can also choose among several button styles. The listed choices are Colored or Mono, Extra Light, Light, and Dark. The source does not describe additional theme controls beyond these styles, so prospective users should treat them as the documented appearance options for this release.

Haptic feedback is another part of the interaction design. The description says different feedback responses are used for killing apps and for locked apps. It also states that this feature is supported only on iPhone 6s or newer devices. That device requirement applies to haptic feedback specifically and should not be read as a general statement that the entire tweak requires an iPhone 6s or newer.

  • Animated lock glyphs and app-killing animations are included.
  • Button styles include Colored or Mono, Extra Light, Light, and Dark.
  • Different haptic responses are described for killing apps and locked apps.
  • Haptic feedback is limited to iPhone 6s or newer devices.

Compatibility and package requirements

The package stanza lists firmware version 15.0 or newer as a dependency, and the package description presents the tweak as supporting iOS 15 through iOS 26. The detailed information panel gives the more precise range as iOS 15.0 through 26.0.1. Because those two descriptions use slightly different wording, users should compare their device’s exact iOS version with the package information shown by their package manager before proceeding.

The same information panel explicitly states that KillX Pro Neo is not compatible with iPadOS. It also warns that tweaks which force iPadOS features such as Split View are not compatible. This is an important limitation for users of iPad-based jailbreak environments: the broad iOS version range should not be interpreted as support for iPadOS hardware.

The package metadata lists three dependencies: mobilesubstrate, PreferenceLoader version 2.2.3 or newer, and com.opa334.altlist. These components are package requirements, not optional feature suggestions. The metadata also marks the package as conflicting with and replacing the older package identifier com.cemck.killx-pro. That relationship matters if an older KillX Pro package is already present, because package-management behavior may account for the earlier identifier during installation or upgrade planning.

The listed package size is 3.04 MB in the depiction, while the metadata reports an installed size of 3,660 KB and an archive size of 3,185,526 bytes. Small differences between displayed size values can reflect whether a package manager is showing the compressed archive or installed footprint.

  • Explicitly not compatible with iPadOS.
  • Dependencies: mobilesubstrate, PreferenceLoader 2.2.3 or newer, and AltList.
  • The package conflicts with and replaces com.cemck.killx-pro.

What to verify before installing

KillX Pro Neo 3.0 is a commercial package, and the official depiction includes a return policy. Refund requests are described as being accepted within 24 hours of purchase under acceptable circumstances. The page says requests should clearly describe the issue, and that a request can be closed if there is no response through chat within seven days. It also says issues already stated in the package description, including listed compatibility limitations, are not grounds for a refund.

For users considering the package, the first checks are straightforward: confirm the device is running an explicitly supported iOS version, confirm that it is an iPhone rather than an iPad, and review whether the required dependencies are available in the package manager. Users who rely on music playback should also note the documented detection-and-lock behavior, while users with older iPhones should not expect haptic feedback if the device predates the iPhone 6s.

The package page provides the developer’s support contact and requests clear details such as crash logs or screen recordings for issues. Since version 3.0’s changelog only says “Initial Release,” the package description and compatibility warnings are the main source-provided guidance available for evaluating the release.

  • Check the exact iOS version against the listed 15.0–26.0.1 range.
  • Do not assume iPadOS support; the official page explicitly excludes it.
  • Review the listed dependencies before purchasing or installing.
  • Read the return policy, including its 24-hour window and stated exclusions.
  • For support, prepare clear issue details and relevant crash logs or screen recordings.
