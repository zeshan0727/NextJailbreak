palera1n 3.0.0 Beta 4 Fixes Linux GUI Privilege-Escalation Flaw

The November 21 beta 4 release fixes a timing-attack issue in palera1n’s Linux GUI helper that could allow root privilege escalation. It remains a pre-release: stable 2.4 is still the latest stable tag.

By Zeeshan Barvi · Originally published September 22, 2026 · Updated November 22, 2026 · Verified against the official beta 4 release, fix commit, project README and installation documentation

Release status: GitHub published v3.0.0-beta.4 on November 21, 2026 at 03:09 UTC (06:09 in Qatar) and marks it as a pre-release. The latest non-prerelease release remains v2.4, published July 27, 2026. Beta 4 is the newest 3.0 test build—not a stable palera1n 3.0.0 release.

What beta 4 fixes

The official changelog contains one change: it fixes a timing attack that could allow an attacker to gain root privileges from palera1n’s Linux GUI builds. The project says the issue was introduced in v3.0.0-beta.3.

The release note scopes the problem to GUI Linux builds. It does not say that the same issue affected the command-line workflow or the macOS build, so those environments should not be described as affected without additional evidence. Beta 4 does not announce a new jailbreak exploit, a new device family, or an expanded firmware range.

What changed in the fix commit

The official beta 4 fix commit shows the implementation change behind the release note. The previous Linux helper wrote a shell script to /tmp/udevhelper.sh, changed its permissions, and then launched that file through pkexec. The fix removes that temporary-file handoff and passes the helper script directly to pkexec sh -c; it also resolves the invoking username from the process UID, with an environment-variable fallback.

This is a source-level explanation of the patch, not a reproduction procedure. The release note does not publish a CVE identifier or claim that the issue was exploited in the wild. Do not infer either from the phrase “timing attack.”

Device and firmware support did not expand

Beta 4 is a Linux GUI security maintenance release. It does not change palera1n’s checkm8 hardware boundary. The project README lists A8 through A11 devices and supported Apple T2 hardware; its phone and tablet list includes models such as iPhone 6s through iPhone X, iPad mini 4, iPad Air 2 and the listed A8–A10X iPads. The manual explicitly excludes arm64e devices, so an iPhone XS or newer A12-and-later iPhone is not made compatible by beta 4.

The official installation guide describes palera1n as compatible with A11 and earlier devices on iOS 15.0 and later, while the current manual’s overview lists iOS/iPadOS/tvOS 15–26 and bridgeOS 5–10. Those broad ranges must still be checked against the project’s exact device list and current documentation. The beta 4 changelog does not add an iOS 27 support statement or certify every beta and build in the broad range.

There are important A11 restrictions. On iPhone 8, iPhone 8 Plus and iPhone X, the passcode cannot be used while jailbroken. The manual says the passcode must be off on iOS 15 while jailbroken; on iOS 16 it must have been off since restore, and “Erase All Content and Settings” counts as a restore. Back up first and do not proceed if those restrictions are unacceptable.

palera1n is semi-tethered: after a device reboot, the computer tool must be run again to enter the jailbroken state. The device can still boot normally without the computer; the computer is needed to re-enter the jailbreak.

Host and DFU checks before testing a beta

  • macOS or Linux: these are the host platforms covered by the project’s installation instructions. For Windows, follow the official palen1x route rather than assuming the beta 4 release contains a Windows installer.
  • USB cable: the official guide warns that some USB-C to Lightning connections can fail during DFU entry and recommends trying USB-A to Lightning where needed.
  • Apple Silicon Mac: the guide says you may need to unplug and reconnect the device after “Checkmate!” appears in the logs.
  • Linux host: the guide documents issues with some Ubuntu-based distributions and AMD Ryzen systems. If DFU or exploit setup fails, check the official troubleshooting notes instead of repeatedly changing device settings.

Safe beta 4 update checklist

  1. Record the exact device model, chip, iOS/iPadOS version and build. Do not infer jailbreak support from a package’s minimum iOS version.
  2. Confirm that the device appears in palera1n’s official device list. Treat A11 passcode and restore restrictions as a hard requirement, not an optional workaround.
  3. Back up important data before testing a pre-release and keep a known recovery route available.
  4. Download only from the official beta 4 release page and choose the host architecture that matches your Mac or Linux computer.
  5. If you use the Linux GUI, do not keep using beta 3: beta 4 is the release that fixes the issue called out by the maintainers.
  6. Remember that palera1n is semi-tethered. After a reboot, run the tool again to return to the jailbroken state.
