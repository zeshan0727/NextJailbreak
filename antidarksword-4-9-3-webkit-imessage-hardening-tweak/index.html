AntiDarkSword 4.9.3: What Its WebKit and iMessage Mitigations Cover

AntiDarkSword is a configurable hardening layer for vulnerable iPhones. The jailbreak tweak can restrict WebKit features, remote content and selected message-processing paths; the separate TrollFools build covers fewer surfaces inside injected apps.

By Zeeshan Barvi · Published October 11, 2026 · Verified against the official 4.9.3 release, README, compatibility guide and package metadata

Security reality check: AntiDarkSword does not patch iOS, WebKit or the named CVEs. Its protection list is the developer’s description of behavior-changing mitigations. Installing a tweak on an outdated, jailbroken device is not equivalent to installing Apple’s security updates.

What version 4.9.3 actually changed

AntiDarkSword 4.9.3 was published on May 15, 2026 and remains the latest official release checked on October 11, 2026. Its short changelog says only that labels and the README were updated. That matters: the extensive mitigation set below is the current project feature set, not a claim that every feature first appeared in 4.9.3.

The release ships four distinct downloads: modern rootless, modern rootful, legacy rootful and TrollFools. The package identifier is com.eolnmsuk.antidarksword; the official control metadata lists mobilesubstrate, preferenceloader and com.opa334.altlist as dependencies.

What the jailbreak tweak can restrict

The current README describes three layers of protection. The WebKit-facing controls can disable JIT and JavaScript, spoof the user agent, and restrict WebRTC, WebGL, autoplay and local-file access. Mail and Messages controls can block remote content, suppress risky attachment previews and reduce automatic download behavior. At the highest preset, the tweak also targets selected messaging-related daemons and enables the project’s “Corellium decoy.”

The developer presents three presets rather than a single all-or-nothing switch:

  • Level 1: concentrates on Safari, Safari view services, Messages and Mail, with baseline JIT/JavaScript restrictions and media or local-file controls.
  • Level 2: extends the rules to third-party browsers, messaging, email, social, finance and several jailbreak apps, and enables remote-content blocking for Messages and Mail.
  • Level 3: adds broader browser restrictions plus optional hooks for imagent, apsd, identityservicesd and IMDPersistenceAgent.

Those controls can materially reduce functionality. Disabling JavaScript, WebGL, WebRTC or remote content may break websites, sign-in flows, calls, previews and embedded media. Start with the least restrictive preset that matches the threat model and change one group at a time.

The TrollFools build is intentionally narrower

The no-jailbreak option is a dylib for TrollStore and TrollFools, injected into individual apps. It can apply several WebKit restrictions, user-agent changes, autoplay blocking and local-file controls inside those apps. The official comparison table does not credit it with iMessage auto-download interception, system-daemon protection or the Corellium decoy.

The TrollFools variant also exposes a biometric-gated settings overlay with a three-finger double-tap. It is useful when only selected apps need hardening, but it cannot reproduce system-wide daemon hooks without a jailbreak.

What AntiDarkSword does not prove

The project names DarkSword, Coruna, BLASTPASS and several CVEs, but that naming is not an independent security audit. A mitigation can block one delivery route or feature without eliminating the underlying memory-safety bug, alternate parsing paths or future exploit variants. There is also a tradeoff in relying on injected code to protect a modified operating system.

  • It does not update Safari’s WebKit engine or Apple system frameworks.
  • It does not make a jailbroken device equivalent to a fully patched device.
  • It does not guarantee protection against every exploit using a named campaign or vulnerability.
  • Its high-restriction settings may interfere with expected browser, messaging and notification behavior.

If Apple offers a supported security update that preserves your needs, that update remains the stronger fix. AntiDarkSword is most reasonably viewed as optional defense-in-depth for devices intentionally kept on vulnerable firmware.

Which package should you install?

  1. Confirm the exact iOS version, chip and jailbreak environment before downloading.
  2. Open the official AntiDarkSword 4.9.3 release; avoid third-party mirrors.
  3. Choose iphoneos-arm64 for a conventional rootless jailbreak, iphoneos-arm for a modern rootful jailbreak, or iphoneos-arm_legacy only for the listed iOS 13–14 legacy setup.
  4. Use the TrollFools dylib only through TrollStore and TrollFools, and only for apps you intentionally select.
  5. Install the declared dependencies and keep a safe-mode or package-removal path available before enabling restrictive daemon hooks.

If you are installing a local package through Sileo, follow our rootless DEB installation guide. Our rootless basics guide explains why the arm64/arm naming convention cannot be interpreted without the package layout.

Bottom line

AntiDarkSword 4.9.3 is unusually transparent about the differences between jailbreak and TrollFools coverage, and it supplies separate builds for three jailbreak layouts. Its value is configurability: users can reduce risky browser and messaging behavior without pretending the tweak repairs the OS itself. The cautious approach is to start at Level 1, verify normal browsing and messaging, then add restrictions only when their benefit outweighs the breakage.

Frequently asked questions

Does AntiDarkSword patch DarkSword, Coruna or BLASTPASS?

No. The developer describes mitigations for behaviors and attack paths associated with those threats. The tweak does not patch the underlying iOS or WebKit vulnerabilities and is not a replacement for an Apple security update.

Which build is for Dopamine?

The official table assigns the iphoneos-arm64 DEB to rootless jailbreaks including Dopamine on iOS 15.0–17.0. Confirm that Dopamine supports the exact device and firmware before treating the tweak’s range as usable.

Can I use AntiDarkSword with TrollStore but no jailbreak?

Yes, through the separate TrollFools dylib on developer-listed iOS 15.0–17.0. It covers fewer protections and cannot provide the jailbreak build’s system-daemon or iMessage auto-download hooks.

Is version 4.9.3 a major security-engine update?

No. The official 4.9.3 changelog says labels and the README were updated. The article describes the current overall feature set and does not attribute all of it to that point release.
