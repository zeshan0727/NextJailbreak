WifiCrush 1.0.2 Automates Wi-Fi and 5G Switching on iOS 15–26

WifiCrush watches saved Wi-Fi signal strength, moves to a stronger saved network or mobile data when configured thresholds are crossed, and returns to the preferred network when it recovers.

By Zeeshan BarviPublished November 2, 20268 min read
Current release: Havoc lists WifiCrush 1.0.2, published November 2, 2026, for rootless and RootHide jailbreak environments on iOS 15.0–26.0.1. PreferenceLoader is required; CCSupport is optional.

What WifiCrush 1.0.2 actually changes

WifiCrush is not a signal booster. It automates decisions that normally require opening Control Center: staying on a preferred saved network while it is healthy, moving to a clearly stronger saved network when it weakens, enabling mobile data when every configured Wi-Fi connection is below the chosen threshold, and returning after Wi-Fi recovers.

The developer says mobile data is disabled only after Wi-Fi remains stable for 30 seconds and a connectivity check against Google, Cloudflare and Apple confirms Internet access. During a call, the tweak can move to mobile data when Wi-Fi weakens and hold that path until the call ends. Those are developer-published behavior claims; Next Jailbreak has not independently measured handoff loss, battery use or carrier-specific call continuity.

How the orbit interface works

The main screen places the iPhone at the center of an orbit, with saved networks positioned around it and signal values shown in dBm. A heart marks a preferred “crush” network; the status line explains why the current network is being kept or what switch is expected next.

Users can select up to three preferred networks, temporarily request the strongest available network, and prioritize 5 GHz when its signal is close enough to a 2.4 GHz alternative. The feature is useful for a home with separate 2.4 GHz and 5 GHz names, but it cannot repair poor access-point placement or congestion.

Control Center behavior differs by iOS version

Version 1.0.2’s changelog says the Control Center tile now works on iOS 18 as a regular CCSupport module. On iOS 15–17, its location follows the older implementation. CCSupport is not required for the core switching engine; install it only if you want the tile.

The listing also offers an optional change that makes Apple’s stock Control Center Wi-Fi button turn Wi-Fi fully off. That is a different behavior from stock iOS, which normally disconnects temporarily. Enable it only if you understand that automation cannot rejoin Wi-Fi while the radio is explicitly disabled.

Set up WifiCrush safely

  1. Confirm a supported rootless or RootHide jailbreak is active and use its normal Sileo or Zebra package source.
  2. Open the official Havoc listing and verify version 1.0.2 and package ID com.pitroytech.wificrush.
  3. Install PreferenceLoader when prompted. Add CCSupport only if the Control Center module is needed.
  4. Open WifiCrush, sign in to Havoc and activate the purchase. Record the displayed support code if activation fails.
  5. Select one preferred network first and use a conservative signal threshold. Verify normal Wi-Fi before enabling mobile-data fallback.
  6. Walk between known coverage areas and confirm the status line matches the expected switch. Test again during a non-critical call before relying on call handoff.

If Sileo reports a dependency error, do not force dpkg. Use the rootless dependency troubleshooting guide and confirm that the repository has supplied the correct environment-specific package.

Settings that matter most

  • Automatic versus custom signal levels: Start with Automatic. Custom thresholds can cause repeated switching when two access points hover around the same value.
  • Preferred-network list: Select only saved networks you trust. The tweak cannot join a network that iOS has not already saved and authenticated.
  • Strongest mode: Use it as a temporary override, not a substitute for correcting a bad preferred-network order.
  • Mobile-data fallback: Confirm the cellular plan and roaming settings before enabling it. Automatic fallback can consume mobile data.

Privacy and network checks

The developer says activation sends no Wi-Fi names, location data or usage statistics and that the tweak works offline after activation. Separately, its Internet-return test contacts Google, Cloudflare and Apple. Those connectivity probes are functional network traffic, so “works offline after activation” should not be interpreted as “never contacts the Internet” when verification is enabled.

This article reports the developer’s privacy statement and documented probe hosts; it is not an independent traffic audit. If a DNS filter blocks all three hosts, WifiCrush may keep mobile data active because it cannot confirm that Wi-Fi has working Internet.

Troubleshooting WifiCrush 1.0.2

It never switches away from weak Wi-Fi

Confirm WifiCrush is enabled, the alternate network is already saved in iOS, and its signal is clearly above the configured threshold. Disable Strongest mode if it is holding another path. Verify that Wi-Fi itself is not fully disabled by the optional Control Center behavior.

Mobile data does not activate

Check that cellular data is enabled for the SIM and that the device has service. The tweak cannot create coverage or bypass a carrier restriction. Test outside a call first, then inspect the app’s status line for the next planned action.

Mobile data stays on after Wi-Fi returns

Allow at least the documented 30-second stability window. If Wi-Fi works in Safari but the app does not accept it, temporarily allow the Google, Cloudflare and Apple connectivity checks through DNS or firewall filters.

The Control Center tile is missing

Install CCSupport, respring, then add the module from Control Center settings. On iOS 18, version 1.0.2 uses a regular CCSupport module; on older supported versions its placement differs.

Activation fails

Confirm the package was purchased with the Havoc account signed into the package manager, reopen WifiCrush and tap Activate. Include the displayed device code when contacting the developer. Do not post that code publicly.

SpringBoard or networking becomes unstable

Reboot into the non-jailbroken state, jailbreak with tweak injection disabled, and remove WifiCrush before reenabling injection. Dopamine users can follow the bad-tweak recovery guide.

Should you install WifiCrush 1.0.2?

Consider it if you regularly move between saved 2.4 GHz and 5 GHz networks, need a configurable cellular fallback, and already have a supported rootless or RootHide jailbreak. Its status screen and conservative return check make the switching logic visible rather than completely opaque.

Skip it if the real problem is poor router coverage, carrier service or ISP speed; if mobile-data use must never happen automatically; or if the exact device and firmware lack a compatible jailbreak. WifiCrush can choose among available connections, but it cannot improve their physical quality.

Frequently asked questions

Does WifiCrush boost Wi-Fi signal?

No. It selects among saved Wi-Fi networks and mobile data according to signal and connectivity checks.

Is RootHide supported?

The official listing claims both conventional rootless and RootHide support. Install only the package intended for the active environment.

Is CCSupport mandatory?

No. PreferenceLoader is required; CCSupport is optional for the Control Center tile.

Why does WifiCrush contact Google, Cloudflare and Apple?

The listing says it uses those hosts to confirm that recovered Wi-Fi actually has Internet before turning mobile data off.
