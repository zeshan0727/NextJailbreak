ElleKit vs libhooker vs Substitute: Which Tweak Injector Should You Use?

For most jailbreak users, this is not a normal three-way choice: keep the injector integrated by the jailbreak bootstrap. ElleKit is the current cross-API option documented by Dopamine and palera1n workflows; libhooker and Substitute belong to different jailbreak generations and integrations.

By Zeeshan Barvi · Published October 25, 2026 · Source status checked against the official projects

Do not swap core injection packages just to experiment. A tweak injector is part of the jailbreak’s trust, launch, safe-mode and package-dependency chain. Replace it only when the jailbreak project explicitly documents that migration.

Quick verdict

  • Dopamine, modern rootless palera1n or meowbrek2: use the ElleKit build supplied or recommended by that environment.
  • A bootstrap built around libhooker: keep its libhooker package and configuration unless the jailbreak maintainer publishes a migration path.
  • A Substitute-based jailbreak: keep that bootstrap’s Substitute build. A newer commit or different API does not make a cross-bootstrap replacement safe.
  • Tweak developers: ElleKit’s current documentation explicitly implements both Substrate and libhooker APIs, but runtime compatibility still depends on the target jailbreak, architecture and process.

What a tweak injector actually does

A tweak injector loads code into selected processes and provides hooking APIs that let a tweak replace or extend functions and Objective-C methods. It is not the jailbreak exploit, package manager or bootstrap. The jailbreak still has to supply the privileges, filesystem layout, launch configuration and package dependencies that make injection work.

This separation explains why “supports iOS 27” in a library README is not a jailbreak-availability claim. ElleKit’s source documents tested arm64 configurations through iOS 27, but a device still needs a compatible jailbreak or research environment for that exact firmware and hardware.

ElleKit: the broad compatibility layer

ElleKit’s current README describes direct C-function patching, Objective-C hooking, an arm64 assembler and a Swift JIT implementation. Crucially for existing tweaks, it reimplements both the Substrate and libhooker APIs. The project lists Dopamine, palera1n and meowbrek2 as users.

The release picture needs careful wording. The source repository’s latest Git tag is 1.1.3, while the separate official repository that serves ellekit.space currently contains signed package-pool files named 1.2 for both iphoneos-arm and iphoneos-arm64. This comparison therefore calls 1.2 the current official repository package without pretending a matching GitHub Release page exists.

libhooker: source availability is not a migration guide

CoolStar’s public libhooker repository is a one-commit open-source import. The commit title identifies it as libhooker 1.6.9, and the tree includes libhooker, Substrate and Substitute compatibility shims. GitHub shows no packaged releases in that repository.

That source is valuable to developers, but it does not mean a user can install the repository’s placeholder package definition over ElleKit or Substitute. The working package, launch services, safe mode and dependency graph came from the jailbreak distribution that integrated libhooker.

Substitute: a Substrate-compatible runtime library

The official sbingner fork describes Substitute as a free runtime-modification library. Its README explains arbitrary function and Objective-C method replacement and positions the project as a free substitute for Cydia Substrate. The source branch has recent development, but the README still labels the project alpha and the repository does not publish a current GitHub Release asset.

Those facts are not contradictory: source activity and a polished end-user jailbreak package are different things. Use the Substitute build maintained by the jailbreak that depends on it, not a self-built branch or a package copied from another bootstrap.

Why API compatibility does not make frameworks interchangeable

  • Filesystem paths differ. Rootful, conventional rootless and RootHide environments do not share one tweak directory or package architecture.
  • Launch integration differs. The bootstrap decides how the injector starts and which processes receive code.
  • Safe Mode differs. Recovery behavior is part of the framework and jailbreak integration, not just the hook API.
  • Package dependencies differ. APT can remove or replace core components when forced across bootstrap families.
  • A compatible API is not a compatible binary. A tweak can compile against a familiar header and still rely on OS, architecture or implementation details.

Safe decision checklist

  1. Identify the exact jailbreak, bootstrap and package architecture.
  2. Check which injector the jailbreak project names in its own documentation.
  3. Use only that project’s repository or the injector’s official repository when explicitly instructed.
  4. Never force-remove the installed injector to satisfy a tweak from an unrelated environment.
  5. If tweaks stop loading, boot with injection disabled and remove the last incompatible tweak before touching the framework.

For environment differences, use the rootful, rootless and RootHide comparison. Dopamine users can follow the bad-tweak recovery guide, while palera1n users should start with the current palera1n installation guide. Before any package, check the tweak compatibility checklist.

Frequently asked questions

Can I replace ElleKit with libhooker or Substitute?

Not as a general troubleshooting step. Keep the injector integrated by the jailbreak unless its maintainer documents an exact migration.

Does ElleKit run every Substrate or libhooker tweak?

No. ElleKit implements those APIs, but a tweak can still fail because of firmware changes, architecture, process restrictions or assumptions about a different jailbreak.

Does ElleKit’s iOS 15–27 arm64 testing mean iOS 27 is jailbroken?

No. It reports library testing, not public jailbreak availability for every device and firmware.

Which framework is fastest?

The official sources do not provide one comparable cross-framework benchmark. Real performance depends on the hooks, target processes and jailbreak integration, so this article does not invent a winner.
