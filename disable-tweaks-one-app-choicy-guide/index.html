How to Disable Tweaks for One App with Choicy

Choicy can stop every tweak from loading into one app, or load only the specific tweak dylibs that app needs. The safe approach is to start with a one-time test, then make the narrowest permanent rule that fixes the conflict.

By Zeeshan Barvi · Published October 15, 2026 · Verified against opa334’s official Choicy source, depiction, changelog and repository package index

Choicy is not a jailbreak-detection bypass. The developer states this explicitly. Disabling injected tweaks can solve a tweak conflict, but an app may still detect jailbreak files, environment changes or other artifacts.

What Choicy can control

Choicy optionWhat it doesBest use
Launch Without TweaksStarts the app once without tweak injection, without changing its saved rule.Confirm whether injected tweaks are causing the crash or glitch.
Disable Tweak InjectionPrevents injected tweak dylibs from loading into that app or process.Keep one app consistently clean when it does not need jailbreak tweaks.
Custom Tweak ConfigurationUses an allow list or deny list for individual tweak dylibs.Keep one required tweak while excluding a conflicting one.
Global Tweak ConfigurationDisables selected tweak dylibs globally, with per-process overrides.Handle a known-bad tweak across many apps; avoid this for a one-app problem.

Before you begin

  • Install Choicy 1.5.4-2 from opa334’s official repository or another repository that serves the developer’s unmodified package.
  • Confirm that Preferences/Settings loads Choicy and its Applications list.
  • Use a compatible jailbreak with tweak injection. Choicy’s official depiction says iOS 10–26, but that package range does not create jailbreak support for every device and firmware.
  • Match the package architecture to your bootstrap: the official package index publishes iphoneos-arm and conventional rootless iphoneos-arm64 builds. Do not assume that proves RootHide compatibility.

Version 1.5.4 added basic arm64e support for iOS 17–26, and 1.5.4-2 fixed a regression that broke iOS 15 and earlier. Use 1.5.4-2 rather than the initial 1.5.4 build.

1. Test the app once without tweaks

  1. Return to the Home Screen.
  2. Touch and hold the affected app icon.
  3. Choose Launch Without Tweaks from the shortcut menu.
  4. Repeat the action that normally crashes, freezes or misbehaves.

If the problem disappears only during that launch, an injected tweak is a plausible cause. If the problem remains, do not turn Choicy into a guessing exercise: the app, its data, the jailbreak itself or jailbreak detection may be responsible.

2. Disable all tweak injection for that app

  1. Open Settings → Choicy → Applications.
  2. Select the affected app.
  3. Enable Disable Tweak Injection.
  4. Reopen the app and test it again.

Choicy’s own preference text says applications are automatically restarted when their configuration changes. If the app still appears in the app switcher, close it and open it again before deciding the rule failed.

3. Keep only the tweaks the app needs

Disabling all injection also removes useful app-specific tweaks. When you need one of them:

  1. Return to Settings → Choicy → Applications → the app.
  2. Turn off Disable Tweak Injection.
  3. Enable Custom Tweak Configuration.
  4. Choose Allow mode.
  5. Select only the tweak dylib or dylibs the app genuinely needs.
  6. Reopen the app and test.

An allow list is the safer troubleshooting baseline because newly installed tweaks do not silently begin loading into the app. A deny list is useful when the app needs most of your normal tweaks and you have already identified the one conflicting dylib.

4. Find the conflicting tweak methodically

If several tweaks normally load into the app, add them back in small groups rather than one at a time from the start. When the problem returns, split the last group and test again. This narrows the conflict without repeatedly changing every switch.

  • Change one Choicy rule at a time.
  • Fully relaunch the app after each change.
  • Keep notes on which dylib names were allowed or denied.
  • When one tweak is identified, check its official changelog before downgrading or removing it.

For a damaged package transaction rather than an app-only conflict, use the Sileo dependency-error guide. Choicy changes injection policy; it does not repair package metadata or missing libraries.

5. Apply SpringBoard or daemon rules cautiously

Choicy also exposes SpringBoard, daemons and additional executables. These are not ordinary apps:

  • a SpringBoard configuration needs a manual respring;
  • some daemon changes may require a userspace reboot;
  • blocking the wrong essential tweak or support library can remove expected jailbreak behavior until the rule is reversed.

Use daemon controls only when you know the process name and the tweak dylib involved. For a single crashing App Store app, stay in the Applications list.

Global configuration versus per-app rules

Global Tweak Configuration is convenient when one dylib should be excluded almost everywhere, but it is broader than most fixes require. Choicy supports overriding the global rule for individual applications and services. Before adding a global deny rule, ask whether the same result can be achieved with one per-app allow list.

If the app still does not open

  • Use the one-time shortcut again to confirm the saved rule is actually the difference.
  • Disable every custom rule for the app, then recreate only one rule.
  • Check whether the app opens while the device is not jailbroken; this separates an injection conflict from a broader app or data problem.
  • Update the identified tweak from its original source.
  • Do not claim Choicy bypassed jailbreak detection; the developer explicitly says it does not.

If the whole device is entering Safe Mode or a respring loop, follow the Dopamine bad-tweak recovery guide instead of changing many per-app rules.
