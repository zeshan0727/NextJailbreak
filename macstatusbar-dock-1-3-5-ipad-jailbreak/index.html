MacStatusBar&Dock 1.3.5 Improves Stage Manager Windows on Jailbroken iPads

The free rootless tweak’s latest release makes Stage Manager behave more like a single Mac-style desktop, then fixes force-quit, window placement, rotation and menu-targeting problems reported during its rapid public rollout.

By Zeeshan Barvi · Published October 5, 2026 · Version 1.3.5 released October 4, 2026

What changed in version 1.3.5?

MacStatusBar&Dock 1.3.5 changes the Stage Manager engine so app windows can float over the Home Screen while icons, widgets and desktop items remain visible and usable behind them. Restoring a minimized app from the App Switcher now adds that window to the current workspace instead of hiding the windows already there, and swiping from the left edge no longer opens Stage Manager’s window-group list.

The release also narrows Force Quit to the selected app window. Other fixes keep a newly opened window from landing directly over another one, place “Fit to Window” tiles correctly above the Dock after rotation, send the window-menu layout to the front app, and keep the Window menu usable when a window’s top edge sits beneath the menu bar. On iPadOS 16.4 or later, force-quitting an app while windows are put aside should no longer bring that app back with the others.

A Mac-like layer, not macOS on iPad

The tweak replaces parts of the iPad interface with a Mac-inspired menu bar, magnifying Dock, Finder-like desktop and movable app windows. Earlier 1.3 releases added desktop files and folders, a Wi-Fi menu, a simple text editor and drag-and-drop access to Downloads. It still runs iPadOS apps; this is not macOS, a virtual machine or a way to run Mac software.

Version 1.3.3 also added right-to-left menu-bar layouts for Arabic, Hebrew, Persian and Urdu. That is useful beyond appearance: app menus and status items mirror to match the writing direction.

Compatibility needs careful reading

The developer describes MacStatusBar&Dock as an iPad-only rootless tweak for iPadOS 15 and 16. It does nothing on iPhone. iPadOS 17 and later remain experimental and are disabled by default unless the user chooses “Enable Anyway.” The package declares a minimum firmware of iPadOS 15.0, but that package range does not mean every iPad or every firmware has a usable jailbreak.

The documented developer test devices are an M1 11-inch iPad Pro on iPadOS 15.6.1 with Dopamine and a 9.7-inch iPad Pro on iPadOS 16.7.7 with palera1n. An iPad Pro 10.5-inch on 16.6.1 is listed as a user report. Stage Manager support is more conditional: version 1.3.4 exposed its engine on iPadOS 16.0 and 16.1, but the project labels 16.0 untested, while 16.2 and 16.3 were also introduced as untested paths. A reported M2 iPad Pro crash on 16.1 is documented with the suggestion to use Aerial 5.0 instead.

Dependencies and window engines

The package requires a compatible hooking platform—ElleKit, libhooker or Substrate—plus AltList. The project also calls for Choicy or iCleaner Pro so only one window engine is injected at a time. Optional engines include Aerial 3.0 or 5.0, MilkyWay4 0.1.1 for iPadOS 15, and Zetsu 1.6.2 or 1.6.6. Mixing multiple engines is a likely source of conflicts, so follow the project’s configuration notes before respringing.

Where to get it—and what to verify

MacStatusBar&Dock is free and GPL-3.0 licensed. The developer’s release ledger identifies 1.3.5 with source commit c574c09a8b50455b3ef482384cd4d8b59a8aa705 and publishes SHA-256 1ef615022a4163095c398f161a8841529fef26ec56cc3a3bc15e30e44c4d7538 for the rootless package. Use the official repository rather than a re-upload, and confirm the version and checksum before installing.

If you are deciding between package managers, see our Sileo vs Zebra comparison. For a safer first launch, work through the tweak compatibility checklist and disable other window-management tweaks until you know the base setup is stable.
