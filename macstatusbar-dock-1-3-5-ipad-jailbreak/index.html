MacStatusBar&Dock 1.7.9.2 Fixes Covered-Window Launches and Stage Manager Dragging

The 1.7.9.2 maintenance release fixes two Stage Manager problems that could leave an app hidden behind another window or resize the wrong window during a drag. The wider 1.7.9 line also adds a battery menu, Home-to-minimize behavior and low-memory controls.

By Zeeshan Barvi · Published October 5, 2026 · Updated November 5, 2026 · Current official package: 1.7.9.2

This is an iPad-only rootless tweak. The developer says it does nothing on iPhone, does not publish a RootHide build and supports iPadOS 15 through 18. A listed firmware range does not create a jailbreak for an otherwise unsupported iPad.

What 1.7.9.2 fixes

Version 1.7.9.2 is a focused Stage Manager repair. Dragging one window should no longer resize a smaller window behind it. Apps opened from another launcher, a link or Spotlight should bring their existing window to the front instead of appearing to do nothing behind a covered window.

The preceding 1.7.9.1 build fixed the same front-window problem for apps opened from the Dock, App Library or Home Screen. Together, those patches close a confusing failure mode: the app had opened, but its window remained completely covered.

What arrived in the 1.7.9 line

  • Battery menu: tap the menu-bar battery for Low Power Mode, Sleep Guard and Battery Settings; a new icon beside the clock opens Control Center.
  • Home Minimizes Windows: a bottom-edge swipe or Home-button press minimizes windows to reveal the Home Screen; reopening an app restores its window.
  • Finder-menu folders: a Home Screen folder can be added to Finder’s menu through its Haptic Touch actions.
  • Desktop icon radius: desktop app icons can be adjusted from square to circular.
  • Keep Tailspin Off: enabled by default on 2 GB iPads to prevent an iPadOS diagnostics trace from holding tens of megabytes of memory.

The same release also repairs Settings crashes on iPadOS 17, trackpad scrolling in the Today panel on iPadOS 17 and 18, Aerial window state after locking, and menu-bar behavior while a Home Screen folder is open.

How to update safely

  1. Close important documents and finish file transfers in Finder or the Downloads stack.
  2. Record the active window engine and temporarily disable competing window-management tweaks. Do not inject Aerial, Zetsu and MilkyWay4 together.
  3. Refresh sources in Sileo or Zebra and confirm the package identifier is com.besiktasliseba.macstatusbaranddock.
  4. Install version 1.7.9.2 from Havoc or the developer repository, then respring once.
  5. Test one full-screen app and one window first. Check Dock launch, Spotlight launch, window dragging and Home-to-minimize before reopening a large desktop.

The developer ledger publishes a 2,137,860-byte rootless DEB with SHA-256 d043ace2b8dc396fc15a5bbb8834af39a88fc40b332a34a48d801b39770b794a. That checksum applies to the developer-repository package recorded in the ledger; do not use it to reject a separately signed marketplace artifact unless the source says the files are identical.

If the App Switcher, gestures or windows behave incorrectly after changing engines, revert to the last working engine and respring before diagnosing the tweak itself.

Recovery if the update causes Safe Mode or hidden windows

  1. Enter the jailbreak’s Safe Mode. If SpringBoard loops, launch the jailbreak with tweak injection disabled.
  2. Use Sileo or Zebra to remove MacStatusBar&Dock, or disable its injection and all but one window engine with Choicy or iCleaner Pro.
  3. Respring and verify the stock Home Screen, Dock and App Switcher work before reinstalling.
  4. Reinstall only the base tweak first. Add the chosen window engine after the menu bar and Dock remain stable.
  5. For a covered app window on an older build, update to 1.7.9.2; as a temporary escape, switch desktops, use Force Quit, or disable the window engine and respring.

Do not delete Finder’s desktop or Trash directories as a generic troubleshooting step. Those contain user files, not disposable tweak preferences. For general recovery, see the Dopamine bad-tweak recovery guide.

Frequently asked questions

Does MacStatusBar&Dock work on iPhone?

No. The developer documents it as iPad-only and says it does nothing on iPhone, including iPhones made to resemble an iPad.

Does it support RootHide?

No RootHide package is documented. The published package uses the conventional rootless iphoneos-arm64 architecture.

Is the tweak macOS for iPad?

No. It provides a Mac-inspired menu bar, Dock, Finder, Activity Monitor, multiple desktops and window controls around iPadOS apps. It does not run macOS applications.

Should I install every window engine?

No. Use one compatible engine. Multiple injected window engines are a conflict risk and make recovery harder.
