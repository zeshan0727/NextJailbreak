ShowVolumeControl 1.0.0 Adds a Persistent Volume Control to iOS 16 Media Controls

ichitaso has published ShowVolumeControl 1.0.0, an MIT-licensed jailbreak tweak whose stated purpose is to always show the volume control in iOS 16 media controls. The package is listed as compatible with rootless, roothide and rootful environments, depends on firmware 16.0 or later and mobilesubstrate, and conflicts with two similarly named volume-control packages.

Key points

  • ShowVolumeControl 1.0.0 is an initial release rather than an update to an earlier public version.
  • The tweak is explicitly described as working only on iOS 16.
  • The repository and package metadata list support for rootless, roothide and rootful setups.
  • The implementation targets Apple's MediaRemoteUI bundle and forces the media-control volume-control view to remain enabled.
  • The package depends on mobilesubstrate and declares a firmware requirement of iOS 16.0 or later.
  • It conflicts with and replaces two other volume-control packages, so users should review existing related tweaks before installing.

What ShowVolumeControl changes

ShowVolumeControl is a small jailbreak tweak focused on one interface behavior: keeping a volume control visible in media controls. The official description says it will “always show volume control on the media controls,” while also warning that it works only on iOS 16. That makes the package relevant to users who want volume adjustment available directly from the media-control interface rather than relying only on the device’s physical buttons or other system controls.

The available source describes a persistent-visibility change, not a redesigned volume interface. It does not claim to add new audio features, alter volume limits, change the appearance of the control, or support media controls outside the stated iOS 16 scope. Those distinctions matter because the package’s purpose is narrow: it changes whether the volume-control view is shown.

What changed in version 1.0.0

Version 1.0.0 is identified on the official package page as the initial release. The public repository also contains one commit labeled “Initial commit,” with the project files added together. As a result, this release should be read as the first published version of ShowVolumeControl rather than a maintenance update with a long change history.

The initial source includes the tweak implementation, package metadata, build configuration and an MIT license. The repository description and README use the same concise explanation of the feature: always showing the volume control on media controls on iOS 16. No separate bug-fix list, settings panel, customization options or release-specific limitations beyond the iOS 16 statement are documented in the supplied source.

  • Release: 1.0.0.
  • Release status: initial release.
  • License: MIT, according to the repository license file.
  • Price: free, according to the official package page.

How the implementation works

The source code provides a direct explanation of the tweak’s behavior. Its package filter targets the com.apple.MediaRemoteUI bundle, which is the system component identified by the project for the relevant media-control interface.

Within that target, the tweak hooks the MRUNowPlayingView method setShowVolumeControlsView:. Instead of passing through the value supplied by the original caller, the hook invokes the original method with YES. In practical terms, the implementation asks the media-control view to show its volume-control view whenever this setter is used.

This source-level detail supports the project’s stated feature, but it does not establish behavior on every device, media application or iOS 16 build. The supplied materials do not include a test report or device-specific compatibility matrix. Readers should therefore treat the official iOS 16 statement as the documented compatibility boundary and check their own setup before relying on the tweak.

Compatibility and dependency details

The official depiction lists iOS 16 compatibility and identifies rootless, roothide and rootful as supported environment types. The package control file is more specific about the minimum firmware dependency, declaring firmware version 16.0 or later. At the same time, the README and repository description say “only work iOS 16,” so users should not interpret the firmware dependency as a promise of support for later major iOS releases.

The package also depends on mobilesubstrate. That dependency is important because the tweak is built as a substrate-style injection into the MediaRemoteUI process. The source does not provide additional dependency version requirements, and it does not document whether any particular bootstrap, package manager or jailbreak tool is required beyond the listed environment categories.

The Makefile defines arm64 and arm64e architectures and uses an iPhone target with an iOS 16.0 deployment target. It contains build branches for rootless and roothide package schemes, as well as a default build path. These are useful developer-facing details, but they should not be expanded into claims that every device using those architectures will work identically.

  • Documented operating-system scope: iOS 16.
  • Package metadata minimum: firmware 16.0 or later.
  • Environment types listed by the official page: rootless, roothide and rootful.
  • Declared dependency: mobilesubstrate.
  • Architectures listed in the build configuration: arm64 and arm64e.

Conflicts and installation checks

ShowVolumeControl’s package metadata declares both Conflicts and Replaces entries for com.p2kdev.nowplayingvolumecontrol and apt.cydiakk.nowplayingvolumecontrol-rootless. This is a significant installation consideration for users who already have a similarly named now-playing volume-control tweak installed. The metadata indicates that the packages are considered overlapping or incompatible, but it does not describe how an existing installation will be handled in every package manager.

Before installing, users should check whether either of those package identifiers is present and review the package manager’s proposed changes. They should also confirm that the device is running the documented iOS 16 scope, that the jailbreak environment matches one of the listed rootless, roothide or rootful categories, and that mobilesubstrate is available as a dependency.

The supplied sources identify the author’s repository and package depiction as the official distribution references. Readers should use those original channels and avoid unofficial copies. The source materials do not provide a troubleshooting procedure, rollback guide or claim that installation is risk-free, so users should preserve their normal package-management recovery path before changing system UI components.

  • Check for com.p2kdev.nowplayingvolumecontrol before installation.
  • Check for apt.cydiakk.nowplayingvolumecontrol-rootless before installation.
  • Review dependency and conflict prompts rather than assuming an existing tweak will coexist.
  • Use the project’s official distribution references, not unofficial packages or mirrors.

Why this release matters

The change is modest but practical for users who find the media-control volume interface too conditional or difficult to access. By forcing the relevant visibility setter to YES, ShowVolumeControl addresses a specific interaction preference without advertising a broader redesign of the lock-screen or media-player experience.

Its narrow scope is also the main compatibility caveat. The project is explicitly tied to iOS 16, targets MediaRemoteUI and depends on substrate injection. Users on another major iOS release should not assume that the tweak will work simply because the package declares firmware 16.0 or later. Likewise, the presence of rootless, roothide and rootful build paths does not replace checking the device’s actual jailbreak environment and installed dependencies.

Because this is version 1.0.0 and the repository contains only the initial commit, there is limited release history available in the supplied material. Potential adopters should pay attention to future source changes and revised compatibility notes before updating their system or replacing an existing volume-control tweak.
